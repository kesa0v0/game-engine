# 호스트 함수의 결정론 검사 켜기

호스트 함수(spec S7)는 게임 개발자가 C#으로 짜는 코드다. 엔진은 커널 코드를 컴파일할 때 결정론을 깨는 구성을 막지만(spec P2), 호스트의 코드에는 그 검사가 닿지 않는다. 또 엔진은 실행 중에 "이 기계와 저 기계의 결과가 다르다"를 알아챌 수 없다. 그래서 커널과 같은 검사를 호스트 함수 프로젝트에도 켤 수 있게 내놓는다(spec-gaps G220). 켤지는 호스트가 정한다.

## 켜는 법

호스트 함수만 모은 프로젝트(`.csproj`)에 한 줄을 넣는다.

```xml
<Import Project="(엔진 저장소)/src/Kesa.Engine.Analyzers/Determinism.props" />
```

커널도 같은 파일을 가져다 쓰므로, 커널이 빌드되면 이 설정도 동작한다. 호스트 함수가 아닌 코드(렌더링, UI, 입력 등)는 부동소수점과 시계를 써야 하므로 같은 프로젝트에 두지 않는다. 호스트 함수와 그 함수가 부르는 계산만 따로 모은다.

## 잡는 것

| 코드 | 무엇 | 예 |
|---|---|---|
| `KE0001` | 부동소수점 타입과 리터럴 | `double d = 1.5;` → `int`나 `Fixed`를 쓴다 |
| `KE0002` | 순서가 보장되지 않는 순회 | `foreach (var kv in dictionary)` → 정렬하거나 `SortedDictionary`·`List`를 쓴다 |
| `RS0030` | 금지 목록(`BannedSymbols.txt`)의 API | `DateTime.Now`, `System.Random`, `Guid`, `string.GetHashCode`, 문화권 의존 비교(`StartsWith(string)`), `Parallel`·`Task.Run` |

셋 다 오류로 나온다(`RS0030`은 원래 경고라서 이 파일이 오류로 올린다). 난수가 필요하면 `Writes` 함수가 받는 `HostAccess`의 `RandInt`·`RandRange`·`Random`·`Choice`·`Sample`을 쓴다. 이것은 스크립트 `random`과 같은 시드, 같은 흐름이다.

호스트 프로젝트에 `BannedSymbols.txt`를 하나 더 두면 엔진 목록과 함께 적용된다. 게임에만 해당하는 금지(예: 렌더링 쪽 정적 클래스)를 거기 적는다.

## 잡지 못하는 것

이 검사는 코드 모양만 본다. 아래 것은 호스트가 지켜야 한다.

- **정적 변수에 숨긴 상태.** 함수 호출 사이에 값을 기억하면 저장·불러오기 뒤에 결과가 달라진다. 상태는 엔티티 칼럼에 둔다.
- **이 프로젝트 밖의 코드.** 호스트 함수가 부르는 다른 라이브러리(엔진 밖 물리, Unity의 `Mathf` 등)는 검사하지 않는다.
- **리플렉션이나 `dynamic`으로 우회한 호출.**
- **기계마다 다른 입력.** 파일, 네트워크, 환경 변수를 읽는 것.

실행 중 어긋남을 감지하는 것(상태 체크섬)은 리플레이·멀티플레이를 만들 때 그 기능의 일부로 한다(G220). 순수 호스트 함수를 두 번 불러 비교하는 검증은 하지 않는다. 같은 기계 안에서 비교하면 기계마다 다른 문제(부동소수점, 해시 순서)를 잡지 못하기 때문이다.

## Unity

Unity는 `.csproj`를 직접 쓰지 않고 어셈블리 정의(`.asmdef`)로 컴파일한다. 일반 지식으로는 Unity도 Roslyn 분석기 DLL을 `RoslynAnalyzer` 레이블로 받는다. 하지만 이 저장소에서 Unity로 확인한 적은 없다. Unity 패키지 형태가 정해질 때(spec P1a) 같이 확인한다.
