# 10. 모드를 고칠 때와 아직 없는 것

## 모드를 고칠 때: 저장 호환

플레이어의 저장 파일은 엔티티와 그 값, 배정 표, 멈춘 흐름, 난수 상태를 든다. `derived` 값과 Def 값은 저장하지 않고 불러온 모드에서
다시 읽는다. 그래서:

| 바꾼 것 | 옛 저장을 불러오면 |
|---|---|
| Def 값(밸런스, 글 키) | 그대로 된다. 새 값이 쓰인다 |
| 모드 내용 | 경고 `SAV003`(어느 파일이 바뀌었나)와 함께 된다 |
| 새 `field`에 기본값이 있음 | 된다. 기본값으로 채운다 |
| 새 `field`에 기본값이 없음, 범위를 좁혀 저장 값이 벗어남, 타입을 바꿈 | 거절 `SAV002` |
| 컴포넌트·멤버·Def를 지움 | 기본은 거절 `SAV002`(무엇이 사라졌나 모두 나열). 호스트가 "지운 것 버리기"로 부르면 경고 `SAV005`와 함께 버리고 된다 |
| 멈춘 흐름의 함수 본문을 고침 | 거절 `SAV004`. 공백·주석만 고쳤으면 된다 |

- 멈춘 흐름(답을 기다리는 `ask`, `wait`)은 **멈춘 그 본문에서만** 이어 간다. 본문을 고치려면 그 흐름이 끝난 뒤에 배포하거나,
  호스트가 깨진 흐름을 취소하고 불러오게 한다(`SAV006`). 멈추지 않은 함수는 새 본문이 그냥 쓰인다.
- 이름 바꾸기·타입 바꾸기를 옮겨 주는 `migrate`는 아직 없다.
- 봇의 기억(9장)은 호스트가 판 세이브 옆에 따로 저장한다. 불러온 모드에서 `bot_state`나 그 칸, 봇의 설정이 사라졌으면 그 값을
  버리고 경고와 함께 되살린다. 봇 함수가 사라졌으면 되살리지 못한다.

## 아직 없는 것

| 없는 것 | 지금은 |
|---|---|
| 스크립트 안에서 숫자를 글로 바꾸기(`str()` 등) | `text("키", n=수)`로 번역문에 넘기고 `NUMBER`로 서식을 정한다(8장) |
| 다른 모드의 `@ui_action`을 덮어쓰기·패치 | 같은 일을 하는 동작을 제 이름으로 새로 쓴다 |
| `submit`이 받을 질문을 고르기(`request=`) | 한 연결이 같은 커맨드를 받는 질문 둘을 함께 받으면 거절된다(8장) |
| 봇이 합법 수를 스크립트로 읽기 | 열린 질문은 `questions()`로 보고, 답할 만한 수를 적고 거절은 흘려보낸다(9장) |
| 봇이 후보 수에 점수를 매겨 고르는 도우미(`Score`·`BotAction`, `std.ai`) | 봇 함수 안에서 직접 비교해 고른다 |
| 싼 시험 판 복사 | `with imagine():`의 복사는 판 크기만큼 든다(유닛 하나에 약 7µs, 1천 개면 7ms). 큰 판에서 깊이 읽어야 하면 작은 판을 리스트로 따로 만들어 읽는다(9장) |
| 기여 행의 만료, 여러 걸음의 `to=` | id를 칸에 적어 두고 `@on(Tick)`에서 `remove_contrib`, 붙일 때 `add_contrib`·뗄 때 `remove_contribs` |
| `try`, 문자열 인덱싱, 튜플, `match`의 이름·점 이름·리스트·사전·클래스 패턴 | 3장의 대안 (`match` 패턴은 가드로) |
| Def를 지우는 패치 | `override=True`로 바꾸거나, 그 Def를 쓰지 않게 패치 |
| 한 엔티티에 여러 연결(공동 조종) | 한 연결 이름을 여럿이 나눠 쓴다 |
| `migrate`(저장 옮기기) | 위의 저장 호환 규칙 안에서 고친다 |
| 엔진이 만드는 레퍼런스 페이지 | 스텁(`engine stubs`)을 본다 |
| Unity 화면(UXML)의 일부 | 규칙(8장)과 해석기, Unity 패키지(`hosts/unity/uk.kesa.engine.unity`)가 있고 창 없는 확인이 통과했다. 창(`window`, 모달, ESC, 끌기)도 있다. 모드 USS(`<Style src>`, Unity USS 그대로)도 있다. 아직 없는 것: USS의 `@import`와 `url()`로 그림 밖의 파일 읽기, 인라인 `style`, IL2CPP 빌드에서 돌려 본 확인, Unity 안에서 눌림·끌기·ESC와 프레임마다 갱신을 돌려 본 확인 |
| 월드 표시(판 위의 그림)의 나머지 | `look`·`where` 칸, `look`·`at`·`onto`·`between`, 표시 `@world_marks`·`mark`는 있다(8장). 그림 정의 `.look.xml`(`Sprite`·`Text`·`Model`·`Group`)과 공간 `.space.xml`(`grid`)로 Unity에 그리고 표시·엔티티·빈 칸을 누를 수 있다(`@world_input`, 내장 입력 `primary`·`secondary`, 모드 입력의 키 `.input.xml`). 한 번 일어나는 효과 `@world_fx`·`fx`, 연출 방식 `Mod(presentation=…)`(`staged`는 신호마다 단계), 사라질 때의 `exit` 그림, 옮겨 가는 시간 `move`와 그림 정의의 시간 칸(`fade-in`·`solid`·`fade-out`·`rise`·`drift`·`grow`)이 있다. 아직 없는 것: `Include`, 기본 공간, `onto`·`between` 그리기, 다른 공간 종류(육각·연속·구역), 모델 색의 마스크 텍스처, 모델 애니메이션의 층·조건 전이(상태 `State`·블렌드 `Clip`·뼈에 붙이기 `Attach`·색 `tint`·`Paint`·크기 `scale`·모델 누르기는 있다), 패널 안의 View(작은 지도·초상)와 View마다 다른 그림, 카메라를 옮기라는 모드 요청(방향 `turn`·눕기와 `face`, 카메라 `.view.xml`의 `top`·`tilted`는 있다), 모더가 고르는 글꼴, 커서·끌기 같은 입력 상태 읽기 |

이 목록은 엔진이 자라면서 줄어든다. 무엇이 정해졌는지는 `docs/decisions/`(결정 기록)에 있다.
