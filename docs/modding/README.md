# 모더 안내서

이 엔진으로 게임과 모드를 만드는 사람을 위한 안내서다. 엔진 자체를 고치는 사람용 문서(`spine-spec.md`, `spec-gaps.md`)와 달리
**무엇을 어떤 순서로 쓰는지**만 다룬다.

이 엔진에서는 **게임 자체가 모드**다. 커널은 규칙을 모르고, 모드가 데이터(스키마·Def)와 규칙(함수·커맨드)을 모두 준다.
그래서 "게임 만들기"와 "남의 게임에 모드 얹기"는 같은 도구를 쓴다.

## 장

1. [시작하기](01-start.md): 모드 폴더, `mod.py`, `engine check`, 편집기 스텁, 오류 읽기
2. [데이터](02-data.md): 스키마(컴포넌트·타입·Ref), Def와 상속, 패치와 로드 순서
3. [로직](03-logic.md): 함수 언어, 엔티티 읽고 쓰기, `query`, `derived`와 기여 행, 난수, 실행 예산
4. [커맨드](04-commands.md): `@command`, 사전 조건, `choose`·`cost`, 실패와 되감기
5. [흐름과 시간](05-flow.md): `ask`, 응답 커맨드, `wait`, 마감, 틱
6. [반응](06-reactions.md): 신호와 `@on`, `@when`, 단계
7. [자리와 숨긴 정보](07-seats-and-hidden.md): 배정 표, `acts_for`, `controller`, 보기 정책
8. [화면에 보일 값](08-screen.md): 순수 함수로 값 만들기, 콘솔의 `ui/console.txt`, 번역 파일(`locale/`), 화면 동작(`ui_state`·`@ui_action`·`submit`)
9. [모드를 고칠 때와 아직 없는 것](09-updates-and-limits.md): 저장 호환, 지금 없는 기능

## 예시

- `samples/skirmish`: 작은 전투(5×5 판, 두 진영). 차례 루프, 응답 커맨드, 명중 때 묻는 질문, 콘솔 화면, 유닛 고르기 → 공격(화면 동작).
- `samples/guide`: 이 안내서용 작은 항구(`harbor`)와 그것을 고치는 모드(`lighthouse`). 스커미시에 없는 기능(키 줄, `derived`와
  기여 행, 상속, 패치, 신호와 반응, 마감 있는 질문, 보기 정책)을 담았다.

안내서의 예시 코드는 이 두 곳에서 가져온다. 두 모드는 테스트(`SkirmishTests`, `GuideSampleTests`)가 불러 한 판을 돌리므로,
예시가 깨지면 테스트가 먼저 실패한다(spec-gaps G252). 파일 이름이 붙지 않은 짧은 조각은 설명용이다.

## 레퍼런스는 어디에

빠짐없는 이름 목록(내장 함수, 데코레이터, 내 스키마의 클래스)은 이 안내서에 적지 않는다. `engine stubs`가 모드마다 만드는
`.pyi` 스텁이 레퍼런스다(1장). 편집기가 그것으로 자동완성과 타입 검사를 한다.

## 표기

- 오류 코드(`SCH004`, `RUN013` 등)는 `engine check`나 실행 오류에 그대로 나오는 코드다. 앞 세 글자가 영역이다
  (`LEX` 글자, `PAR` 구문, `MOD` 모드, `LOD` 로딩, `EVL` 평가, `SCH` 스키마, `DEF` Def, `PAT` 패치, `INH` 상속, `LNK` 참조,
  `VAL` 값, `CMD` 커맨드, `RUN` 실행, `SAV` 저장, `HST` 호스트 함수, `LOC` 번역).
- "호스트"는 엔진을 띄우는 프로그램이다(콘솔 `kesa-play`, Unity 패키지와 데모, 나중의 Godot 클라이언트). 모더가 C#을 쓸 일은 없다.
