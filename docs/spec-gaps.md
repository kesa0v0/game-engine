# spec 빈틈 목록

`spine-spec.md` 8절의 절차에 따라, 구현하다 spec이 비어 있거나 애매한 곳을 만나면 여기에 적는다. 추측으로 채운 곳도 반드시 적는다. 구현이 끝나면 각 항목을 spec의 결정으로 옮기고 이 목록에서 지운다.

**상태:** 잠정 = 구현이 이렇게 동작하지만 확인 필요 · 확인 = 사용자가 동의함 · 반영 = spec에 옮김.

| # | 위치 | 무엇이 비어 있었나 | 어떻게 정했나 | 이유 | 상태 |
|---|---|---|---|---|---|
| G1 | S1 ① 정렬 | "의존 관계가 없는 모드끼리는 id 순"을 문자 그대로는 만족할 수 없다. 예: `a`가 `z`에 의존하고 `b`는 무관하면, id 순으로는 a < b < z인데 의존성은 z가 a보다 앞서야 한다. | Kahn 알고리즘에서 "지금 로드할 수 있는 모드 중 id가 서수상 가장 작은 것"을 먼저 둔다. 위 예는 `b z a`. | 결정적이고 입력 순서와 무관하며 의존성을 항상 지킨다. | 확인 |
| G2 | S1 매니페스트 | 모드 id 형식이 없었다. | `[a-z][a-z0-9_]*`. 점(`.`)은 쓸 수 없다. | 모드 id가 호스트 함수·단계 이름의 네임스페이스 접두사(`core.find_path`)로 쓰이므로 점이 들어가면 모호해진다. | 잠정 |
| G3 | S1 매니페스트 | `use(...)` 목록이 어디에 있는지, mod.py에 무엇이 올 수 있는지가 없었다. | mod.py에는 `Mod(...)` 호출 하나와 `use(...)`/`use_all(...)`만 온다. 모두 AST로 읽고 인자는 리터럴이어야 한다. 경로는 모드 폴더 기준 상대 경로, `/` 구분자, `..`와 절대 경로 금지. `use`는 `.py` 파일만. | "파일 실행 없이 AST로 읽는다"를 지키려면 실행 순서 목록도 실행 없이 읽혀야 한다. | 잠정 |
| G4 | P2 `fixed` 리터럴 | 소수 자리가 6을 넘는 리터럴의 처리. | 오류(`LEX007`). 단, 넘는 자리가 모두 0이면(`1.5000000`) 허용. | 조용히 반올림하면 모더가 쓴 값과 다른 값이 된다. | 확인 |
| G5 | S9 진단 | 위치 표기 규칙. | 줄·열은 1부터, 열은 UTF-16 코드 단위. 파일 경로는 모드 루트 기준 상대 경로, 구분자 `/`. 줄바꿈은 `\r\n`·`\r`·`\n` 모두 한 줄. UTF-8 BOM은 무시. 진단 출력은 (파일, 줄, 열, 코드, 메시지) 순으로 정렬. | VS Code·C# 문자열과 같은 단위. 절대 경로는 골든 출력을 기계마다 다르게 만든다. | 잠정 |
| G6 | S9 진단 코드 | 코드 체계가 열린 질문이었다. | 영역 접두사 + 세 자리: `LEX`(렉서), `PAR`(파서), `MOD`(매니페스트·정렬). 영역은 단계가 늘 때 추가. | 최소한의 체계로 시작. | 잠정 |
| G7 | S1 ① 발견 | `mod.py`가 없는 폴더, 이름 대소문자가 다른 경우. | `mod.py`가 없는 폴더는 경고 후 건너뜀. `Mod.py`처럼 대소문자만 다르면 오류. `.`으로 시작하는 폴더는 조용히 무시. | 대소문자 무시 파일 시스템(Windows)과 아닌 곳에서 결과가 같아야 한다. | 잠정 |
| G8 | S1 ① 정렬 | 선택 의존성(`optional`)이 설치되어 있지만 로드에 실패한 경우. | 없는 것으로 본다: 순서만 잃고 이 모드는 로드한다. 추가 진단은 없다(실패한 모드의 진단은 따로 나옴). | spec에 없음. 선택 의존성의 뜻("없어도 된다")에 가장 가까운 해석. | 확인 |
| G9 | S1 ① 정렬 | `loadAfter`·`optional` 대상이 설치되지 않은 경우. | 조용히 무시. 단, 설치된 모드 중 이름이 아주 비슷한 것이 있으면 경고 + "혹시 …?". | 없어도 되는 참조지만, 오타면 순서가 조용히 틀어진다. | 잠정 |
| G10 | S1 ① 정렬 | 두 폴더가 같은 모드 id를 선언한 경우. | 둘 다 비활성화. 각 진단의 `related`에 다른 쪽 위치. | 어느 쪽을 고를지 근거가 없다. | 잠정 |
| G11 | S1 ① 정렬 | 사이클에 든 모드에 `loadAfter`/`optional`로만 걸린 모드. | 로드한다(사이클 모드는 없는 것으로 보고 순서만 잃음). 필수 의존(`dependencies`)이면 비활성화. | G8과 같은 해석. | 확인 |
| G12 | S1 매니페스트 | `Mod(...)` 필드 목록. spec에는 `id`, `dependencies`, `loadAfter`, `optional`만 있었다. | `version`(S8 세이브 메타에 필요), `defaultLanguage`(X4 P3)를 추가. 필드 이름은 spec 표기대로 camelCase. 모르는 필드는 오류 + "혹시 …?". | S8·X4가 mod.py에서 읽는다고 했으므로. | 잠정 |
| G13 | S2 언어 | 파이썬 부분집합의 어휘 수준 제한. | 들여쓰기의 탭은 오류. 16·8·2진수, 지수 표기, 허수 금지. 문자열 접두사는 `u`만(`r`·`b`·`f`는 미지원). 이스케이프는 `\\ \' \" \n \r \t \0 \xhh \uXXXX \UXXXXXXXX`와 줄 잇기만. 튜플·집합·슬라이스·언패킹·체인 비교·조건식·람다·컴프리헨션은 이 단계에서 미지원(`PAR002`, 구문 오류와 구분). | spec S2는 문장 수준 허용 목록만 있었다. 컴프리헨션·람다는 spec상 허용이므로 로직 단계에서 지원 예정. 데코레이터와 `match` 문도 같은 방식으로 미지원 보고(`match`는 소프트 키워드라 블록을 여는 줄에서만). | 잠정 |
| G14 | S2 언어 | 식별자에 쓸 수 있는 문자. | **ASCII만**: `[A-Za-z_][A-Za-z0-9_]*`. 비 ASCII 글자가 섞인 이름은 `LEX011` + "표시 문자열은 문자열이나 텍스트 키에". 문자열·주석·Def id(문자열)에는 제한 없음. 나중에 파이썬 규칙(XID 표 + NFKC 정규화, 유니코드 버전 고정)으로 넓힐 수 있다. ASCII는 두 규칙에서 같으므로 기존 모드·세이브가 깨지지 않는다. 그러려면 렉서 밖(세이브 칼럼 이름, 해시, did-you-mean)은 이름을 ASCII로 가정하지 않는다. | 파이썬은 식별자에 XID 표와 NFKC 정규화를 쓴다. 이를 그대로 따르려면 표를 엔진에 넣어야 하고, 따르지 않으면 파이썬과 뜻이 달라진다(한글 완성형/조합형 등). 식별자는 세이브에 남는 내부 이름이고 화면 문자열은 텍스트 키로 간다(S2, X4). 비 ASCII 문자를 이름 한 덩어리로 묶는 판정만 런타임 유니코드 표를 쓰는데, 이는 오류 메시지를 고르는 용도이고 허용 여부는 바꾸지 않는다. | 확인 |
| G15 | S1 ① 정렬 | 매니페스트가 깨진 모드에 의존하는 모드의 보고. | `id`만 읽혔으면 "설치되었지만 실패"로 보고 의존 모드는 `MOD009`(의존성 로드 실패). `id`도 못 읽으면 알 수 없으므로 `MOD007`(설치 안 됨). | 모더가 엉뚱한 곳을 찾지 않게. | 잠정 |
