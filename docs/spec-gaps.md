# spec 빈틈 목록

`spine-spec.md` 8절의 절차에 따라, 구현하다 spec이 비어 있거나 애매한 곳을 만나면 여기에 적는다. 추측으로 채운 곳도 반드시 적는다. 구현이 끝나면 각 항목을 spec의 결정으로 옮기고 이 목록에서 지운다.

**상태:** 잠정 = 구현이 이렇게 동작하지만 확인 필요 · 확인 = 사용자가 동의함 · 반영 = spec에 옮김.

| # | 위치 | 무엇이 비어 있었나 | 어떻게 정했나 | 이유 | 상태 |

| G1 | S1 ① 정렬 | "의존 관계가 없는 모드끼리는 id 순"을 문자 그대로는 만족할 수 없다. 예: `a`가 `z`에 의존하고 `b`는 무관하면, id 순으로는 a < b < z인데 의존성은 z가 a보다 앞서야 한다. | Kahn 알고리즘에서 "지금 로드할 수 있는 모드 중 id가 서수상 가장 작은 것"을 먼저 둔다. 위 예는 `b z a`. | 결정적이고 입력 순서와 무관하며 의존성을 항상 지킨다. | 확인 |

UTF-8 BOM은 무시. 진단 출력은 (파일, 줄, 열, 코드, 메시지) 순으로 정렬. | VS Code·C# 문자열과 같은 단위. 절대 경로는 골든 출력을 기계마다 다르게 만든다. | 잠정 |

| G7 | S1 ① 발견 | `mod.py`가 없는 폴더, 이름 대소문자가 다른 경우. | `mod.py`가 없는 폴더는 경고 후 건너뜀. `Mod.py`처럼 대소문자만 다르면 오류. `use`·`use_all` 경로도 단계마다 디스크 이름과 서수 비교해, 대소문자만 다르면 `MOD002` + 실제 이름으로 "혹시 …?". `.`으로 시작하는 폴더는 조용히 무시. | 대소문자 무시 파일 시스템(Windows)과 아닌 곳에서 결과가 같아야 한다. | 잠정 |

| G9 | S1 ① 정렬 | `loadAfter`·`optional` 대상이 설치되지 않은 경우. | 조용히 무시. 단, 설치된 모드 중 이름이 아주 비슷한 것이 있으면 경고 + "혹시 …?". | 없어도 되는 참조지만, 오타면 순서가 조용히 틀어진다. | 잠정 |
| G10 | S1 ① 정렬 | 두 폴더가 같은 모드 id를 선언한 경우. | 둘 다 비활성화. 각 진단의 `related`에 다른 쪽 위치. | 어느 쪽을 고를지 근거가 없다. | 잠정 |
| G11 | S1 ① 정렬 | 사이클에 든 모드에 `loadAfter`/`optional`로만 걸린 모드. | 로드한다(사이클 모드는 없는 것으로 보고 순서만 잃음). 필수 의존(`dependencies`)이면 비활성화. | G8과 같은 해석. | 확인 |
| G12 | S1 매니페스트 | `Mod(...)` 필드 목록. spec에는 `id`, `dependencies`, `loadAfter`, `optional`만 있었다. | `version`(S8 세이브 메타에 필요), `defaultLanguage`(X4 P3)를 추가. 필드 이름은 spec 표기대로 camelCase. 모르는 필드는 오류 + "혹시 …?". | S8·X4가 mod.py에서 읽는다고 했으므로. | 잠정 |
| G13 | S2 언어 | 파이썬 부분집합의 어휘 수준 제한. | 들여쓰기의 탭은 오류. 16·8·2진수, 지수 표기, 허수 금지. 문자열 접두사는 `u`만(`r`·`b`·`f`는 미지원). 이스케이프는 `\\ \' \" \n \r \t \0 \xhh \uXXXX \UXXXXXXXX`와 줄 잇기만. 튜플·집합·슬라이스·언패킹·체인 비교·조건식·컴프리헨션은 이 단계에서 미지원(`PAR002`, 구문 오류와 구분). **②에서 바꿈:** 첨자 안의 쉼표(`dict[K, V]`)는 파싱한다(타입 표기용, 값 인덱싱은 평가기가 거부, G22). `def`는 머리부만 파싱한다(G17). 람다는 파싱한다(G33). | spec S2는 문장 수준 허용 목록만 있었다. 컴프리헨션은 spec상 허용이므로 로직 단계에서 지원 예정. 데코레이터와 `match` 문도 같은 방식으로 미지원 보고(`match`는 소프트 키워드라 블록을 여는 줄에서만). | 잠정 |
| G14 | S2 언어 | 식별자에 쓸 수 있는 문자. | **ASCII만**: `[A-Za-z_][A-Za-z0-9_]*`. 비 ASCII 글자가 섞인 이름은 `LEX011` + "표시 문자열은 문자열이나 텍스트 키에". 문자열·주석·Def id(문자열)에는 제한 없음. 나중에 파이썬 규칙(XID 표 + NFKC 정규화, 유니코드 버전 고정)으로 넓힐 수 있다. ASCII는 두 규칙에서 같으므로 기존 모드·세이브가 깨지지 않는다. 그러려면 렉서 밖(세이브 칼럼 이름, 해시, did-you-mean)은 이름을 ASCII로 가정하지 않는다. | 파이썬은 식별자에 XID 표와 NFKC 정규화를 쓴다. 이를 그대로 따르려면 표를 엔진에 넣어야 하고, 따르지 않으면 파이썬과 뜻이 달라진다(한글 완성형/조합형 등). 식별자는 세이브에 남는 내부 이름이고 화면 문자열은 텍스트 키로 간다(S2, X4). 비 ASCII 문자를 이름 한 덩어리로 묶는 판정만 런타임 유니코드 표를 쓰는데, 이는 오류 메시지를 고르는 용도이고 허용 여부는 바꾸지 않는다. | 확인 |
| G15 | S1 ① 정렬 | 매니페스트가 깨진 모드에 의존하는 모드의 보고. | `id`만 읽혔으면 "설치되었지만 실패"로 보고 의존 모드는 `MOD009`(의존성 로드 실패). `id`도 못 읽으면 알 수 없으므로 `MOD007`(설치 안 됨). | 모더가 엉뚱한 곳을 찾지 않게. | 잠정 |
| G16 | S1 ②a 스키마 파일 | 스키마 파일을 어떻게 가려내는지("예: 모드 폴더의 `schema/`")가 예시로만 있었다. | `use(...)`/`use_all(...)` 목록을 파일 단위로 편 뒤, 경로가 `schema/`로 시작하는 파일은 ②a, 나머지는 ②b. 각 묶음 안에서는 목록 순서. mod.py 문법은 그대로. 대소문자만 다른 `Schema/`는 `LOD001`. | S1의 "파일 실행 순서는 `use`로 명시"와 "mod.py는 AST로만 읽는다"를 둘 다 지킨다. 별도 `use_schema`는 문법을 늘리고, 자동 발견은 명시 원칙에서 벗어난다. | 확인 |
| G17 | S2 함수 정의 | 스키마가 가리키는 함수(`derived(int, health_max)`)를 로딩 슬라이스에서 어디까지 다룰지. | `def`는 머리부(이름, 매개변수 이름과 어노테이션, 반환 어노테이션)만 파싱하고 본문은 건너뛴 채 함수 값으로 묶는다. 로드 중에는 호출하지 않는다(호출하면 `EVL005`). 본문 파싱·순수성 판정은 식 언어 단계. 매개변수 기본값, `*args`/`/`는 계속 `PAR002`. 람다는 G33. | ②는 함수를 값으로 등록하기만 하면 된다. 본문 평가기는 식 언어 단계의 일이다. 본문의 구문 오류는 그 단계까지 보고되지 않는다(어휘 오류는 지금도 보고됨). | 확인 |
| G18 | S1 `use_all` | `use_all("dir/")`의 범위와 순서, 같은 파일이 두 번 나오는 경우. | 그 폴더 아래 `.py` 전부를 하위 폴더까지, 모드 폴더 기준 상대 경로(`/`)의 서수 순으로. `mod.py`는 빠진다. 이미 나온 파일은 처음 자리에서 한 번만 실행(`use("schema/base.py")` 뒤 `use_all("schema/")` 허용). `use("mod.py")`는 `LOD001`. | 정렬된 순서는 spec대로. 하위 폴더를 포함해야 `use_all("defs/")` 하나로 정리된 폴더를 쓸 수 있다. 먼저 실행할 파일만 앞에 적는 사용을 막지 않는다. | 잠정 |
| G19 | S1 중복 Def ID | ID가 타입별로 하나인지 전체에서 하나인지. | 타입과 무관하게 **전역에서 하나**. 같은 모드나 의존 관계가 있는 모드끼리면 나중 것만 `DEF001`(의존 대상이면 "override=True" 안내). 서로 의존하지 않는 두 모드면 둘 다 오류(둘 다 비활성화). | S1의 `defs["Name"].field`가 타입 없이 이름으로 찾는다. 독립 모드끼리는 어느 쪽이 맞는지 근거가 없다(G10과 같은 해석). | 잠정 |
| G20 | S2 최상위 이름 | 파일 사이에 최상위 이름(`def`, `x = ...`)이 공유되는지, 다시 묶을 수 있는지. | **모드마다 이름 공간 하나**를 실행 순서(스키마 파일 → Def 파일)대로 쓴다. 쓰기 전에 정의되어 있어야 하고(파이썬과 같음), 한 이름은 한 번만 묶는다(`EVL004`). 내장 이름(`component`, Def 타입 이름 등)은 다시 묶을 수 없다. 다른 모드의 함수를 이름으로 쓰는 방법은 아직 없다. | `import` 대신 `use`라는 S2의 말은 같은 모드의 파일들이 한 덩어리라는 뜻으로 읽었다. 재바인딩 금지는 Starlark 규칙이며 "로드 후 정의는 동결"과 맞는다. | 잠정 |

| G22 | S2 로드 시점 평가 | 로드 중에 어떤 식을 평가하는지. | 리터럴, 리스트, 맵, 이름, 호출, 타입 표기의 `[...]`, 수 앞의 `+`/`-`만. 그 밖의 연산자·속성 접근·값 인덱싱은 `EVL002`(식 언어 단계에서 추가). 맵 키는 `str`·`int`만이고 중복 키는 오류. 이에 맞춰 스키마의 `dict[K, V]`도 K를 `str`·`int`·`DefId[...]`로 제한한다(그 밖이면 ②a에서 `SCH004`. 채울 수 없는 맵을 선언 단계에서 막는다). 첨자 안의 쉼표(`dict[K, V]`)는 이제 파싱된다(G13의 "튜플 인덱스 미지원"을 바꿈). 값 인덱싱에서는 여전히 거부. | Def와 스키마에 필요한 최소한. `fixed` 연산이 아직 없다. 파이썬은 `1 == 1.0 == True`라서 키 타입을 섞으면 뜻이 갈린다. | 잠정 |
| G23 | S4·schema-design 4.2 이름 충돌 | Def 타입과 컴포넌트의 이름 공간, 충돌 시 어느 모드를 끌지. | Def 타입과 컴포넌트는 **한 이름 공간**(둘 다 Def 파일에서 생성자 이름이 됨). 여러 모드가 같은 이름을 선언하면 선언한 모드 모두 `SCH001`. `extend`가 타입 자체의 이름과 겹치면 확장한 모드만, 두 확장끼리 겹치면 둘 다 `SCH005`.
