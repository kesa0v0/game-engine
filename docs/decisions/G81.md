**위치:** S1 ⑥ `.pyi` 스텁의 파일 배치와 CLI (G71 보강, schema-design 4.3)

**무엇이 비어 있었나:** G71이 파일 배치와 `pyrightconfig.json`을 CLI로 미뤘다. 모드 파일은 아무것도 `import`하지 않으므로 스텁이 내장 이름으로 보여야 하는데 그 방법이 없었다.

**어떻게 정했나:** 별도 명령 `engine stubs <mods-dir>`. 로드된 모드마다 `<모드 폴더>/__builtins__.pyi`에 G72 스텁을 덮어쓴다(UTF-8, BOM 없음). pyright는 이 파일의 이름을 그 폴더 아래 파일의 내장 이름으로 넣는다. `<mods-dir>/pyrightconfig.json`은 없을 때만 `pythonVersion` 3.12로 만들고 있으면 건드리지 않는다. 쓴 파일은 stdout에 한 줄씩, 로드 진단은 G79 텍스트로 stderr에 낸다. 종료 코드는 G78이고 파일 쓰기 실패는 환경 문제(2)다. 비활성화된 모드는 로드 결과가 없어 스텁을 만들지 않고 기존 파일도 지우지 않는다(이 모드의 스텁을 어떻게 줄지는 열린 점). `check`는 파일을 쓰지 않는다.

**이유:** pyright 1.1.389 실험: 모드마다 `__builtins__.pyi`를 두면 오타 인자가 잡히고 의존하지 않은 모드의 이름은 “not defined”라서 모드별 보이는 범위(4.3)가 편집기에서도 지켜진다(`executionEnvironments` 없이도 같음). `check`가 읽기만 하는 판정으로 남아 CI에서 모드 폴더가 바뀌지 않고, 명령 하나에 일 하나라 G80과 같은 모양이다. 설정 파일은 모더가 손댔을 수 있어 덮어쓰지 않는다.

**상태:** 확인
