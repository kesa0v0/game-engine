**위치:** G402가 미룬 것: 표시(`mark`)가 경계를 건너는 모양

**무엇이 비어 있었나:** G402는 표시를 값 종류가 아니라 `@world_marks` 결과의 모델 타입으로 두고 모양은 구현 때 정한다고 했다. 경계의 공개 API는 호스트가 기대는 계약이다.

**어떻게 정했나 (사용자가 고름):**

- `WorldMarks(since)`: `since`가 0이면 지금 보일 표시 전부, 아니면 그 도장 뒤에 생기거나 바뀐 것(`Changed`)과 없어진 열쇠(`Gone`). 도장은 `WorldObjects`와 따로 센다.
- `BridgeMark`: `Key`, `Look`, `Where`, `Click`(없으면 보이기만), `Error`. 열쇠는 `함수id/` 뒤에 `key=`의 값이나 그림 이름과 자리, 겹치면 `#순번`(G396). 호스트는 열쇠를 견주기만 하고 뜻을 읽지 않는다.
- 표시 함수가 실패하면 그 함수의 표시는 열쇠가 함수 id인 오류 표시 하나다(`Look`·`Where`가 null, 호스트는 경고만).
- 누르면 호스트가 `Act(Click.Action, Click.Arguments)`를 낸다. `click=`의 동작은 있는 `@ui_action`이어야 한다(실행 오류).
- 로직 언어에 튜플이 없으므로 G395의 `click=("동작", {인자})`는 `click=["동작", {인자}]`로 적는다.

고른 것: `WorldObjects`와 같은 꼴(이것), `WorldObjects`에 합침(엔티티 id 열쇠와 글자 열쇠가 섞임), 전체 목록만 주고 견주기는 호스트(호스트마다 다시 구현).

**이유:** 호스트가 엔티티 물체와 표시를 같은 방식(도장, 바뀐 것, 없어진 것)으로 받아 같은 코드로 만들고 고치고 지운다. 견주기 규칙(G396)이 한곳에 있어 호스트마다 어긋나지 않는다.

**상태:** 확인
