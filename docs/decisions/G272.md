**위치:** X1 호스트가 답을 내는 길을 하나로 (G232에서 이어짐, 사용자 제안: "응답 커맨드(내용: 예)")

**무엇이 비어 있었나:** 답을 내는 호스트 API가 둘이었다. 선택지는 `Answer(연결, 질문, 답하는 엔티티, 번호)`, 응답 커맨드는 `Respond(연결, 질문, 커맨드, 인자)`이고, 할 수 있는 응답 수는 `LegalResponses`가 주지만 선택지는 `Request.Choices`에서 따로 읽었다. 호스트(콘솔의 `ConsoleGame.Options`)는 두 길을 나눠 다뤘다.

**어떻게 정했나:**
- `LegalResponses(질문, by, 최대)`가 선택지마다 엔진 예약 커맨드 **`kesa.pick`**의 수를 응답 수와 같은 목록에 낸다. 인자는 `choice`(선택지 번호)이고 답하는 엔티티는 다른 수처럼 수의 `By`다. 순서는 선택지 수가 먼저(대상 순서 → 선택지 순서), 그다음 응답 커맨드 수다. 최대 개수에 함께 센다.
- 호스트는 무엇이든 `Respond(연결, 질문, 수의 커맨드, 수의 인자)`로 낸다. `kesa.pick`이면 커널 안에서 지금의 `Answer` 길(입구, 번호 범위, 이어 가기)로 간다. 스크립트가 받는 답은 지금과 같다(`r.response`는 `None`, `r.index`·`r.choice`·`r.by`).
- 인자가 값이 아니라 번호인 것은, 못 보는 엔티티가 선택지에 있으면 그 연결의 화면에서 `HiddenValue`로 가려지고(번호는 그대로, G200) 숨김 값은 커맨드 인자로 낼 수 없으며, 같은 값의 선택지도 번호로만 갈리기 때문이다. 그래서 `ViewAs`에서도 가려진 선택지의 수는 빠지지 않는다.
- `kesa`를 모드 id로 쓸 수 없게 해야 모드 커맨드와 겹치지 않는다(지금 로더는 막지 않음, G273). `kesa.pick`은 `responses=`에 적을 수 없고 스텁에도 나오지 않는다. 호스트의 `CheckCall`·`LegalMoves` 같은 커맨드 목록에는 없다(질문에만 딸림).
- `Answer`는 그대로 둔다(커널 안의 길이자 테스트 68곳이 쓰는 API). 없앨지는 나중에 정한다.

**이유:** 사용자의 목표는 "호스트가 분기하지 않는 것"이었다. 커널에서 `Answer`를 없애고 합치면 답 처리와 G126·G138·G139·G161·G234를 다시 열어야 하지만, 호스트가 보는 목록과 내는 함수만 하나로 하면 커널의 답 뜻을 건드리지 않고 같은 목표에 닿는다. AI·테스트도 "합법 수 목록에서 하나를 내기" 한 길이 된다(spec "커맨드 = AI·네트워크·테스트의 기준점"). 선택지를 진짜 커맨드로 만들면(예 커맨드·아니요 커맨드) 단순한 질문마다 선언이 필요해 G138이 `choices`를 둔 이유와 어긋난다. OpenSpiel의 `legal_actions`도 모든 행동을 한 목록의 번호로 준다(일반 지식).

**상태:** 확인

**바뀜:** 엔진 커맨드의 이름은 `engine.pick`이고 모드 id `engine`은 예약이다 → G273.
