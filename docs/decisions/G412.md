**위치:** G390·G343에서 이어서: 그림·공간 정의를 해석하는 코드의 어셈블리

**무엇이 비어 있었나:** G390은 그림 정의가 UXML 장치를 다시 쓴다고 했고, G343은 UXML의 그리지 않는 부분을 `Kesa.Engine.Ui`에 두었다. 그림 정의 해석을 그 어셈블리에 넣을지 나눌지 없었다.

**어떻게 정했나 (사용자가 고름):**

- 해석은 `Kesa.Engine.Ui`에 둔다. 경계만 참조하고 결정론 분석기를 켜는 것은 그대로다.
- 렌더러 인터페이스는 화면용과 판 위 그림용을 나눈다. 시험용 렌더러로 `dotnet test`에서 시험한다(G343과 같은 방식).
- 어셈블리 설명을 "화면과 판 위 그림 정의의 해석"으로 넓힌다.

고른 것: Ui 안(이것), 새 어셈블리 `Kesa.Engine.Looks`(이름은 맞으나 Ui 내부를 열어야 해 내부가 계약처럼 굳음), Unity 패키지 안에만(`dotnet test`로 시험 못 함).

**이유:** 읽기·식·펼치기가 화면 UXML과 같은 장치라 한곳에 있어야 어긋나지 않고, 공개 API를 새로 열지 않는다.

**상태:** 확인
