**위치:** X1 질문의 선택 방법(창·지도 강조 클릭 등)을 누가 정하나, 질문에 실을 추가 정보

**무엇이 비어 있었나:** 이전 엔진 TR은 질문 모양이 C# 클래스로 고정되어(`PendingChoiceData`는 정당·제목·설명·문구 키 목록뿐, `PendingTargetSelectionData`는 후보 id뿐) 해소 중인 카드나 `Amount`처럼 UI가 보여 줄 정보를 더하려면 엔진을 고쳐야 했고, 종류마다 전역 자리가 하나라 새 종류나 동시 질문이 막혔다. 선택 방법은 게임마다 다르다: 효과 코드가 지정(RimWorld `Targeter`·창, Slay the Spire 선택 화면, HOI4 `on_map_mode`), UI가 후보 종류로 결정(MTG 계열 클라이언트), 스크립트는 종류 이름만 주고 모양은 UI 파일이 정함(패러독스 이벤트 `type`·`.gui`). (모두 일반 지식)

**어떻게 정했나:** **스크립트는 제안만, 결정은 UI.** `ask`는 선택 사항으로 `hint=` 문자열을 받아 Request에 싣고 커널은 해석하지 않는다. 해석과 등록이 없을 때의 기본 방식(후보 종류에 따라 강조 클릭 또는 목록 창)은 UI 모듈 몫이다. 질문에는 모드가 정하는 자유 데이터 `data=`(값·엔티티)도 실을 수 있고 UI는 그것과 시뮬레이션 상태(S10 path)를 읽는다. 선택 방법은 답의 의미를 바꾸지 않으므로 응답은 어떻게 골랐든 같은 데이터이고 AI·서버·테스트는 `hint`를 무시한다. 여러 단계 고르기(강조 후 확인, 필터)는 UI 로컬(`@ui_action`)이다. `hint` 이름 규칙과 UI 쪽 등록 방식은 UI 모듈을 만들 때 정한다.

**이유:** 커널이 표시 방식 목록을 검사하면(B) 새 방식마다 커널을 고쳐야 해 TR의 고정 클래스와 같은 벽이다. UI가 후보 종류로만 정하면(C) 예외 연출을 요청할 길이 없다.
