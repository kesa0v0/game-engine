**위치:** S1 ⑤ 링크가 만드는 것

**무엇이 비어 있었나:** spec의 "문자열 참조를 Ref로"는 G32(`Ref`=엔티티, `DefId`=Def) 이전의 문장이라 맞지 않았고, ⑤가 값을 바꾸는지 검사만 하는지 없었다.

**어떻게 정했나:** ⑤는 **검사만 하고 값은 Def id 문자열로 둔다.** ④의 최종 값에서 `DefId["X"]` 값(리스트·맵 안, 맵 키 포함)과 키 컴포넌트의 줄 키를 모두 찾아, 가리키는 Def가 있는지 확인하고 실패는 값을 적은 곳의 `파일:줄`과 "혹시 …?"로 알린다. 새 객체나 참조 색인은 만들지 않는다. 모더는 Def를 id 문자열로 쓴다(S2). 자동완성·따옴표 없는 표기(`Resource.Wood` 같은 속성 접근)는 같은 id 문자열로 풀리는 문법 설탕으로 나중에 더할 수 있다(후속 과제, ⑤는 바뀌지 않음).

**이유:** S2·세이브(S7)·덤프와 맞고 구현이 가장 단순하다. 객체 참조로 바꾸면 세이브·덤프에서 다시 id로 바꿔야 하고 회차를 다시 돌 때 낡은 참조가 남을 위험이 있다.

**상태:** 확인

**바뀜:** 값은 여전히 문자열이지만, ⑤가 짧은 이름을 전체 이름으로 바꿔 둔다(`"Sloop"` → `"harbor:Sloop"`, 맵 키 포함, G261). 그래서 "검사만 하고 값은 그대로"가 "검사하고 전체 이름으로 바꿈"이 된다.
