**위치:** G397이 "끌기 중이면 시작과 지금 자리"를 읽기 내장으로 읽는다고 했으나, G482·G483으로 끌기가 모양 종류의 값이 되었다.

**어떻게 정했나 (사용자가 고름):**

- `drag("입력")` 하나. 입력마다 따로 물어 더하기·빼기 미리 보기를 따로 그릴 수 있다.
- 값은 종류가 낸 값이라 미리 보기와 확정이 같은 것을 본다. 무거운 계산(올가미 채우기)은 호스트에 남는다.
- 칸마다 되는지 다르게 보이는 일은 모드가 표시 함수 안에서 한다.
- 부담(30×30 판 등)은 구현할 때 잰다.

고른 것: 입력 이름으로 종류의 값(이것), 이것에 더해 선언만으로 호스트가 그리는 기본 미리 보기(Factorio `SelectionModeData`처럼, 뒤에 더해도 깨지는 것이 없어 미룸), 이름 없이 묶음 dict(값 타입이 섞이고 어느 끌기든 바뀌면 모두 다시 부름), 날것 경로만(미리 보기의 채우기가 스크립트에서 돌아 예산 문제).

**이유:** RimWorld는 모양을 `DrawStyleCategoryDef`로 고르고 엔진이 계산한 칸으로 지정 도구가 강조를 그린다. Factorio는 엔진이 선언대로 그리고 모드는 끝만 받아, 그리는 중에 게임 상태로 계산한 예상을 보일 수 없다. CS2·웹·uGUI는 움직일 때마다 코드가 다 하며 G397의 당겨 읽기·G482와 맞지 않는다(RimWorld 1.6 위키·Factorio API 문서·CS2 커뮤니티 문서, 일부 일반 지식).
