**위치:** G330에서 이어서: UXML에서 리스트를 반복하는 표기

**무엇이 비어 있었나:** G330은 반복이 UXML 안의 선언형이고 항목마다 변수 하나를 정의한다고만 정했다. 이전 엔진은 `ui-repeater`·`item-template-vpath`·`item-context-key` 세 속성으로 적었고(28곳) 템플릿은 늘 별도 UXML 파일이었다. Vue(`v-for="item in items"`)와 Angular는 속성 하나로 변수와 목록을 함께 적고, XAML은 목록과 템플릿을 따로 둔다(일반 지식).

**어떻게 정했나:** **속성 하나, 자식이 템플릿이다.**

- `for="변수 in 모드.함수(인자)"`: 호출식은 G332의 문법(호출 하나)을 따르고 리스트를 돌려주는 함수를 부른다. 변수 이름은 모더가 짓는다(G330).
- `for`를 단 요소가 항목들을 담는 컨테이너다. 그 요소의 자식들이 항목 하나의 모양이고, 항목마다 자식 한 벌이 만들어진다. 변수는 그 자식들 안에서 쓴다. 바깥 변수도 보인다(G330).
- 정하지 않았다: 항목을 새 리스트와 짝짓는 키, 별도 UXML 파일을 컴포넌트로 가져와 인자를 넘기는 기능(패널 루트 변수를 선언하는 모양과 같은 질문), 비었을 때의 보임, 이전 엔진의 `filter-path` 같은 거름.

**이유:** 속성 하나가 짧고 변수 이름과 목록이 한 줄에 붙어 읽기 쉽다. 작은 반복에 파일을 하나씩 만들게 하지 않는다. 별도 파일 템플릿이 필요한 재사용은 반복이 아니라 컴포넌트의 문제로 따로 본다.

**상태:** 확인
