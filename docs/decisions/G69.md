**위치:** S1 ⑥ 동결본이 기본값을 채우는가 (S4 보강)

**무엇이 비어 있었나:** S4는 "Entity는 읽을 때 없으면 Def 기본값"이라 했는데, 동결된 Def가 `default`를 이미 합쳐 두는지 읽는 쪽이 스키마를 다시 찾는지 없었다.

**어떻게 정했나:** 동결본에는 모든 `const`(컴포넌트 안의 `const` 멤버 포함)의 **완성된 값**이 들어간다: 값이 없으면 스키마 `default`, 리스트·맵은 빈 컬렉션. 값의 출처는 `Default`(스키마 기본값)로 표시해 덤프(S9)에서 구분된다. G67로 필수 값은 이미 다 채워져 있어 구멍이 없다. 런타임 칼럼 `field`의 기본값은 엔티티를 만들 때의 일(S4)이라 Def에 채우지 않고, `field`는 값이 적혀 있을 때만 동결본에 있다. 동결본은 변경 메서드가 없는 읽기 전용 객체다.

**이유:** 런타임이 스키마 없이 Def만 읽으면 되고 값 → 기본값 두 단계를 읽는 코드마다 반복하지 않는다. `field`의 초기값은 `default_from`처럼 계산이 필요한 것도 있어 Def 동결의 일이 아니다.

**상태:** 확인
