**위치:** G300에서 이어서: `to=` 걸음이 닿는 엔티티가 대상 컴포넌트를 가질 수 있는지의 로드 검사

**무엇이 비어 있었나:** G300은 로드 검사로 "닿는 엔티티 타입이 대상 컴포넌트를 가질 수 있는지"를 적었다. 구현하며 보니 이 엔진은 아무 엔티티에나 아무 컴포넌트를 런타임에 붙일 수 있다(`World.Add`, 2단계 테스트의 `Fortified`). 그래서 Def 타입의 컴포넌트 목록에 없다고 보너스가 틀린 것은 아니다. 후보는 (A) 검사하지 않기, (B) Ref 대상 타입의 Def 컴포넌트 목록에 없으면 경고, (C) 오류(런타임에 붙이는 정상 설계를 막음)였다.

**어떻게 정했나:** **(A).** 닿는 엔티티가 대상 컴포넌트를 가질지는 로드 때 보지 않는다. 대상(`"Melee.dmg"`)의 컴포넌트·`derived`가 있는지와 `to=`의 Ref·역방향 컬렉션이 있는지는 그대로 검사한다. 닿은 엔티티에 대상 컴포넌트가 없으면 그 보너스는 읽히지 않을 뿐이다.

**이유:** 이름 오타는 이미 잡히고, 남는 것은 "붙어 있지 않으면 안 나온다"뿐이다. (B)는 런타임에 붙이는 설계에서 끌 수 없는 경고를 남긴다. RimWorld의 `equippedStatOffsets`도 폰에게 의미 없는 스탯이면 조용히 효과가 없다(일반 지식).

**상태:** 확인
