**위치:** S1 Def id의 이름 공간 ⑥ 작성용 스텁의 Def id `Literal` (G72에서 이어짐)

**무엇이 비어 있었나:** 작성용 `.pyi`는 모드마다 만들고(`StubGenerator.Generate(modId, ...)`) Def id 자리(`DefId[X]`, `parent=`, 키 컴포넌트의 키, `patch.*`의 대상)를 보이는 Def id의 `Literal`로 낸다(G72). 이름 공간이 생겨 한 모드 안에서 `"Sloop"`과 `"harbor:Sloop"`이 둘 다 맞는 표기가 되었는데(G261) 어느 쪽을 넣을지 없었다.

**어떻게 정했나:** **그 모드의 스텁에는 내 모드 Def의 짧은 이름과 보이는 모든 Def의 전체 이름을 함께 넣는다**(`Literal["Sloop", "rigs/Brig", "harbor:Sloop", "harbor:rigs/Brig", "core:Galleon"]`). 짧은 이름을 앞에 두어 자동완성에서 내 모드 것이 먼저 보이게 한다. 자리마다 어떤 Def를 넣는지(구체만, `parent`는 abstract 포함 등)는 G72 그대로다.

**이유:** 스텁의 일은 엔진이 받는 것은 통과, 아닌 것은 표시이고, 이 모양만 G261의 풀이 규칙과 같다. 전체 이름만 넣으면 가장 흔한 `spawn("Sloop")`이, 내 모드를 짧은 이름만 넣으면 맞는 `"harbor:Sloop"`이 빨간 줄이 된다. `kind == "Sloop"` 같은 비교는 둘 다 `Literal` 안의 문자열이라 스텁이 잡지 못하므로 G261의 `check` 경고가 맡는다. Pylance가 `Literal` 문자열을 자동완성해 준다는 것은 일반 지식이다.

**상태:** 확인
