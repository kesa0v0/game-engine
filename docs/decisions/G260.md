**위치:** S1 Def id의 이름 공간 ③ 참조할 때 짧은 이름 풀이 (G258에서 이어짐)

**무엇이 비어 있었나:** 정의 자리는 늘 내 모드 기준이지만(G258), Def를 가리키는 자리(`spawn("Sloop")`, `parent=`, `patch.*`의 대상, `DefId` 값, `choose(from_=[...])` 등)에서 짧은 이름을 어느 모드의 것으로 볼지 없었다.

**어떻게 정했나:** **엄격하게 푼다.** 이름의 첫 조각이 그 모드에 보이는 모드의 id(자기 자신 포함, 보이는 범위는 지금 규칙 그대로)면 전체 이름이고, 아니면 내 모드 기준 상대 이름이다(`pirates`에서 `"Sloop"` → `pirates.Sloop`, `"harbor.Sloop"` → `harbor.Sloop`, `"rigs.Brig"` → `pirates.rigs.Brig`). 의존 모드에서 찾아 주는 일은 없다. 내 하위 이름 공간의 첫 조각이 내게 보이는 모드 id와 같으면 정의할 때 오류라서 모호함이 생기지 않는다. 실행 중에 계산된 이름도 그 함수를 정의한 모드 기준으로 같은 규칙을 쓴다.

**이유:** 규칙이 한 줄이고 남의 모드가 바뀌어도 내 이름 풀이가 흔들리지 않는다. 짧은 이름을 의존 모드까지 찾게 하면 의존 모드가 업데이트로 같은 이름을 더할 때 잘 되던 모드가 "모호함" 오류로 깨진다(파이썬 `from x import *`의 문제, 일반 지식). 기본 게임을 가리킬 때 `core.`를 적어야 하지만 어느 모드의 것인지 코드에 드러난다. 사례(일반 지식): Minecraft는 앞부분을 생략하면 한 가지 기본 이름 공간으로만 본다. 파이썬 상대 import식 `.rigs.Brig` 표기는 점 하나를 더 기억해야 해서 고르지 않았다.

**상태:** 확인

**바뀜:** G261에서 구분자가 `:`·`/`로 바뀌어 "첫 조각이 보이는 모드 id면 전체 이름"과 "하위 이름 공간이 모드 id와 같으면 정의 오류"는 없어졌다. `:`가 있으면 전체 이름, 없으면 내 모드 기준이다. 의존 모드에서 찾아 주지 않는 것과 계산된 이름의 기준은 그대로다.
