**위치:** G417에서 이어서: `.input.xml`의 `key=` 안에 무엇을 어떻게 적나

**무엇이 비어 있었나:** G417은 모드 입력의 이름과 기본 키를 `.input.xml`에 두기로 했으나 키를 적는 글의 모양은 정하지 않았다. 모더가 직접 적는 형식이라 계약이다.

**어떻게 정했나 (사용자가 고름):**

- `key="수정 키 + … + 키"`. 조각은 `+`로 나누고 둘레의 빈칸은 무시한다.
- 수정 키는 `SHIFT`·`CTRL`·`ALT`이고 한 번씩, 둘까지 쓴다(Input System의 `OneModifier`·`TwoModifiers`).
- 키는 마지막 조각 하나다. Input System `Key` 열거형의 이름(`R`, `Digit1`, `F5`, `Enter`, `Space`, `Numpad0`)이나 내장 입력 `primary`·`secondary`(마우스 왼쪽·오른쪽 단추, 다른 장치에서는 그 장치의 주·보조 누름)를 쓴다. 대소문자는 가리지 않는다.
- 모르는 이름은 로드 때 문제로 알리고("혹시 …?") 그 선언만 빠진다. 키 이름 목록은 호스트가 준다.
- Unity 패키지는 `com.unity.inputsystem` 1.18.0(Unity 6000.3에 든 버전)에 의존하고 선언마다 `InputAction`을 만든다. 플레이어가 키를 바꾸는 것은 Input System의 다시 묶기와 덮어쓰기 저장을 쓴다(모드 파일은 그대로).
- 같은 키에 수정 키가 더 붙은 입력이 같은 순간 눌리면 그것만 낸다(`SHIFT + R`을 누르면 `R`은 안 남).

고른 것: Input System `Key` 이름(이것), 옛 입력의 `KeyCode` 이름(새 Input System과 이름이 달라 바꾸는 표가 필요함), Input System 바인딩 경로를 그대로(`<Keyboard>/r`, 길고 장치에 묶임), 조합을 속성으로 나눔(`shift="true"`), 패키지가 Input System에 기대지 않고 게임이 연결.

**이유:** 새 Input System에 붙이므로 이름을 처음부터 그쪽에 맞추면 바꾸는 표 없이 이어진다. `+`로 잇는 글은 Factorio `custom-input`의 `key_sequence = "CONTROL + SHIFT + R"`와 같은 모양이고(일반 지식), 마우스를 내장 입력 이름으로 적어 터치·패드 호스트도 같은 뜻으로 읽는다.

**상태:** 확인
