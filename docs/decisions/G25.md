**위치:** S1 Def 리터럴

**무엇이 비어 있었나:** Def 리터럴에 쓸 수 있는 키워드와 검사 시점.

**어떻게 정했나:** 그 타입의 const와 컴포넌트 중 **쓰는 모드에 보이는 것**만. 다른 컴포넌트는 `DEF002`(특정 Def에 붙이려면 Def 패치 안내). 숨은 확장 이름은 `SCH003`. ②b의 검사는 모양까지(컴포넌트 자리에 `Health(...)`, 키 컴포넌트는 `{"Key": Skill(...)}`, `derived` 값은 쓸 수 없음). 값의 타입·범위·기본값은 ⑥. `parent`·`abstract`·`override`는 필드가 아니라 Def 메타 정보로 따로 둔다. 이 셋은 const 이름과 컴포넌트 이름으로 쓸 수 없다(둘 다 Def 리터럴의 키워드가 됨). 선언 함수의 옵션 이름도 그 함수의 멤버 이름으로 쓸 수 없다: `deftype`·`extend`의 `components`, `component`의 `key`·`keys`(값 선언이 오면 "예약된 이름" `SCH004`).

**이유:** 이름은 ②a 뒤에 고정이라 지금 잡는 편이 오류가 가깝다. 값 검사는 패치·상속 뒤의 최종 값으로 해야 한다. 특정 Def에 컴포넌트를 붙이는 길은 S4가 Def 패치로 정했다.

**상태:** 잠정
