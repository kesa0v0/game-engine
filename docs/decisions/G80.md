**위치:** S9 최종 Def 덤프의 CLI 진입점 (G76 보강)

**무엇이 비어 있었나:** G76은 덤프의 모양만 정했고 CLI에서 어떻게 부르는지 없었다. G79로 `check --json`의 stdout은 JSON 한 덩어리뿐이라 같은 stdout에 덤프를 실을 수 없다.

**어떻게 정했나:** 별도 명령 `engine dump <mods-dir>`. stdout에는 G76 덤프 JSON만, 로드 진단은 G79의 사람용 텍스트(요약 줄 포함)로 stderr에 낸다. 종료 코드는 G78 그대로이고, 오류가 있어도 살아남은 모드로 덤프를 낸다. 특정 Def만 고르는 옵션은 뒤로 미룬다.

**이유:** 오류가 있을 때 원인을 보는 것이 덤프의 목적이다. S9의 다른 “왜?” 도구도 각자 명령이 될 자리이고, `check`는 짧고 결정적인 판정으로 남는다. 옵션 하나로 출력 종류가 바뀌는 방식(`check --dump`)은 혼란스럽고, 파일 출력은 실패 경우만 늘린다.
