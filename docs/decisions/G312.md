**위치:** G311에서 이어서: 감싸는 표기

**무엇이 비어 있었나:** G311은 다른 모드의 함수를 감싸기로만 정했고, 무엇을 감싸는지와 원래 함수를 받는 자리를 어떻게 적을지가 비어 있었다. 후보는 (1) 데코레이터 `@wrap(대상)`, (2) 최상위 호출 `wrap(대상, 함수)`, (3) 대입 `pandemic.cure_cost = ...`였다.

**어떻게 정했나:** **(1) `@wrap(pandemic.cure_cost)`.** 감싸는 함수의 첫 매개변수가 바로 안쪽 함수(원래 함수, 또는 먼저 감싼 모드의 것)이고 이름은 자유다(관례는 `original`). 나머지 매개변수는 대상과 이름·개수가 같아야 하고 로드 때 검사한다. 그래서 대상을 위치 인자로 부르든 이름 인자로 부르든 그대로 들어온다. 감싸는 함수는 `@on` 핸들러처럼 로직에서 직접 부르거나 값으로 쓸 수 없다.

```python
@wrap(pandemic.cure_cost)
def virulent_cost(original, player, disease):
    return original(player, disease) + (1 if pandemic.disease_of(disease).Virulent.on else 0)
```

**이유:** `@on`·`@when`·`@command`와 같은 모양이고 함수 곁에 무엇을 감싸는지가 적힌다. (2)는 함수와 대상이 떨어져 있고 감싸는 함수를 따로 부를 수 있는지가 또 문제가 된다. (3)은 다른 모드의 이름을 바꾸는 것으로 읽혀 로드 시점 값이 얼어 있다는 규칙(G309)과 어긋난다. 근거: Harmony는 대상 메서드를 특성으로 적고 원래 인자를 이름으로 받는다(일반 지식).

**상태:** 확인
