**위치:** 로직용 `.pyi`에서 `Ref[T]`와 엔티티 타입

**무엇이 비어 있었나:** 작성용 스텁(G72)은 Def 파일만 생각해 로직의 이름(`command`·`ask`·`query`·`Ref` 등)이 없어서, 엔진이 받아들이는 로직 파일에 pyright가 "정의되지 않음" 오류를 냈다(시나리오 ②로 13개 재현). 같은 이름 `Party`가 Def 파일에서는 생성자, 로직의 `Ref[Party]`에서는 엔티티 타입이다.

**어떻게 정했나:** **같은 클래스가 두 역할을 다 한다:** 스텁에 `type Ref[T] = T`를 두고 Def 타입·컴포넌트 클래스에 엔티티 읽기 속성을 더한다. 그 Def 타입이 가진 컴포넌트는 늘 붙어 있으므로(떼면 엔진 오류) `Seat: Seat`, 그 밖의 보이는 컴포넌트는 None일 수 있는 `Fog`(`Optional[Fog]`), `field`는 쓸 수 있는 속성, `derived`는 읽기 전용 속성, Def 상수는 Def 타입 이름 속성(`party.Party.size`)이다. 타입을 적지 않은 매개변수는 검사하지 않는다. **기준: 엔진이 받아들이는 파일에서 pyright 오류 0개**(모르면 `Any`).

**이유:** pyright 1.1.389 실험에서 Def 생성자·`Ref[Party]`·속성 읽기와 쓰기는 오류 없이, 오타·`derived` 쓰기·타입 틀린 값은 오류로 나왔다. `Ref[T]`를 `Any`로 두는 안은 가짜 오류는 없지만 자동완성과 오타 검사도 없다. 가짜 오류가 나면 모더가 검사기를 끈다. Paradox 스크립트의 VS Code 검사기 CWTools도 게임 규칙 정의로 자동완성과 오타 검사를 준다(일반 지식).

**상태:** 확인
