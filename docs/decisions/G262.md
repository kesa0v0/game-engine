**위치:** X4 Def 이름의 번역 키 (G255에서 멈췄다가 Def id 이름 공간 G258~G261을 정한 뒤 이어짐)

**무엇이 비어 있었나:** Def의 화면 이름을 번역 파일에서 찾을 키가 없었다. Fluent 메시지 이름은 `[a-zA-Z][a-zA-Z0-9_-]*`만 받아 Def id의 `:`·`/`를 그대로 쓸 수 없고, id를 `-`로만 바꾸면 모더가 지은 일반 키와 겹칠 수 있었다(`harbor:already/open` → `harbor-already-open`이 예시 모드의 실제 키 `harbor-already-open`과 같음). 같은 키는 하나만 살아남으므로(G256) 조용히 엉뚱한 글이 나온다.

**어떻게 정했나:** **Def의 번역 키는 Def id의 `:`와 `/`를 `-`로 바꾸고 앞에 `def-`를 붙인 것이다**(`harbor:rigs/Brig` → `def-harbor-rigs-Brig`). `def-` 접두사는 엔진이 예약하고, 모더가 `def-`로 시작하는 일반 키를 쓰면 `check`가 오류를 낸다(엔진 글의 `kesa-`와 같은 방식). Def의 종류 이름은 키에 넣지 않는다. 한 Def에 붙는 여러 글(설명 등)을 나누는 법은 이어서 정한다.

**이유:** 조각에 `-`가 없고(G259) `:`는 첫 조각 뒤에 한 번뿐이라 바꾼 키가 겹치지 않고 id로 되돌릴 수 있으며, 모드 id가 소문자로 시작해(G2) Fluent 이름 규칙도 맞는다. `_`로 바꾸면 조각 안의 `_`와 겹친다. Def id는 종류와 상관없이 전역에서 하나라(G19) 종류 이름 없이도 겹치지 않고, 종류 이름을 넣으면 모더가 종류 이름을 바꿀 때 모든 키가 깨진다. 사례: RimWorld는 Def 번역을 `DefInjected/<Def 종류>/` 폴더에 두어 일반 번역(`Keyed`)과 키 공간을 나누는데 접두사가 같은 효과를 낸다. 패러독스는 키가 id 그대로라 모드끼리 키가 겹치는 일이 흔하다. Minecraft는 등록부가 종류별이라 `item.create.brass_ingot`처럼 종류를 붙인다(일반 지식).
