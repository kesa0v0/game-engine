**위치:** S7 호스트 함수의 호출 모양과 이름 공간

**무엇이 비어 있었나:** S7은 "모드 id 접두사 네임스페이스(`core.find_path`), 충돌은 로드 오류"라고만 했다. 접두사가 로드된 모드여야 하는지, 어느 모드에서 보이는지, 무엇과 충돌하는지가 없었다. 스크립트 함수는 모드마다 따로인 이름 공간에 있어(G20·G105) `core.xxx` 모양은 다른 뜻으로 쓰이지 않고, `random.randint`처럼 "이름 공간.함수" 모양은 이미 있다(G179).

**어떻게 정했나:** **이름은 `소유모드id.자유로운.점.경로`다**(예: `core.path.find`, `core.economy.run_phase`). 커맨드(G109)·단계(G152)와 같은 "모드 id가 맨 앞" 규칙이다. 등록할 때 소유 모드를 밝히고, 게임 개발자가 등록하는 함수는 게임의 기본 모드가 소유한다(나중에 모드 DLL을 지원하면 그 모드가 소유자가 된다). **소유 모드 자신과 소유 모드를 필수 의존성으로 적은 모드에서만 보이고**, 그 밖에서 쓰면 로드 오류다(소유 모드가 빠지면 의존한 모드도 함께 비활성화되어 정리된다, S1). 스크립트는 `import` 없이 전체 경로로 부르고(`core.path.find(a, b)`), 함수 값으로 담을 수 있다(`find = core.path.find`). 경로 중간(`core`, `core.path`)은 값이 아니다. 같은 모드 안에서 같은 경로를 두 번 등록하면 등록 오류, 소유 모드가 로드되지 않았으면 그 등록은 쓰이지 않는다. 모드 스크립트가 최상위에 다른 모드 id와 같은 이름을 만들면 그 이름 공간을 가리므로 로드 오류다. 오타는 로드 때 "혹시 …?"로 잡는다(G108과 같은 검사). **다른 모드의 스크립트 함수를 `모드id.이름`으로 부르는 것은 이번에 열지 않는다**(G20 "아직 없다" 그대로, 공개 범위 등을 따로 정해야 함). 같은 이름 모양으로 나중에 열 수 있다.

**이유:** 처음 기록은 "모드 id 꼴이면 아무 접두사나, 로드된 모드일 필요 없음"이었는데, spec S7 원문("모드 id 접두사 네임스페이스")과 G152("자기 모드 접두사의 단계만 선언, S7 호스트 함수와 같은 규칙")와 어긋나 사용자가 짚었고 고쳤다. 모든 모드에서 보이게 하면 소유 모드가 없을 때 쓰는 쪽의 규칙이 따로 필요하다. 일반 지식: RimWorld에서 다른 모드의 C#을 쓰는 모드는 그 모드를 의존성으로 적는다.

**상태:** 확인

**바뀜:** 다른 모드의 스크립트 최상위 이름을 같은 모양 `모드id.이름`으로 연다. 같은 모드의 호스트 함수 경로 첫 조각과 스크립트 이름이 겹치면 로드 오류 → G309.
