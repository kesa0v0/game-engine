**위치:** G397은 끌기를 "시작 자리와 지금 자리" 읽기로만 정했다. Coup이 자유형 지역 그리기(올가미 안 채우기, Shift·Alt로 더하기·빼기)를 바랐다.

**무엇이 비어 있었나:** 끝난 끌기가 명령이 되는 사건이 없었고, 판 위 입력의 모양(붓·올가미·사각형·상자 고르기·끌어다 놓기·화살표·방향과 폭·길게 누르기)은 계속 늘어난다. 모양마다 엔진 계약을 더하면 끝이 없고, 모두 모드 스크립트에 맡기면 올가미 채우기 같은 일이 실행 예산에 걸린다.

**어떻게 정했나 (사용자가 고름):**

- 공통 날것은 입력 이름, 단계(시작·움직임·끝·취소), 지나간 자리 순서, 그 자리의 커서 아래 엔티티다. 자리가 무엇인지는 공간 종류가 정한다.
- 기본 종류 `path`는 날것을 그대로 핸들러에 준다. 등록에 없는 모양은 모더가 이것을 받아 스크립트로 만든다.
- 그 위에 모양 종류를 호스트에 등록한다(공간 종류 G410과 같은 방식). 엔진이 몇 가지를 주고 게임은 C#으로 더한다. 종류가 내는 값의 모양은 그 종류의 계약이다.
- 처음 구현은 `path`, 그리드용 `lasso`, 그리는 중의 상태를 읽는 내장(G397)이다.

고른 것: 날것과 등록 종류를 겹침(이것), 날것만(새 모양에 엔진이 그대로이나 무거운 모양이 예산에 걸리고 모드마다 같은 코드), 등록 종류만(빠르나 등록에 없는 모양은 게임 C# 없이 못 만듦).

**이유:** 엔진은 값만 알고 기하는 호스트에 둔다는 G410·G416의 기준을 입력에도 쓴다. Unity Input System의 Interaction(`Hold`·`MultiTap`을 등록 클래스로), RimWorld 1.5의 `DrawStyleDef`(그리기 방식을 Def와 작업자 클래스로), Factorio의 선택 도구(엔진은 사각형 하나, 모드가 나머지)가 같은 꼴이다(일반 지식).

**구현하며 정한 것 (사용자 확인 전):**

- `path`: 바로 앞과 같은 자리는 넣지 않는다. 칸 공간(그리드의 `[x, y]`)이면 프레임 사이에 건너뛴 칸을 8방향 이웃 칸(브레젠험 선)으로 메운다. 자기와 겹치면 같은 칸이 다시 들어간다.
- `lasso`: 끝 칸에서 시작 칸으로 곧게 닫은 선도 테두리다. 테두리 칸은 들고, 안은 감은 수가 0이 아닌 칸이다(두 번 감은 고리도 채움). 순서는 y 다음 x. 칸 공간이 아니면 끌기를 열지 않고 판의 문제로 알린다.
- 끌지 않고 뗀 누름에서 모양 종류가 붙은 입력은 나가지 않는다(핸들러는 종류의 값을 받으므로).
- 같은 조합에 모양 종류가 붙은 입력이 여럿이면 모두 함께 그리고 뗄 때 모두 낸다(누름 입력과 같은 규칙).
- 연출을 붙잡고 있을 때(G430) 떼면 건너뛰기만 하고 끌기는 버린다.
- 잰 값(이 컴퓨터, Release, 30×30 테두리 116걸음, 미리 보기가 칸마다 표시 하나): 걸음마다 커서·획 약 0.7ms, 표시 다시 맞추기 약 1.4~1.7ms, 가장 느린 걸음(900칸 가까이) 8~11ms. 칸이 바뀔 때만 든다.
