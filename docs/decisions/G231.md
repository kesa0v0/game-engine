**위치:** S2·S9 속성 이름 오타 검사의 함수 반환 타입 (G228의 2차, 남은 일 1번)

**무엇이 비어 있었나:** G228은 함수를 부른 결과를 늘 모름으로 두어 `a = first(); a.Fod`, `annotated().Fod`(`-> Ref[Unit]`을 적은 함수), `same(x).Fod`(`def same(u): return u`)가 모두 `engine check` 오류 0개였다(2026-10-19 재현). pyright는 셋 다 잡았다. 적은 반환 타입은 파싱만 하고 쓰지 않았다.

**어떻게 정했나:** **적은 반환 타입 + 본문의 `return` + 부른 자리의 인자로 다시 추론(나).** 같은 모드의 함수(이름에 묶은 람다 포함, 커맨드·핸들러·반응 제외)를 이름으로 부르면 결과의 타입은 다음과 같다. 반환 타입을 적었으면 그것이다(본문보다 앞섬, 매개변수와 같은 규칙. 엔티티가 아닌 타입이면 모름). 적지 않았으면 본문의 `return` 값들을 지역 변수처럼 합친다(`None`은 빠지고, 다르면 모름, 값 없는 `return`은 None, 람다는 본문의 타입). 적지 않은 매개변수는 그 호출에서 넘긴 인자의 타입(위치·이름 인자)으로 본문을 다시 훑고, 적은 매개변수는 적은 타입, 넘기지 않은 매개변수는 모름이다. 같은 함수에 같은 인자 타입이면 기억한 결과를 쓴다. 함수 안에서 부른 함수도 같은 규칙으로 따라간다(재귀는 이미 `EVL002`라 모름으로 끊는다). 다시 훑을 때는 오류를 내지 않는다(그 함수 자신의 검사가 낸다). 모드 사이에는 함수를 가져오는 길이 없어 같은 모드만 본다.

**이유:** 엔진만으로 `check`가 pyright만큼 잡아야 한다(G228의 이유). 매개변수를 적지 않는 도우미(`def same(u)`)가 흔해 적은 타입만 보면(다) 효과가 작다. 부른 자리 추론은 pyright의 call-site return type inference와 같다(일반 지식). 재귀가 금지라 끝없이 도는 문제가 없고 G229의 도우미 따라가기와 같은 틀이다.

**상태:** 확인
