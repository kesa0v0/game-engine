**위치:** G430을 고쳐: staged가 무엇을 기다리나

**무엇이 비어 있었나:** G430은 효과만 기다렸다. 뒤에 더한 옮기기(G432)는 붙잡지 않아서, 효과가 흐려지기 시작하면 유닛이 물러나며 미끄러지는 동안 봇이 다음 행동을 하고 플레이어도 다른 유닛으로 공격할 수 있었다(플레이 모드에서 사용자가 봄). 종류마다 기다릴지를 따로 정하면 새 연출을 더할 때마다 빠뜨린다.

**어떻게 정했나:**

- 원칙: staged에서 화면은 세계를 따라잡는 동안 붙잡는다. 따라잡는 중이란 끝이 있는 재생이 붙잡을 때를 아직 넘기지 않은 것이다.
- 재생마다 붙잡을 때가 하나 있다: 효과(퇴장 포함)는 흐려지기 시작할 때까지(G430의 꼬리 겹침), 옮기기는 도착할 때까지. 무대가 재생 목록 하나를 들고 판은 그것이 바쁜지만 본다.
- 순서: 새 효과를 신호마다 한 단계씩 띄우고(앞 단계가 붙잡을 때를 넘기면 다음), 단계가 다 뜨면 판(물체·표시)을 세계에 맞추고, 그로 생긴 재생이 끝날 때까지 더 기다린다. UXML은 그 뒤에 바뀐다.
- 붙잡는 동안의 누름은 건너뛰기다: 재생을 모두 끝 상태로 보내고, 아직 맞추지 않은 판도 옮기지 않고 바로 놓는다.
- 반복 애니메이션(모델 상태)은 끝이 없어 재생이 아니다. 끝이 있는 새 재생(예: 모델의 `once`)은 붙잡을 때만 알리면 같은 규칙을 따른다.
- 붙잡기는 한 연결의 화면 일이다. 세계는 커맨드를 바로 처리하고 아무도 기다리지 않는다. 화면을 다 본 뒤에 다음 차례를 열고 싶으면 게임 규칙(모드가 묻는 준비 확인 등)으로 한다. 단계가 많이 쌓였을 때 빨리 감기는 멀티플레이를 붙일 때 정한다.
- 모더가 정하는 것은 그대로 `Mod(presentation="instant"|"staged")`다. `instant`는 기다리지 않는다. 플레이어가 덮는 설정(빠른 이동 등)은 나중 일이다.

고른 것: 종류마다 기다릴지 적는 칸(모드 선언 `wait_moves`, 그림 정의 `hold`)을 두기와, 원칙 하나(이것). 사용자가 종류마다 정하는 방식 자체를 짚어 원칙으로 갔다.

**이유:** 기다릴지를 종류마다 정하면 새 연출이 생길 때마다 빠진다(옮기기가 그렇게 빠졌다). "화면이 세계를 따라잡는다"는 하나의 뜻이면 판은 종류를 몰라도 되고, 붙잡기가 연결마다의 화면 일이라 서버 권위 멀티플레이와도 부딪치지 않는다. Civilization이 이동·전투 연출을 기다릴지를 플레이어 설정(빠른 이동·빠른 전투)으로 두는 것처럼 이것은 보는 쪽의 일이다(기억에 의한 것).
