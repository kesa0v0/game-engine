**위치:** S1 Def id의 이름 공간 ① 첫 조각 (X4 Def 이름의 번역 키를 정하다 드러남, 사용자 제안 2026-10-20)

**무엇이 비어 있었나:** Def id는 타입·모드와 무관하게 전역에서 하나인 문자열이고(G19) 글자 제한이 없다(G14). `core.Wood`의 점은 엔진에게 그냥 글자라서, 모드 접두사를 손으로 붙이는 관례(spine-spec의 `cost['core.Wood']` 예)와 "서로 의존하지 않는 두 모드의 같은 id는 둘 다 오류"(G19)가 함께 있었다. Def 이름을 번역 키로 바꿀 때(Fluent 이름에는 점이 없음, G255) 점이 구분인지 글자인지 알 수 없었다. 사용자는 `core.submodule.somenamespace.defname`처럼 늘려 쓰려 했고, 엔진이 실제 이름 공간으로 다루기를 제안했다.

**어떻게 정했나:** **Def id는 점으로 나눈 이름 공간이고, 첫 조각은 그 Def를 만든 모드의 id로 강제한다.** 정의할 때 적는 id는 내 모드 기준의 상대 이름이고 엔진이 앞에 모드 id를 붙인다(`harbor`의 `Ship("Sloop")` → `harbor.Sloop`, `Ship("rigs.Brig")` → `harbor.rigs.Brig`). 정의 자리의 점은 언제나 내 모드의 하위 이름 공간이다. 남의 이름 공간에는 새 Def를 만들 수 없고(오류), `override=True` 교체(G21)만 남의 전체 id(`Ship("harbor.Sloop", override=True)`)를 쓴다. 엔진이 나중에 자체 Def를 두면 쓸 이름 공간을 예약한다(지금은 엔진 Def 없음). 이어서 정할 것: 조각의 글자 규칙(번역 키를 위해 `-` 제외 예정), 참조할 때 짧은 이름 풀이와 모호함, 저장·비교에 쓰는 정규형과 스크립트의 문자열 비교, 바뀌는 기존 결정(G14·G19·G21·G34·G63·G72, S8 저장). 구현은 그 뒤.

**이유:** 이름 공간을 들이는 가장 큰 이득은 서로 모르는 모드 사이의 Def id 충돌이 구조적으로 없어지는 것이고 강제해야만 보장된다. 남의 것을 바꾸는 길은 이미 `override=True`로 있어 막히는 쓰임이 없다. 사례(일반 지식): Minecraft는 id가 `모드id:경로`인 이름 공간이고 Forge는 다른 모드의 이름 공간에 등록하면 "Potentially Dangerous alternative prefix" 경고를 낸다(경고만이라 겹침이 남음). RimWorld·Factorio·패러독스는 전역 이름에 모더가 접두사를 손으로 붙인다.

**상태:** 확인

**바뀜:** G261에서 구분자가 점이 아니라 `모드id:경로`, 경로 안은 `/`로 바뀌었다(`harbor.rigs.Brig` → `harbor:rigs/Brig`). 첫 조각을 만든 모드로 강제하는 것은 그대로다.
