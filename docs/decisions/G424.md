**위치:** G417에서 이어서: 핸들러가 부른 입력 이름이 선언에 없을 때 호스트가 어떻게 아나

**무엇이 비어 있었나:** G417은 선언에 없는 입력 이름을 호스트가 로드 때 경고한다고 정했다. 키 선언은 호스트가 읽지만 어느 핸들러가 어느 입력을 받는지는 커널만 안다.

**어떻게 정했나 (사용자가 고름):**

- `IHostSession.WorldInputs()` → `BridgeWorldInput` 목록. 칸은 `Input`(입력 이름), `Target`(Def 타입이나 공간 이름), `Action`(`모드.동작`), `Mod`이고 순서는 로드 순서다.
- 경고는 호스트가 낸다. `Kesa.Engine.Ui`의 `InputLibrary.CheckHandlers(목록)`이 내장 `primary`·`secondary`와 선언에 없는 이름을 문제로 돌려준다.
- 표시의 `inputs=` 이름은 실행 중에 만들어지므로 그릴 때 `LookStage`가 같은 기준으로 한 번씩 경고한다(선언 목록을 받았을 때).

고른 것: 새 메서드와 핸들러 목록(이것), `UiActions()`의 `BridgeCommand`에 입력 목록 칸(명령에서는 늘 빈 칸), 이름 글자 목록만(누가 불렀는지 적을 수 없음).

**이유:** 경고에 어느 모드·동작인지 적을 수 있고, 같은 목록으로 키 도움말("I: 유닛 보기")을 만든다. RimWorld 키 설정 화면이 `KeyBindingDef` 목록에서 나오는 것과 같은 쓰임이다(일반 지식).

**상태:** 확인
