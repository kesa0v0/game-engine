**위치:** S1 ④ Def 하나의 처리 순서와 `inherit` 식 (G30·G50 보강)

**무엇이 비어 있었나:** 자식의 `inherit` 식을 언제 평가하는지, 그 값 위에 패치가 어떻게 쌓이는지가 없었다.

**어떻게 정했나:** Def 하나는 (1) 부모의 최종 값 확정, (2) 자식이 적은 값과 `inherit` 식을 부모 최종 값으로 평가, (3) 그 Def의 패치를 기록된 전역 순서(G50)로 적용, 의 순서로 처리한다. 부모부터 자식으로 위상 정렬해 한 번에 계산한다. 패치 입장에서 `inherit` 칸은 평가가 끝난 일반 값이다(`move=inherit.move + 1`, 부모 `move=2`에 `set 9`이면 9, `add 2`이면 5). 부모 체인의 순환은 `parent` 오류.

**이유:** 패치가 항상 일반 값만 보므로 G53의 기준값이 단순하고, 지연 값에 연산 목록을 쌓는 복잡한 의미가 없다.

**상태:** 확인
