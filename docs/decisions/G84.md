**위치:** S9 경고를 오류로 올리는 옵션 (S9 열린 질문, G78 보강)

**무엇이 비어 있었나:** S9가 “경고를 오류로 승격하는 옵션(CLI)”을 열린 질문으로 남겼고, G78은 올린 뒤의 심각도로 판정한다는 것만 정했다.

**어떻게 정했나:** `engine check --warnings-as-errors` 하나. 모든 경고를 심각도 `error`로 바꾼 진단으로 출력하므로 텍스트, JSON의 `severity`·`counts`·`ok`, 종료 코드가 모두 올린 뒤의 값이다. 정보(`info`)는 올리지 않는다. 코드와 메시지·위치·힌트·관련 위치는 그대로이고 정렬 기준에 심각도가 없어 순서도 같다. `dump`와 `stubs`는 이 옵션을 받지 않는다(사용법 오류). 코드별로 고르는 옵션은 필요해지면 더한다.

**이유:** 컴파일러의 `-Werror`·`TreatWarningsAsErrors`와 같은 이름과 동작이라 익숙하다. 출력의 심각도 자체를 바꿔 G78의 “종료 코드 0 ⇔ `ok`”가 유지된다. 정보는 의심이 아니라 알림(G38의 건너뜀)이라 올리면 호환 패치를 가진 모드가 늘 실패한다. 판정 명령은 `check`뿐이다.

**상태:** 확인
