**위치:** X4 조사 함수와 Def 속성으로 고르기 (spec X4 "조사 등은 언어 팩의 확장 포매터", G267에서 이어짐)

**무엇이 비어 있었나:** `{ $ship }을 샀다`는 넣는 이름의 받침에 따라 "슬루프을"처럼 틀린다. 번역자는 `$ship`에 무엇이 올지 모른다. G267에서 Def 이름 값으로는 `select`가 안 되는 것을 확인해 성별처럼 Def에 따라 고르는 길도 따로 필요했다.

**어떻게 정했나:**
- **조사는 번역문의 함수다:** `{ JOSA($ship, "을") } 샀다` → "슬루프를 샀다"·"갈레온을 샀다". 이름(값의 글)에 고른 조사를 붙여 돌려준다.
- 조사는 짝 중 아무 쪽이나 적는다(`"을"`과 `"를"`은 같은 짝). 짝: 이/가, 을/를, 은/는, 과/와, 으로/로(ㄹ 받침이면 "로": 길로), 이나/나, 이랑/랑, 아/야, 이여/여, 이라/라. 모르는 조사는 `check` 오류(번역 오류라 모드를 끄지 않음, G257)이고 실행 중에는 이름 뒤에 적힌 조사를 그대로 붙인다.
- 마지막 글자가 한글이면 받침으로, 숫자면 읽는 소리로(3 삼 → 을, 2 이 → 를, 10 십 → 을) 고른다. 받침을 알 수 없는 글(라틴 글자 등)은 두 형태를 다 쓴다(`Sloop을(를)`).
- 엔진이 모든 언어의 번역에 넣는다. 이름이 대문자인 것은 Fluent 내장 함수(`NUMBER`)의 관례다.
- **Def 속성으로 고르기:** `{ DEFATTR($ship, "gender") -> [f] 그녀 *[other] 그것 }`. Def 이름 값의 Def에서 그 Fluent 속성(G263, `.gender = f`)의 글을 문자열로 돌려줘 `select`가 된다. 속성 이름과 값은 모더가 정한다. 속성이 없으면 빈 문자열이라 기본 가지로 간다.
- 글을 다 채운 뒤 `(을)를` 같은 표시를 고치는 뒤처리는 두지 않는다.

**이유:** Fluent 함수 문법 그대로라 `check`가 모르는 조사·잘못된 인자를 줄 번호와 함께 잡고, 함수가 G267의 Def 이름 값을 받아 이름 글을 직접 본다(G254 실험에서 `JOSA` 확인). 뒤처리 표시는 아무 자리 뒤에나 붙는 장점이 있지만 보통 글의 괄호와 헷갈리고 오타를 잡기 어려우며, 길을 둘 두면 문서와 검사가 두 배다(사용자가 함수 하나로 고름). 사례: 이전 게임 QU는 `{Target.Label | josa:을}`(U14), RimWorld 한국어는 `LanguageWorker_Korean`이 완성된 글의 `(을)를` 같은 표시를 고친다고 기억한다(소스로 확인하지 않음). `DEFATTR`는 G267 실험에서 함수가 돌려준 문자열로 `select`가 되는 것을 확인한 방식이다.
