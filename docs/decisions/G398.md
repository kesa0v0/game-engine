**위치:** G395에서 미룬 것: 맞는 순간의 피, 떠오르는 숫자처럼 상태가 아닌 사건의 표현

**무엇이 비어 있었나:** 정한 장치는 모두 상태를 보인다. 맞은 뒤의 상태만으로는 "방금 맞았다"를 알 수 없다. 커널에는 신호(`signal`·`emit`·`@on`)가 있지만 경계에는 전해지지 않는다.

**어떻게 정했나 (사용자가 고름):**

- 규칙은 표현을 모르고 신호만 낸다.
- `@world_fx(신호)` 함수는 화면 함수 등급이고, 신호가 난 뒤 호스트가 연결마다 그 연결의 눈으로 부른다. 신호의 값을 받아 `fx(그림 값, at=놓을 곳)` 목록을 돌려준다. 못 보는 대상이면 빈 목록을 돌려주면 된다.
- 신호 자체는 호스트로 나가지 않는다. 함수의 결과만 나가므로 비밀 신호가 화면 쪽으로 새지 않는다.
- 효과의 길이·움직임은 그래픽 정의(G390)가 정한다. 같은 신호에 여러 모드가 각자 함수를 더할 수 있다. 화면 없이 돌 때는 부르지 않는다.
- 판은 효과를 기다리지 않는다. 커맨드가 순식간에 끝나 대상이 이미 사라진 뒤에 효과가 재생되는 문제는 따로 정한다.

고른 것: 게임 규칙이 직접 효과를 부름(RimWorld `FleckMaker`: 짧으나 규칙이 표현을 알고, 누구에게 보이나를 규칙이 판단해야 하고, 화면 없이 돌 때 꺼야 함), 신호를 받는 화면 쪽 함수(이것), 신호를 호스트로 흘리고 그래픽 정의가 신호 이름에 효과를 닮(0 A.D. 메시지 꼴: 스크립트가 필요 없으나 신호를 누가 보나를 거르는 규칙과 조건을 XML에 적어야 함). 일반 지식 포함.

**이유:** 상태 쪽 원칙과 같다: 규칙은 표현을 모르고, 판단은 화면 쪽 함수가, 생김새는 그래픽 정의가 맡는다. 숨긴 정보가 신호를 타고 새는 길을 처음부터 막는다.

**상태:** 확인
