**위치:** G393에서 이어서: 그림 칸과 짝이 되는 자리 칸의 이름

**무엇이 비어 있었나:** G393은 자리 칸을 `Place["T"]`로 적었다. 구현해 보니 내장 이름은 타입 이름으로 쓸 수 없어(SCH004), 장소 타입을 `deftype("Place")`로 지은 시험 모드 두 곳이 깨졌다. 지도 게임에서 "Place"는 흔한 타입 이름이다.

**어떻게 정했나 (사용자가 고름):**

- 칸 타입은 `Where["T"]`. 값은 `at(…)`·`on(…)`·`between(…)` 같은 자리이고, 칸이 하는 일은 "이 엔티티가 화면의 어디에 보이나"에 답하는 것이다.
- `Look["T"]`은 그대로 둔다.

고른 것: `Placement`(흔한 이름을 피하지만 "놓아진다"는 뜻이 남는다), `Place` 예약, 모드 타입이 내장을 가림, `Where`(이것), `Anchor`(UI 기준점과 헷갈림), `ShownAt`(길고 다른 내장과 모양이 다름). 사용자가 place는 "엔티티가 놓아진다"에 가까워 더 맞는 이름을 원했다.

**이유:** 칸은 동작이 아니라 위치를 묻는다. `Look`(무엇으로)과 `Where`(어디에)가 짝을 이루고, `Where`는 모더가 타입 이름으로 쓸 일이 없다.

**상태:** 확인
