**위치:** G82 스키마 스텁에 컴포넌트·Def 타입 이름이 없음

**무엇이 비어 있었나:** G82는 스키마 스텁을 모드와 무관한 하나(`GenerateSchema()`)로 정했다. 그래서 스키마 파일의 `derived` 함수에 `def hmax(h: Health) -> int:`처럼 타입을 적으면 엔진은 받지만 pyright는 `"Health" is not defined` 오류를 냈다(재현함, G207 이전부터 있던 문제).

**어떻게 정했나:** **스키마 스텁도 모드마다 만든다:** `StubGenerator.GenerateSchema(모드 id, 로드 결과)`는 모드와 무관한 부분에 그 모드가 보는 컴포넌트·Def 타입 클래스(G207의 엔티티 읽기 속성 포함)를 더한다. 스키마 파일에서 `fixed`·`TextKey`는 `field(fixed)`에 넘기는 값이므로 클래스 안의 타입 자리에는 `int`·`float` 합과 `str`로 풀어 쓴다. `query`는 스키마 파일에서는 느슨한 것 하나다. ②에서 실패해 선언을 모르는 모드는 모드와 무관한 것만 쓴다. `engine stubs`가 이것을 쓴다.

**이유:** `h.base_max` 같은 읽기의 오타는 로드 때 보지 않으므로(G108) 스텁이 잡는 것이 이득이다(`base_maxx` 재현, pyright 오류로 나옴). 모르는 이름을 모두 `Any`로 두는 안은 스키마 파일의 모든 오타를 놓치고, 타입을 적지 말라고 안내하는 안은 적은 모더에게 가짜 오류를 남긴다.

**상태:** 확인
