**위치:** G254 번역 파일의 위치와 모드 사이의 같은 키 (번역 팩 모드 포함)

**무엇이 비어 있었나:** 번역 파일을 모드 안 어디에 두는지, 언어 이름을 어떻게 적는지, 두 모드가 같은 언어에서 같은 키를 정의하면(남의 모드를 번역하는 팩 포함) 어떻게 하는지 없었다. `mod.py`의 `defaultLanguage`(G12)는 아무 문자열이나 받았다.

**어떻게 정했나:**
- **위치:** 모드 폴더의 `locale/<언어 태그>/` 아래 `.ftl` 파일 전부(하위 폴더 포함). `use` 목록에 적지 않고 엔진이 찾으며, 읽는 순서는 `use_all`처럼 상대 경로의 서수 순(G18). 언어 이름은 BCP 47 태그(`en`, `ko`, `pt-BR`)이고 `defaultLanguage`도 같은 태그여야 한다(틀리면 로드 오류, G12의 이 칸을 확정).
- **한 모드 안:** 같은 언어에서 같은 키(글 이름)가 두 번 나오면 오류.
- **모드 사이:** 같은 언어에서 같은 키를 여러 모드가 정의하면 **언제나 로드 순서상 나중 모드가 이긴다.** 두 모드 사이에 의존 순서(어떤 의존 선언이든 전이 경로, G37과 같은 판정)가 있으면 조용히 덮고, 없으면 경고 하나(키, 두 모드, 이긴 모드). 덮어쓰기는 글 하나(속성 포함) 단위다. 번역 팩은 대상 모드를 `dependencies`·`optional`·`loadAfter` 중 하나로 적으면 경고가 없다.

**이유:** 로드 순서는 의존이 없어도 G1의 동률 규칙(모드 id 서수)으로 늘 하나로 정해진다. G19·G37이 순서 없는 겹침을 오류로 한 것은 그 동률 순서가 모드 이름에 달린 우연이라 게임 규칙이 이름 하나로 조용히 뒤바뀌기 때문인데, 번역은 시뮬레이션이 읽지 않아(X4 P2) 누가 이겨도 게임 결과·저장·리플레이·동기화가 같고, 틀리면 화면에서 바로 보인다(사용자 제안, 2026-10-20). 서로 모르는 모드가 우연히 같은 키를 쓰면 한 모드의 화면에 남의 글이 나오므로 경고는 남긴다. 언어 태그는 Fluent·Linguini가 복수형 규칙을 고르는 이름이고 Space Station 14의 `Locale/en-US/`도 같다. RimWorld의 언어 이름 폴더(`Korean`)는 변형 구분에 이름을 따로 지어야 하고, 패러독스의 고정 목록(`l_korean`)은 모드가 언어를 더하기 어렵다(일반 지식). 사용자가 정한 로드 순서로 나중 모드가 이기는 것은 RimWorld와 비슷하다(일반 지식, 세부 미확인).

**상태:** 확인
