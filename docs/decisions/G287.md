**위치:** X4 커맨드·`@ui_action` 이름의 번역 (콘솔 메뉴의 `skirmish.Move(dir=north, …)`에서 드러남)

**무엇이 비어 있었나:** 콘솔은 낼 수 있는 수를 `skirmish.Move(dir=north, party=#1 빨강, unit=#4 병사)`처럼 코드 이름 그대로 보인다(엔티티만 번역됨). 커맨드·화면 동작 이름과 매개변수 이름에 번역 키를 둘지 정하지 않았다(안내서 9장 "아직 없는 것").

**어떻게 정했나:** 엔진은 커맨드·`@ui_action` 이름의 번역 키를 두지 않는다.
- 버튼 글은 호스트 UI 파일의 일이다(G249). 버튼이 커맨드를 가리키고 커맨드 이름은 그 뒤에 감춰진다.
- 콘솔은 시험용 호스트라 지금처럼 코드 이름을 보인다.
- 할 수 있는 것을 정의에서 자동으로 늘어놓는 호스트(CK3의 인물 상호작용 메뉴, RimWorld의 우클릭 메뉴 같은)가 실제로 생기면 그때 키 모양(예: `command-모드-이름`)과 인자를 넣은 글을 정한다.

**이유:** 사용자가 짚은 대로 보통 화면에서 커맨드는 버튼 뒤에 감춰져 이름이 보이지 않는다(2026-10-21). 키를 예약하고 `check`로 검사하는 일은 자동 목록이 흔한 게임에만 값이 있고, 지금 그런 화면은 시험용 콘솔뿐이다. CK3 상호작용·RimWorld 우클릭 메뉴는 이름 글을 따로 두지만(일반 지식) 그것은 그 호스트가 정할 때 사례로 쓴다.

**상태:** 확인
