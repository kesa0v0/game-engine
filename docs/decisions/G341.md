**위치:** G331에서 이어서: `bind-…`가 받은 경계 값을 요소 속성의 타입으로 바꾸는 규칙

**무엇이 비어 있었나:** 함수 결과는 경계 값(`BridgeValue`)이고 요소 속성은 글자·참거짓·숫자처럼 정해진 타입이다. 글자는 번역기가, 이미지(글자 경로, G335)와 클래스(글자나 글자 목록, G333)는 앞 결정이 정했지만 참거짓 속성과 숫자 속성에 다른 타입이 오는 경우와 실패했을 때의 보임은 없었다.

**어떻게 정했나:** **참거짓은 모드 언어의 판정을 따르고, 나머지는 엄격하게 한다.**

- **글자 속성**(`bind-text` 등): 번역기의 맨 값 규칙을 따른다(G267·G269). 정수와 소수는 그대로 쓴다(G334의 임시 상태).
- **참거짓 속성**(`bind-display`, 활성, `bind-class-<이름>`): 모드 언어의 참거짓 판정을 따른다(G104): `None`·`False`·0·빈 글자·빈 리스트·빈 사전은 거짓이고 그 밖(엔티티 포함)은 참이다. `bind-display="mymod.selected()"`로 "고른 유닛이 있으면 보임"을 쓸 수 있다.
- **숫자 속성**(진행 바의 `value`, 불투명도): 정수와 고정소수점만 받고 다른 타입은 오류다.
- **오류:** 그 바인딩만 실패한다. 요소는 직전 값을 유지하고 오류를 기록하며 다른 요소는 계속 그려진다(`Call` 실패를 오류 줄로 보이고 나머지를 그리는 것과 같은 정신, G247).
- 정하지 않았다: 숨김 값(`BridgeHidden`)을 참거짓으로 볼지, 오류를 기록만 할지 화면에 보일지.

**이유:** 셋 중 고른 것: 참거짓만 모드 언어의 규칙, 나머지는 엄격(이것), 모두 엄격(참거짓 속성도 참거짓만 받아 `selected()` 같은 쓰임을 막고 모더가 `is_selected()`를 따로 만들게 됨), 모두 느슨(맞지 않으면 알아서 바꿔 조용히 틀린 화면을 만듦). 참거짓은 모더가 이미 아는 규칙이라 새로 외울 것이 없다.
