**위치:** G398에서 이어서: 커맨드가 순식간에 끝나 대상이 사라진 뒤에 효과가 재생되는 문제

**무엇이 비어 있었나:** 공격 → 맞음 → 죽음이 한 커맨드에서 끝나 호스트가 볼 때는 대상이 이미 없다. 퇴장 연출, 한 커맨드 안의 순서, 3D와 UXML의 어긋남, 커맨드 안의 중간 상태, 건너뛰기, 연출 중 입력, 커널(나중의 백본 ECS)에 주는 부담을 함께 봐야 했다.

**어떻게 정했나 (사용자가 고름):**

- 네트워크 방식은 spec S6대로 열어 둔다(혼자 하기·락스텝·서버 권위). 판이 연출을 기다리는 길은 버린다: 판이 보는 사람마다 하나인 방식으로 묶이고 서버 권위에서는 안 된다(Wesnoth는 컴퓨터마다 판 사본이라 기다림, 일반 지식).
- 커널·경계는 연출 방식을 모른다. 경계는 연결마다 `@world_fx` 결과를 신호가 난 순서대로, 어느 커맨드 묶음에 속하는지와 함께 넘긴다.
- 방식 둘을 Unity 패키지가 부품으로 준다. 바로 그리기: 새 상태를 바로 그리고 사라진 물체만 퇴장 연출 뒤 지우며 효과는 얹는다. 붙잡고 재생: 새 상태를 3D와 UXML 함께 붙잡고, 이번 묶음의 효과를 옛 화면 위에서 순서대로 재생한 뒤 최종 상태를 적용한다(위치는 옮김 보간, 사라진 것은 퇴장 연출). 신호에 싣지 않은 커맨드 안의 중간 바뀜은 적용 때 한꺼번에 보인다.
- 방식은 모드 선언 한 줄(`presentation=`, 이름은 구현 때)이 고른다. 뒤 모드가 이기고, 말이 없으면 바로 그리기(어느 장르에서도 깨지지 않음). 게임 C#이 덮는 길은 두지 않는다(사례가 생기면 더함).
- 건너뛰기·속도는 플레이어 조절로 따로 두고 게임이 설정 메뉴에 붙인다. 같은 프로세스의 봇은 호스트가 생각할 때를 정하므로 재생 중에는 돌리지 않을 수 있다.
- 모더 쪽 약속은 방식과 상관없이 같다: 효과 함수는 신호가 난 뒤의 판에서 돌므로 필요한 값은 신호에 싣는다. 게임이 쓰는 잔재(시체·전리품)는 모드가 엔티티로 남긴다(RimWorld의 시체 꼴, 일반 지식).
- 백본 ECS 설계 때 "신호 사이의 바뀜을 순서대로 꺼낼 수 있으면 연결마다 단계별 재생을 얹을 수 있다"를 있으면 좋은 요구로 본다.
- 붙잡고 재생 중의 입력은 엔진 약속이 아니라 Unity 패키지의 구현 몫이다(기본: 월드·UXML 클릭을 막고 누르면 남은 재생을 건너뜀). 덤으로 UXML도 붙잡히므로 맞음 뒤의 질문 버튼은 재생이 끝난 뒤에 뜬다.

고른 것: 최종 상태를 바로 그리고 떠나는 물체만 남김(커널 요구 없으나 순서·3D와 UXML 어긋남을 못 풂), 연결마다 사건 순서로 재생(XCOM 꼴: 다 되나 커널에 단계별 바뀜 기록·과거 상태가 필요), 묶음 단위로 붙잡고 재생(커널 요구 없이 순서와 어긋남을 풂), 판이 연출을 기다림(버림). 실시간 게임에는 붙잡기가 맞지 않고 턴제 전술·카드 게임에는 맞아서, 하나를 엔진이 정하지 않고 모드가 고른다.

**이유:** 장르마다 답이 달라 엔진이 정하면 다른 장르를 막는다. 장르를 정하는 것은 규칙을 쓴 쪽(모드)이고 토탈 컨버전 모드도 바꿀 수 있어야 한다. 커널이 연출을 모르니 네트워크 방식과 백본 설계가 열린 채로 남는다.

**상태:** 확인
