**위치:** G399에서 이어서: 연출 방식을 고르는 한 줄의 자리와 이름

**무엇이 비어 있었나:** G399는 모드 선언 한 줄이 방식을 고른다고만 정했고 자리와 이름은 구현 때로 미뤘다.

**어떻게 정했나 (사용자가 고름):**

- 자리는 `mod.py`의 `Mod(...)` 칸 `presentation`이다(`defaultLanguage`와 같은 줄).
- 값은 `"instant"`(결과가 바로 판에 보이고 효과는 얹힘)와 `"staged"`(결과를 붙잡고 이번 커맨드 묶음의 효과를 신호 순서대로 보여 준 뒤 적용). 다른 값은 로드 오류(비슷하면 "혹시 …?").
- 여러 모드가 적으면 로드 순서가 뒤인 것이 이기고, 아무도 안 적으면 `instant`.
- 단계는 신호로 낸 사건 단위다. 신호를 내지 않은 중간 바뀜은 적용 때 한꺼번에 보인다.
- 커널은 값을 검사만 하고 뜻을 모른다. 경계는 모드마다 `BridgeMod.Presentation`, 고른 값을 `BridgeContent.Presentation`으로 넘긴다.

고른 것: `instant`/`staged`(이것), `instant`/`stepped`, `instant`/`sequenced`. 처음 낸 `replay`는 어색하다고 빠졌다.

**이유:** 사용자의 말로 "바로 넘어감"과 "처리 연출을 단계별로"의 선택이고 `staged`가 그 뜻(단계를 밟아 보여 줌)에 맞는다.

**상태:** 확인
