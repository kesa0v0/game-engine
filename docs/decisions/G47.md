**위치:** S1·S3 패치 경로의 키 표기 (G34 보강)

**무엇이 비어 있었나:** Def id(비어 있지 않은 문자열)와 `str` 맵 키에는 점이 들어갈 수 있어서(모드 id만 제한됨), 점 경로 `"Cost.core.Wood"`가 `Cost`→`core`→`Wood`인지 `Cost`→키 `core.Wood`인지 모호했다.

**어떻게 정했나:** 경로 조각은 **이름** 또는 **대괄호 첨자**다. 키가 식별자로 쓸 수 있는 이름이면 점 표기(`"Cost.Wood"`, `"Skill.Medicine.level"`), 점이나 특수문자가 든 `str` 키는 `"Cost['core.Wood']"`, `int` 키는 `"Table[3]"`. S3의 첨자 표기(`Stats[s]`)와 같은 모양이고, 경로 해석은 S3와 같은 코드를 쓴다. 점이 든 키를 점 표기로 쓰면 오류 + "`Cost['core.Wood']`로 쓰세요". 따옴표는 `'`·`"` 둘 다 허용하되 문자열 리터럴 규칙을 따른다.

**이유:** 새 문법이 아니라 S3의 표기를 그대로 쓰며, 대부분의 패치는 점 표기로 짧게 유지된다. Def id의 문자를 좁히는 쪽(B)은 ②에서 정한 규칙을 바꾸고, 리스트 경로(C)는 모든 패치를 길게 만든다.

**상태:** 확인

**바뀜:** Def id에는 이제 점이 없고 `:`·`/`가 든다(G261). `DefId` 키 조각은 G261대로 풀려서 `"Cost.Wood"`는 패치하는 모드의 `Wood`이고, 다른 모드의 Def 키는 `"Cost['core:Wood']"`처럼 첨자로 적는다. 점 표기가 안 되는 `str` 키에 첨자를 쓰는 규칙은 그대로다.
