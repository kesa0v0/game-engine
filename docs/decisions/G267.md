**위치:** X4 번역 인자 값 표 (G254 "숫자 인자의 모양"에서 이어짐)

**무엇이 비어 있었나:** `text("키", 이름=값)`(G113)의 값은 커널의 값(int, fixed, str, 엔티티, 숨김 값 등)인데, 번역 파일(Fluent)에 무엇으로 넘기는지 없었다. 실행 중의 Def id는 그냥 문자열이라(G261) `text("harbor-bought", ship=k)`의 `k`가 Def인지 보통 글자인지 값만으로는 모른다. 그대로 넘기면 화면에 "harbor:Sloop을 샀다"가 나온다.

**어떻게 정했나:**

| 값 | 번역 파일에 가는 것 |
|---|---|
| int, fixed | Fluent 수(fixed는 `Fixed.ToString()`의 십진 표기). 복수형 `select`가 된다. 언어별 숫자 모양과 `NUMBER()`는 나중에 정함 |
| str | 글자 그대로. **다만 불린 Def의 전체 이름과 똑같으면 그 Def의 이름 값**(아래) |
| 엔티티 | 그 엔티티의 Def의 이름 값. Def는 커널이 `text()`를 부를 때 적어 두므로 나중에 엔티티가 없어져도 이름이 나오고 번역기는 월드를 읽지 않는다 |
| 숨김 값(G198) | 엔진이 주는 메시지 `kesa-hidden`("알 수 없음")의 글. 모드가 덮어쓸 수 있다 |
| `text()` 값 | 그 글을 같은 언어로 먼저 번역해 넣는다 |
| bool, None | 문자열 `true`·`false`·`none`. 번역문이 `select`로 고른다 |
| list, dict, 함수 등 그 밖 | `text()`를 부를 때 커널의 실행 오류(정적 타입을 알면 로드 때) |

**Def의 이름 값:** 화면에는 그 Def의 번역된 이름(G262의 키 `def-…`의 메시지 값, 폴백은 G257)이 나오고, 번역 파일의 사용자 함수(조사 등)에는 Def id를 아는 값으로 간다. Linguini는 직접 만든 값 타입으로 `select`를 하지 않으므로 Def에 따라 고르는 일은 함수가 문자열을 돌려주는 식(`{ GENDER($ship) -> … }`, 속성 `.gender`를 읽음)이다. 그런 함수는 조사 함수와 함께 정한다.

**시험(2026-10-20, 임시 프로젝트, 저장소에 남기지 않음):** Linguini 0.11.0에서 `IFluentType`을 구현한 값의 `AsString()`이 자리 표시자에 그대로 나오고(`슬루프을 샀다`, `SetFormatterFunc`는 자리 표시자에 쓰이지 않음), 사용자 함수에는 그 타입 그대로 가서 id를 꺼낼 수 있었다. 그 값으로 `select`하면 `Matches`가 불리지 않고 늘 기본 가지였고, 함수가 돌려준 문자열로는 골라졌다. 수는 `1.5`·`-0.25`·`1234567`처럼 불변 문화권 표기로 나오고(독일어도 `1234.5`), `NUMBER()`는 기본으로 없다. 러시아어 복수형은 1.5 → `other`, 21 → `one`.

**이유:** 넘긴 문자열이 실제 Def의 전체 이름(`:` 포함)과 우연히 같으면서 글자 그대로 보여야 하는 경우는 사실상 없어서, 모더가 감싸거나(`defname(k)`) 번역자가 함수로 바꾸게(`{ DEF($ship) }`) 하는 것보다 잊을 일이 없다(사용자가 고름). RimWorld도 Def·Pawn 자체를 인자로 넘기고 번역문이 `{PAWN_label}`처럼 꺼내 쓴다. 엔티티의 Def를 `text()` 때 적어 두면 기록에 남은 글이 엔티티가 죽은 뒤에도 이름을 보이고, 처음 생각한 `kesa-gone`이 필요 없다. list·dict는 어떤 모양으로 보일지 언어마다 달라 모더가 풀어서 넘긴다.
