**위치:** `.look.xml`·`.space.xml`·`.view.xml`의 오류는 Unity에서 `mods.Looks.Problems`로만 보였다(engine-improvements 9번). 그런데 `check`는 게임 코드 없이 돌아서 게임이 등록한 종류(Commander의 `continuous` 공간)를 모른다. 그대로 읽으면 멀쩡한 모드에 오류가 나고, 그 공간을 쓰는 보는 법에도 "그런 공간 없음"이 뒤따른다.

**어떻게 정했나 (사용자가 고름):** 모르는 종류는 경고로 알리고 내용 검사만 건너뛴다. 게임이 종류 선언 파일을 내보내는 안(G221의 방식), 명령줄에 이름을 적는 안과 비교했다.

**이유:**

- 게임 쪽 작업 없이 바로 쓸 수 있고 잘못된 오류가 나지 않는다.
- 나중에 선언 파일을 더해도 경고가 오류로 엄격해질 뿐 모드 파일은 그대로다.

**약점:**

- `gird` 같은 오타도 경고에 그친다("혹시 grid?"는 붙는다). 게임에서는 그 선언이 빠진다.
- `--warnings-as-errors`를 쓰면 게임 종류가 있는 모드는 정상이어도 실패한다.
- 게임이 기본 요소에 속성을 더해 다시 등록하면 그 속성은 오류로 보인다.
- 모르는 종류를 쓰는 보는 법은 `look-at` 값을 검사하지 못하고, 모르는 리그의 보는 법은 `space`도 검사하지 못한다.

**구현하며 정한 것 (사용자 확인):**

- `Kesa.Engine.Cli`가 `Kesa.Engine.Ui`를 참조한다. 읽기 규칙을 복제하지 않기 위해서이고 커널은 그대로다. 모르는 종류를 받는 것은 `LookKinds.AllowUnknown`이고 Unity 호스트의 동작은 바뀌지 않는다.
- 파일이 없는 그림 경로도 오류다. 켜진 모드 폴더 전부에서 찾는다(G335).
- `.input.xml`은 키 이름 목록이 Unity(Input System)에 있어 읽지 않는다. `.uxml`도 이번 범위에 넣지 않았다.

**구현하며 정한 것 (사용자 확인 전):**

- 경고 코드를 `LOK002`로 따로 둔다. 모델 확장자는 Unity 패키지 기본 로더의 `.glb`·`.gltf`를 알고, 그 밖은 `LOK002`다.
- 진단 위치의 열은 항상 1이다. XML 문제의 위치는 줄까지만 있다. 경로는 모드 id가 아니라 폴더로 시작한다.

**확인:** Commander 모드(`--host` 포함)에서 `continuous` 경고 하나만 나오고 오류는 없다. `samples/skirmish`, `samples/guide`는 새 진단이 없다.

**상태:** 확인

**바뀜:** `.uxml`도 읽는다(G481). `.input.xml`은 그대로 읽지 않는다.
