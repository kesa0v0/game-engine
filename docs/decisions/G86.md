**위치:** S4 런타임 첫 슬라이스의 범위와 입구

**무엇이 비어 있었나:** 상태 변경의 입구는 커맨드(S6)인데 커맨드·Flow·트랜잭션이 아직 없어서, 런타임 모델을 어디서부터 만들지 없었다.

**어떻게 정했나:** 호스트용 C# API `World`부터 만든다. 동결된 `DefSet`으로 만들고, Def id로 엔티티 생성·삭제, 컴포넌트·멤버 핸들로 읽기·쓰기, `all(Type)` 순회, 키 컴포넌트 줄, Ref·`inverse`를 다룬다. 스크립트는 이번에 `derived` 계산에만 쓰고, 스크립트가 쓰는 길(커맨드 본문)은 S6에서 이 API 위에 얹는다. 경계는 핸들과 닫힌 값 타입뿐(P1a)이고 정적 기본 월드는 없다(P3). DOTS의 World에서 시스템을 빼고 컴포넌트를 스키마 칼럼으로 바꾸고 Def 기본값 읽기를 더한 것이다. 저장소 벤치(spec 9절)는 이 API가 생긴 뒤 같은 API로 잰다.

**이유:** 로딩처럼 아래층부터 쌓으면 S4의 규칙을 커맨드 없이 테스트로 확인할 수 있다. 커맨드·저장·“왜?” 도구가 모두 이 API를 부르므로 나중에 바뀌지 않는 경계다. 커맨드·Flow까지 한 번에 하면 트랜잭션·롤백·`ask`·난수열이 엮여 너무 크고, 벤치만 먼저 하면 실제 읽기 규칙이 빠져 결론이 약하다.

**상태:** 확인
