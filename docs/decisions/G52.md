**위치:** S1 ④의 결과를 담는 자료구조

**무엇이 비어 있었나:** ④가 만드는 "상속과 패치가 반영된 최종 값"을 어디에 둘지 없었다. G45는 `DefRecord`를 건드리지 않는다고만 했다.

**어떻게 정했나:** ④는 Def마다 **새 객체 `ResolvedDef`**를 만든다. 칸마다 최종 값과 **출처**(Def가 직접 적음 / 부모에서 상속 / 어느 모드의 패치)를 담는다. `DefRecord`(적힌 그대로)와 `PatchLog`는 읽기 전용으로 두고, `ResolvedDef`는 회차마다 새로 만든다(G49). ⑤·⑥·덤프(S9)는 둘 다 읽을 수 있다. 출처 기록은 `PatchLog`의 상태(적용·건너뜀)를 채우는 근거가 된다.

**이유:** `DefRecord`를 고쳐 쓰면 G45의 분리가 깨지고 회차를 다시 돌릴 때 원본이 오염되며 오류가 가리킬 "적은 그대로"가 사라진다. 읽을 때마다 합성하면 ⑥의 동결 전에 같은 계산이 반복되고 상속 값 위의 보류 연산을 다루기 어렵다.

**상태:** 확인
