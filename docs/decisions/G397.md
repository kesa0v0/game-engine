**위치:** G395에서 미룬 것: 표시 함수가 보는 사람을 아는 법, 그리고 호스트 쪽 입력 상태

**무엇이 비어 있었나:** 표시·칸 함수는 UXML 없이 호스트가 불러 "누구 눈으로"를 인자로 받을 자리가 없다. 또 커서 아래 칸까지의 경로 미리보기, 커서를 따라다니는 건물 미리보기, 끌기 선, Shift를 누른 채 이어 붙이기처럼 게임 상태도 UI 기록도 아닌 입력이 필요하다(RimWorld의 건물 놓기 미리보기, 패러독스의 경로 미리보기, 일반 지식).

**어떻게 정했나 (사용자가 고름):**

- 인자는 받지 않는다. 호스트는 연결마다 함수를 따로 부르고 그 연결 기준의 읽기(`questions()`, `ui.*`, `ViewAs`로 걸러진 엔티티)가 "그 사람 것"만 준다.
- 읽기 내장을 더한다: 맡은 자리 목록, 커서 아래의 엔티티나 자리(`at("공간", 값)`, 없으면 `None`), 끌기 중이면 시작과 지금 자리, 눌린 키. 화면 함수 등급(표시·칸·화면 함수·`@ui_action`)에서만 쓴다.
- 읽은 것만 영수증에 남아, 커서를 읽지 않는 함수는 마우스가 움직여도 다시 불리지 않는다. 커서 바뀜은 자리 단위로만 알린다(같은 칸 안의 움직임은 무시). 부담은 구현할 때 잰다.
- 부르는 자리에서 인자를 줄 수는 없다(엔진이 부름). 설정을 바꿔 쓰려면 입구 함수 안에서 모드 제 도우미 함수에 인자를 넘기고, 다른 모드가 바꾸게 하려면 설정을 Def `const`에 둔다.

고른 것: 읽기 내장(이것: `look` 칸 함수에서도 그대로 쓰고 이미 있는 내장과 모양이 같음), 상황 묶음 `ctx`를 인자로(스텁에서 찾기 쉬우나 `Look["T"]` 칸 모양이 바뀜), 이름으로 채워 주는 인자(이름이 맞아야 채워지고 칸 모양이 늘어남).

**이유:** 보는 사람은 이미 연결 단위 읽기에 녹아 있어 인자로 또 넘기면 같은 정보가 두 길로 들어온다. 표시 함수와 칸 함수가 같은 방식으로 읽는다.

**상태:** 확인

**바뀜:** G487 — 끌기 읽기는 "시작과 지금 자리"가 아니라 `drag("입력")`이 모양 종류의 지금 값을 준다(G482·G483).
