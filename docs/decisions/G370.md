**위치:** G369에서 이어서: 봇의 설정과 붙이기

**무엇이 비어 있었나:** 같은 봇 함수를 난이도·성향별로 다시 쓰는 길과, 어느 엔티티에 어느 봇을 누가 붙이는지가 비었다.

**어떻게 정했나:**

- 무엇을 조정할 수 있는지는 모드가 정한다: `@bot def think(me, level: int = 1, style: str = "balanced")`처럼 맡은 엔티티 뒤의 매개변수는 기본값이 있어야 하고 커맨드 매개변수처럼 로드 때 타입을 검사한다.
- 이번 판의 값은 봇을 붙이는 쪽이 넘긴다. 빠진 것은 기본값, 타입이 틀리면 커맨드 인자처럼 거절한다. 호스트는 봇 함수 목록과 매개변수를 물을 수 있다(커맨드의 `Commands()`처럼).
- 붙이기는 호스트(로비·게임 코드)가 정한다. 엔진은 봇을 스스로 돌리지 않고, Def에 기본 봇을 적는 엔진 표기도 두지 않는다. 캠페인처럼 "이 진영은 이 AI"를 데이터로 정하고 싶은 게임은 그 모드(또는 `std.ai`)가 자기 컴포넌트를 정의하고 호스트가 읽는다(모드와 호스트의 약속, 엔진 계약 아님).

**이유:** 고른 것: 설정 매개변수를 받음(이것), 받지 않고 Def나 기억에 둠. 붙이기는 처음에 "모드가 Def에 기본을 적고 호스트가 바꿈"으로 정하고 엔진 기본 컴포넌트 `DefaultBot`까지 정했다가, 커밋 전에 다시 보아 호스트만으로 고쳤다. 어느 자리에 어느 AI는 판을 차리는 쪽의 정보다: Wesnoth는 진영 타입이 아니라 시나리오 파일의 `[side]`에 AI 설정을 두고(wiki.wesnoth.org/Creating_Custom_AIs), 0 A.D.는 로비와 지도의 플레이어 설정에서 고르며(일반 지식), 패러독스·Civilization은 나라마다 고르는 AI가 없다(일반 지식). 타입 정의(Def 스키마)에 두는 사례를 찾지 못했고, 엔진에는 시나리오 층이 따로 없어 판 구성은 모드 스크립트와 호스트의 일이다. 엔진이 갖지 않아 잃는 것은 로드 때 함수 이름 검사 정도다.

**상태:** 확인
