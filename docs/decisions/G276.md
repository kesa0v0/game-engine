**위치:** S6 동작 종류·S10 3항 `@ui_action`: 화면만 바꾸는 동작을 누가 쓰나 (S6 열린 질문의 바탕)

**무엇이 비어 있었나:** spec은 버튼이 시뮬레이션 커맨드(`command=`)나 클라이언트 로컬 동작(`ui_action=`)을 가리킨다고만 정했다. UI 정의 파일은 호스트의 것(G249)이라, 화면만 바꾸는 동작(유닛 골라 두기, 창 펼치기, 렌즈)을 모드 스크립트가 쓰는지 호스트 언어(Unity C#, Godot 스크립트)가 쓰는지가 정해지지 않았다. 로컬 저장소의 모양과 본문의 범위는 이 답에 달려 있다.

**어떻게 정했나:** 모드 스크립트가 쓴다. 엔진이 `@ui_action`과 UI 로컬 저장소를 주고, 호스트의 UI 파일은 그 이름을 가리키기만 한다. 모양은 커맨드와 같게(이름, 타입 있는 매개변수, 로드 때 검사, 모드가 덮어쓰기·패치), 효과는 로컬로만(게임 상태는 읽기만, 로그·저장·네트워크·되감기·입구 검사 없음, 게임을 바꾸려면 커맨드를 제출). 첫 구현은 콘솔 호스트로 시험할 수 있는 작은 몫(스커미시의 "유닛 고르기 → 공격")부터. 로컬 저장소의 모양, 본문이 할 수 있는 것, 커맨드 이름·인자를 UI 파일에서 검사하는 API는 이어서 정한다.

**이유:** 사용자는 UI의 모양뿐 아니라 동작도 모드로 고칠 수 있기를 바란다(2026-10-19). 호스트 언어로 쓰면 모더가 동작을 고치려면 C#·GDScript를 써야 한다. CK3는 GUI 파일을 모드로 고칠 수 있고, 화면만 바꾸는 것은 저장되지 않는 UI 로컬 변수(`GetVariableSystem`)로, 게임을 바꾸는 버튼은 모더가 선언한 `scripted_gui`(`effect`·`is_shown`·`is_valid`, 멀티플레이 동기화)로 나눈다. RimWorld는 버튼(`Command_Action`)이 델리게이트로 상태를 바로 고쳐 멀티플레이 모드가 버튼마다 동기화 패치를 단다(둘 다 일반 지식, 세부 미확인). 이전 엔진의 QU는 초안을 시뮬레이션 상태에 적어 세이브·네트워크로 샜다(use-cases U12).
