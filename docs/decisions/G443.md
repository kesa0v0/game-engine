**위치:** G413에서 이어서: 판 위 물체의 "위"와 "앞"

**무엇이 비어 있었나:** 공간 종류는 자리만 돌려줘 모델 렌더러가 판 Y를 늘 위로 세웠다. plane="xy" 판에서는 모델이 화면 위로 서서 위에서 보는 판에 꼬리 쪽 모습이 보였다. 모델이 어느 쪽을 볼지 정하는 칸도 없었다.

**어떻게 정했나:**

- 공간 종류(C#, 호스트가 더 등록할 수 있음)는 자리와 함께 그 자리의 틀을 준다: 위 축, 북(위에서 볼 때 위쪽), 동(모드 x가 커지는 쪽). 틀은 거울상이 아니다(위에서 볼 때 북이 위면 동이 오른쪽).
  - `grid` plane="xz": 위 = 판 Y, 북 = 판 Z.
  - `grid` plane="xy": 위 = 판 밖으로 나오는 축(판 정면에서 보는 쪽), 북 = 판 Y(화면 위).
  - `flip-y`는 틀을 바꾸지 않는다. y가 아래로 자라는 판에서 y로 옮기면 남(180)이다. 모더가 y의 방향을 그렇게 선언한 것이다.
  - 구면 지도는 자리마다 바깥쪽, 자유 3D 공간은 공간의 축이 위다(그런 공간 종류가 생기면).
- 모델은 틀에 맞춰 세운다: 모델의 위(glTF +Y)가 틀의 위, 파일의 앞(glTF +Z)이 turn 0의 앞(북).
- `turn`(도, 기본 0)은 위에서 본 시계 방향 나침반 방위다: 0 = 북, 90 = 동, 180 = 남, 270 = 서. `Model`과 `Group`에 쓰고 `bind-turn`으로 그림 값에 묶을 수 있다.
- 카메라 `tilted`(G442)의 `tilt`·`turn`도 그 View의 `space` 틀 기준이다.
- 기울기(`pitch`·`roll`)와 자유 회전은 쓸 곳(자유 3D, 카드 뒤집기)이 생기면 같은 틀 기준으로 더한다.

고른 것: 공간 종류가 자리마다 틀(이것), 판 좌표에 고정(판 Y가 늘 위). 회전 표기로는 판 기준 `turn`(이것), 방향 이름(Wesnoth `facing`·RimWorld `Rot4` 꼴), 세 축 `rotate`. 북을 모드 y가 커지는 쪽으로 두면 `flip-y` 판에서 바닥에 눕는 그림(G444)이 거꾸로 서서, 북은 위에서 볼 때 위쪽으로 둔다.

**이유:** 카메라는 호스트가 아무 각도로나 두므로(G440) 방향을 화면·카메라 기준으로 정하면 카메라에 따라 뜻이 바뀐다. 바닥이 xy·xz인 판, 구면, 자유 3D는 "위"가 다르고 그것을 아는 것은 공간 종류뿐이다. 각도는 Unreal의 Yaw(위 축 둘레 도, 0이 앞)와 Tiled의 `rotation`(시계 방향 도)과 같은 꼴이고, 0°의 앞을 파일의 앞으로 둔 것은 glTF·Godot의 model front(+Z)와 같다(Unreal·Godot·Tiled는 문서 확인). 방향 이름은 판 종류마다 달라 모드 함수가 각도로 바꿔 넘긴다.
