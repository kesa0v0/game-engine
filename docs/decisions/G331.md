**위치:** G330에서 이어서: UXML 해석기가 요소 속성을 모드 함수의 값으로 채우는 표기

**무엇이 비어 있었나:** 요소의 `text`·`value`·표시 여부·USS 클래스를 모드 함수 값으로 채우려면 UXML에 그 연결을 적어야 한다. 이전 엔진은 `binding-path`(글자)·`binding-image-path`·표시·활성·불투명도·클래스마다 속성 이름을 따로 두었다.

**어떻게 정했나:** **묶는 속성마다 같은 규칙 하나를 쓴다.**

- `bind-<요소 속성 이름>="모드.함수(…)"`: 해석기가 그 요소 속성에 함수 값을 넣는다(`bind-text`, `bind-value`, `bind-display` 등). 요소 속성 이름과 값 변환은 해석기의 표가 가진다.
- USS 클래스는 값이 한 칸이 아니라 이름표 목록이라 `bind-class-<클래스 이름>="…"`으로 쓴다. 함수가 참이면 그 클래스를 붙이고 거짓이면 뗀다. `bind-class-` 뒤는 모두 클래스 이름이다(`bind-class-hp-low`).
- 구분 기호는 대시다. 콜론은 XML 이름 공간 접두사로 읽혀 선언이 따로 필요해서 쓰지 않는다. UXML은 이전 엔진처럼 직접 읽는다.
- 정하지 않았다: 호출식의 문법 세부(인자로 허용할 것, 중첩), 함수가 클래스 이름 자체를 돌려주는 모양, 이미지, 값을 속성 타입으로 바꾸는 규칙, 패널 루트 변수를 선언하는 모양, 반복이 항목을 대응시키는 키, 버튼이 `@ui_action`을 가리키는 모양.

**이유:** 셋 중 고른 것: 속성마다 같은 규칙(이것), 이전 엔진처럼 용도마다 다른 이름(익숙하나 지원이 늘수록 모더가 외울 단어가 늘고 "함수 값 → 요소 속성"이라는 하나의 동작을 여러 이름으로 적게 됨), 글자 안에 끼워 넣는 표기(`{…}`: 글자에만 쓰이고 글 조립과 번역은 모드 함수와 `text(…)`가 이미 맡음, G263·G269). Vue의 `v-bind:속성`, Angular의 `[속성]`이 같은 방식이다(일반 지식).
