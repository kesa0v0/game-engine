**위치:** G381의 그림 쪽: 게임 상태와 지도 위 물체를 잇는 표기

**무엇이 비어 있었나:** 그림 쪽(G387~G392)을 정한 뒤에도 어느 엔티티를 올리나, 어디에 놓나, 누르면 무엇을 하나, 엔티티가 아닌 표시(후퇴할 칸·화살표)를 어디에 적나가 남았다.

**어떻게 정했나 (사용자가 고름):**

- 자동: Def에 `look`과 `place` 칸이 있는 살아 있는 엔티티 가운데 보는 쪽 눈에 보이는 것을 호스트가 올린다. 칸 함수는 화면 함수 등급이고 영수증으로 다시 부른다.
- 클릭: `@world_click("Unit")`을 단 `@ui_action`(G381의 "종류마다 화면 동작 하나").
- 그때그때 표시: `@world_marks` 함수가 그림 값과 놓을 곳의 목록을 돌려주고, 목록에서 빠지면 지운다.
- 뷰: 호스트에 이름 붙은 뷰가 있고 그래픽 정의(G390)가 `view=`로 뷰마다 다른 정의를 둔다. 맞는 정의가 없으면 기본 정의, 비운 정의는 그 뷰에서 안 그린다. 동시에 뜬 화면(본 지도와 미니맵)과 줌 단계를 이것으로 가른다. 한 화면 안에서 바뀌는 지도 모드는 `Look` 함수가 `ui.*`를 보고 값을 더 넘긴다.
- 남은 약점: 뷰마다 올라가는 엔티티 집합이 다른 경우(그 뷰에서만 보이는 것)와 뷰마다 위치 체계가 다른 경우는 사례가 생기면 정한다.
- `place`가 돌려주는 값의 모양은 따로 정한다.

고른 것: 자동 + 함수 칸(이것), 월드 XML 문서(한눈에 보이나 새 Def 종류를 더하는 모드가 문서를 고치거나 더 둬야 하고 XML이 두 겹), 호스트 C#(모더가 새 종류를 못 올림).

**이유:** G388에서 함수 칸을 고른 기준(새 Def를 더하는 모드가 남의 파일을 고치지 않음)이 여기서도 통한다. 화면마다 다른 생김새는 G387의 "뜻은 호스트가"로 메운다: 그림 값은 하나이고 뷰마다 정의가 다르다. 사례: 패러독스의 줌에 따른 모델·아이콘 전환과 지도 모드, 이전 엔진의 `LensOverrides`(일반 지식 포함).

**상태:** 확인

**바뀜:** 자리 칸의 타입 이름은 `Place["T"]`가 아니라 `Where["T"]` → G400.
