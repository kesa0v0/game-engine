**위치:** G297에서 이어서: 선언에서 모인 기여 줄의 출처

**무엇이 비어 있었나:** `contribs()`의 줄은 `op`·`value`·`source`(엔티티나 None)를 가지고 `Explain`도 이 줄을 근거로 보인다. 저장된 줄은 넣는 쪽이 출처를 주지만, 선언에서 모인 줄은 넣은 이가 없다. 화면·`Explain`은 어디서 왔나("강인함 +3")를, `derived` 함수는 가끔 출처로 거르기를 바란다. 후보는 (A) `source`를 선언을 든 엔티티로 하고 `component`·`key`를 더하기, (B) `source`는 None이고 Def id 하나(`origin`)를 주기(같은 Def 안의 어느 컴포넌트인지 잃고, 관계로 오는 보너스에는 결국 엔티티 출처가 필요)였다.

**어떻게 정했나:** **(A).** 선언에서 모인 줄의 `source`는 그 선언을 든 엔티티다(지금은 늘 자기 엔티티). 줄에 속성 둘을 더한다: `component`는 선언이 있던 컴포넌트 이름(`"Trait"`), `key`는 키 줄에서 왔으면 그 키 Def id(`defid("Tough")`), 아니면 None. 저장된 기여 행은 `component`·`key`가 None이다. `Explain`의 기여 근거도 같은 셋을 담는다. 화면에 무엇으로 보일지(키 Def의 번역 이름이나 컴포넌트 이름)는 호스트와 모드가 정한다.

**이유:** 나중에 관계로 오는 보너스(칼 엔티티가 든 선언)를 열면 `source`가 그 칼이 되어 "이 보너스를 낸 엔티티"라는 뜻이 저장된 줄과 같아진다. ECS로 말하면 어느 엔티티의 어느 컴포넌트(쌍)에서 왔는가이다. 지금 모양에 속성 둘만 더한다.

**상태:** 확인

**바뀜:** `component`는 이름 문자열이 아니라 컴포넌트 값이다(`c.component == Traits`) → G308.
