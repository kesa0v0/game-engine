**위치:** G150에서 이어서: 재귀 깊이 상한을 어디에 둘지 정하다가

**무엇이 비어 있었나:** 단계 예산(G101·G224), 신호 깊이(G147·G150), `advance` 합(G168), 정착 회차(G171)는 호스트가 `World`를 만들 때 넘기는 옵션이었다. G150은 "엔진 설정을 모드가 선언하는 자리가 아직 없어서" 호스트에 두었고 "그런 자리가 생기면 단계 예산과 함께 옮긴다"고 적었다. 게임 로직은 모드이고 호스트는 그리는 층이므로 게임의 성질인 상한은 모드가 정해야 한다.

**어떻게 정했나 (사용자가 고름):**

```python
patch.set("engine:Rules", "max_signal_depth", 200)
patch.add("engine:Rules", "step_budget", 50000)
```

- 엔진이 Def 타입 `EngineRules`와 Def `engine:Rules`를 미리 둔다(엔진 신호·컴포넌트처럼 모두에게 보이고 같은 이름 선언은 `SCH001`). 칸 기본값은 전과 같다. 모두 `int`이고 `min=1`이라 0을 넣으면 그 패치를 한 모드의 `VAL003`.
- 두 모드가 같은 칸을 바꾸면 보통 패치 규칙이다: 순서가 없으면 충돌, 있으면 나중이 이기고 `PAT011` 정보.
- 모드는 `EngineRules(...)`로 Def를 만들 수 없다(로드 오류). 덮어쓰기(`override=True`)도 같은 이유로 막힌다.
- 덤프에는 모드가 패치했을 때만 나온다. 스텁에는 패치 대상 id와 `defdata`로 읽는 상수만 나온다(생성자·`query`·`spawn` 없음). 호스트에 넘기는 Def 목록과 번역 대상에서는 빠진다.
- 상한을 넘었을 때의 안내 문구는 호스트 옵션 대신 이 패치를 가리킨다.
- 봇 한 번의 예산(G375)을 호스트가 봇마다 주는 경계 API는 그대로다. 주지 않으면 이 Def의 `action_step_budget`이다.

고른 것: 엔진 Def를 모드가 패치(이것), 매니페스트에 적기(모드끼리 다를 때의 규칙을 새로 정해야 함). 범위: 재귀 깊이와 함께 기존 상한을 모두 옮김(이것), 재귀 깊이만.

**이유:** 패러독스의 `defines`처럼 게임 상수를 모드가 덮는 모양이다(일반 지식). 충돌·순서·이력은 이미 있는 Def 패치 규칙이 맡아 새 규칙이 없다. 모드 목록이 같으면 값도 같아 멀티플레이에서 저절로 맞는다(호스트 옵션은 호스트마다 다를 수 있었다). 실행 환경이 정할 안전 천장(C# 스택)은 이것과 따로 엔진이 쥔다.
