**위치:** 끌기 입력(G482)과 누름 입력이 같은 포인터 단추를 쓸 때. Unity 호스트는 누르는 순간 `primary`를 냈다.

**무엇이 비어 있었나:** 누르는 순간에는 사용자가 끌지 그냥 뗄지 모른다. 그대로면 부대 칸에서 지역을 그리기 시작할 때 부대 고르기와 지역 칠하기가 둘 다 일어난다.

**어떻게 정했나 (사용자가 고름):**

- 포인터 단추의 누름은 언제나 뗄 때 낸다. 그 단추에 끌기 입력이 걸렸는지와 상관없다.
- 누른 채 문턱을 넘으면 그 누름은 취소되고 끌기가 된다. 문턱은 호스트 설정(화면 거리)이고 모더 계약은 "문턱을 넘으면 끌기"뿐이다.
- 키보드 키는 누르는 순간 낸다.
- 누름 입력이 받는 대상(G419)은 누른 자리의 커서 아래로 찾는다.

고른 것: 포인터 단추는 언제나 뗄 때(이것), 끌기 입력이 걸린 단추만 뗄 때(다른 모드가 끌기를 더하면 같은 단추의 누름 시점이 바뀜), 둘 다 보냄(모드가 겹침을 피해야 함), 같은 단추에 함께 못 검(흔한 조작이 막힘).

**이유:** UI 층의 관례와 같다: 웹 `click`과 `draggable`, Unity uGUI의 `IPointerClickHandler`와 `pixelDragThreshold`, Unreal UMG 버튼의 `DownAndUp`·`PreciseClick`과 Slate 끌기 문턱, Godot 버튼의 Button Release(일반 지식). Unity Input System·Unreal Enhanced Input 같은 입력 액션 층은 시간(Tap·Hold)으로만 가르고 거리 끌기는 게임에 맡긴다.
