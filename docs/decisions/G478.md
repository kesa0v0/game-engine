**위치:** G475 3단계의 호스트 API 모양이 비어 있었다. 낱개 `Get`으로는 칼럼 저장의 이득이 호스트에 닿지 않는다(engine-improvements 15번).

**어떻게 정했나 (사용자가 고름):** 읽기 전용 조각. 호스트 배열로 복사하는 안, 조각에 직접 쓰는 안과 비교했다.

**이유:**

- 복사하지 않아야 Burst에 메모리를 그대로 넘길 수 있다(15번).
- 조각에 직접 쓰면 되감기, 바뀜 도장, 범위 검사를 우회한다. 쓰기는 호출 하나로 받아 이것들을 묶음으로 처리한다.
- 표가 Def마다 따로 있고 죽은 줄이 낄 수 있어 조각이 여러 개다. 살아 있는 구간만 잘라 주므로 줄 번호를 밖에 보이지 않는다. 줄 번호는 판마다 다르고 줄 비우기로 바뀌므로 정체성이 될 수 없다.
- 구조 변경은 즉시 반영되므로(G88) 조각의 수명은 다음 구조 변경까지다. 지난 조각을 쓰면 틀린 값을 주지 않고 오류를 낸다.

Unity DOTS가 chunk마다 배열을 주는 것과 비슷하다. 일반 지식이며 코드로 확인하지 않았다.

**구현하며 정한 것 (사용자 확인 전):**

- API는 `Parts(Def 타입, 멤버들)`, `part.Ids`, `part.Longs(멤버)`(int, bool은 0과 1), `part.Fixeds(멤버)`, `WriteColumn(멤버, ids, 값들)`이다. 조각은 Def 등록 순, 조각 안은 id 순이라 저장하고 불러도 순서가 같다.
- Ref는 읽는 값이 대상의 생사에 따라 달라지므로(G91) 조각에 넣지 않는다. 칸은 숫자로 펴 두었다.
- 런타임에 붙은 값이 조각에서 조용히 빠지지 않도록, 그 컴포넌트를 붙인 엔티티가 있으면 `Parts`가 오류를 낸다. 게임 중에 붙이면 같은 호출이 그때부터 실패할 수 있다.
- 보는 쪽으로 부르는 중이거나 시험 판이면 못 보는 줄과 가린 줄을 뺀다. 영수증과 `when`을 위해 읽은 줄을 기록한다.
- 도장은 엔티티마다 남긴다. 영수증이 엔티티별로 보기 때문이다. 되감기 기록만 묶음에 하나다.

**약점:** 이미 꺼낸 `ReadOnlySpan`은 언어상 검사할 수 없어, 구조 변경 뒤에 계속 읽어도 오류가 나지 않는다. 오류는 조각에서 새로 꺼낼 때와 다음 조각으로 넘어갈 때 난다.

**측정 (.NET 9, 1만 개, 4초 예열):** 읽기는 `Get` 25ns·24B에 조각 0.2ns·0B. 쓰기는 `Set` 38ns에 `WriteColumn` 29ns. 쓰기는 엔티티를 찾고 도장을 찍는 비용이 남아 차이가 작다.

**남은 것:** Unity(Mono·IL2CPP)에서 `Span`과 Burst 전달을 돌려 보지 않았다.
