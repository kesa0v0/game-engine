**위치:** S9 `check` 출력 스키마

**무엇이 비어 있었나:** S9는 “`check` 출력 스키마”를 열린 질문으로 남겼다.

**어떻게 정했나:** `check` JSON은 한 객체다: `version`(1, 스키마가 바뀌면 올림), `ok`(오류 심각도가 하나도 없을 때만 true, 경고·정보는 영향 없음), `counts`(`error`·`warning`·`info`), `mods`(`loaded`는 로드 순서, `disabled`는 모드 id 순), `diagnostics`(결정적 정렬: 파일, 줄, 열, 코드, 메시지). 진단 하나는 `code`, `severity`(소문자 `error`/`warning`/`info`), `message`, `mod`, `file`, `line`, `col`, `hint`, `related`(위치 목록 `file`·`line`·`col`)이고 키는 항상 있으며 없는 값은 `null`이거나 빈 배열이다. 키 순서와 들여쓰기가 고정이라 같은 입력이면 같은 문자열이다. 직렬화는 라이브러리 없이 직접 쓴다(Unity 소스 패키지 P1a). 생성은 순수 함수 `CheckReport.ToJson`이고 파일 읽기·종료 코드·경고를 오류로 올리는 옵션은 CLI의 일이다.

**이유:** CI에서 diff할 수 있어야 하고, 키가 항상 있어야 소비하는 쪽이 존재 검사를 안 한다.

**상태:** 확인
