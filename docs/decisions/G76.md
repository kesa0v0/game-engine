**위치:** S9 최종 Def 덤프 (“왜?” 도구 1)

**무엇이 비어 있었나:** S9는 “최종 Def 덤프 + 필드별 출처”라고만 했고 형식·범위가 없었다.

**어떻게 정했나:** `check`와 같은 JSON(`version` 1)이다. **`abstract`를 포함한 모든 Def**를 등록 순서로, Def마다 `id`·`type`·`mod`·`abstract`·`parent`(id 또는 null)·`consts`·`components`를 낸다. 값마다 `value`, `origin`(`own`·`inherited`·`patched`·`default`), `source`(처음 적은 Def·모드·위치, `default`면 스키마 선언 위치만), `patches`(그 칸에 영향을 준 패치를 적용 순서로, 부모 쪽 패치 먼저: `mod`·`def`·`op`·`path`·`value`·`status`·`file`·`line`·`col`)를 둔다. 구체 Def는 기본값까지 채운 동결본을, `abstract`는 기본값 없이 상속을 펼친 값을 낸다. 컴포넌트는 `values`·`rows`·`attachedBy`로 낸다. 값 표현: 정수는 JSON 정수, `fixed`는 문자열(`"1.5"`, 정밀도 보존), 문자열·bool·`null`은 그대로, 리스트는 배열, 맵은 객체(정수 키도 문자열), 함수는 `{"function": 이름}`. **실패한 패치는 덤프에 넣지 않는다**: 실패한 모드는 비활성화되어 최종 값에 기여하지 않으므로 `check` 진단(`PAT0xx`)으로만 본다(G45). (구현 보강, 2026-10-19) "영향을 준 패치"는 값을 만들 때 따라 적는다(`ResolvedValue.Patches`): 물려받은 값은 부모의 것을 그대로, 자식이 직접 적은 값과 통째 `set`은 그 전 것을 지우고, `add`·`append`·`remove`·맵 항목 `set`은 그 전 것 뒤에 쌓고, `merge="append"` 리스트와 `inherit` 식은 읽은 부모 값의 것을 잇는다. 그래서 자식이 덮은 부모 패치는 나오지 않는다(전에는 부모 체인의 겹치는 경로를 모두 훑었다).

**이유:** 덤프의 목적은 최종 값이 어떻게 만들어졌는지 보이는 것이다. 실패 항목을 섞으면 비활성화된 모드가 기여한 것처럼 보이고, 남기려면 회차 사이로 이력을 보존해야 한다.

**상태:** 확인
