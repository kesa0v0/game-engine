**위치:** G387에서 이어서: 그림 이름이 정적인가 동적인가, 어디서 오나

**무엇이 비어 있었나:** 다친 모습·진영 색·업그레이드처럼 판 중에 바뀌는 그림을 어디서 정할지 없었다. 이전 엔진은 Def에 고정하고 색만 식으로 그릴 때 계산했고(`Self.Owner.Def.Color`), 지도 모드마다 `LensOverrides`를 두었다.

**어떻게 정했나 (사용자가 고름):**

- 표시는 모드의 순수 함수를 불러 그림을 받는다. 이름을 Def `const`에 두든 컴포넌트에 두든 모드가 정한다.
- 함수 칸 `Look["T"]`를 더한다(`const`에만, G374의 `Score`와 같은 좁은 칸). T를 받아 그림을 돌려주고, 화면 함수와 같은 등급이다(게임 상태·`ui.*`·보는 쪽의 눈을 읽고, 쓰지 않는다).
- 칸에 글자를 넣으면(`Unit("Infantry", look="infantry")`) 늘 그 이름이다.
- 돌려주는 값의 모양(이름 하나인지, 표식·값을 더하는지)은 따로 정한다.

고른 것: 중앙 함수만(엔진에 더할 것 없으나 Def를 더하는 모드끼리 함수 덮어쓰기로 부딪힘), 중앙 함수 + 좁은 칸 `Look`(이것), 일반 `Fn["T", R]`을 이번에 엶(쓸 곳이 넓으나 반환 타입 표기·스텁·검사를 정해야 함), Def `const`만(판 중에 못 바뀜), 컴포넌트에 두고 규칙이 바꿈(보이기만 하는 값이 게임 상태에 들어가고 같은 사실이 두 곳).

**이유:** 사용자가 `look`이 함수를 받는 안을 냈다. 규칙이 Def에 붙으면 새 Def를 더하는 모드는 제 함수를 달기만 하고 남의 것은 Def 패치로 그 칸만 바꾸므로 모드끼리 합쳐진다(G239에서 중앙 함수 하나를 버린 이유와 같음, RimWorld도 `graphicClass`로 고르는 법을 Def마다 둠). 좁은 칸이라 `Fn`을 열지 않아도 되고, 나중에 열면 그 다른 이름으로 둘 수 있다.
