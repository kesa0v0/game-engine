**위치:** G395에서 이어서: 판 위 물체를 누르는 것 말고 다른 입력

**무엇이 비어 있었나:** G393·G395는 판 위 입력을 "누름" 하나로 보았다. 그러면 수정 키(Shift+우클릭으로 명령 쌓기), 커서 아래 물체에 키(Factorio의 `R` 회전·`Q` 스포이드, RPG의 `E` 상호작용), 보조 단추(RimWorld·패러독스의 우클릭 명령)를 받을 길이 없다.

**어떻게 정했나 (사용자가 고름):**

- 판 위 입력은 이름 붙은 입력이다. 엔진 내장 입력 `primary`·`secondary`(클릭·탭·패드 단추)와 모드가 선언한 입력(이름과 기본 키, 수정 키는 키 조합에 넣는다)이 있다.
- 핸들러는 `@world_input("입력", "대상 종류")`을 단 `@ui_action`이다. 대상 종류는 엔티티 타입이나 공간 이름이다. `@world_click("T")`은 `@world_input("primary", "T")`이 된다.
- 호스트가 실제 키·마우스·터치를 입력 이름으로 바꾸고 플레이어의 키 바꾸기를 맡는다. 경계로는 입력 이름과 커서 아래 대상(표시·엔티티·자리)이 가고 맞는 핸들러는 커널이 찾는다.
- 받는 순서 표시 → 엔티티 → 빈 자리(G395)는 입력마다 그대로 쓴다.
- 이어서 정할 것: 모드 입력을 선언하는 곳과 키 표기, 표시(`mark`)의 `click=`이 다른 입력을 받는 법, 대상 없이 고른 것에 쓰는 단축키(같은 입력을 화면 쪽에 묶기). 끌기와 커서 올리기(시작·진행·끝이 있음)는 따로 정한다.

고른 것: 이름 붙은 입력(이것), 클릭만 판 위에서 받고 키는 고른 것에만(커서 위 키는 "먼저 누르고 키"로 우회해야 함), 핸들러가 날것의 입력을 받음(키 바꾸기를 모드마다 만들고 터치·패드 호스트가 바꿔 줄 길이 없음).

**이유:** 한 틀로 클릭·키·수정 키·몸짓이 들어오고 키 배치는 플레이어와 호스트의 일로 남는다. Factorio의 `custom-input`이 이름과 기본 키를 데이터에 선언하고, 들어오면 커서 아래 물체와 함께 스크립트 이벤트를 연다(일반 지식).
