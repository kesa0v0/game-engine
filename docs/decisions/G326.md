**위치:** G325에서 이어서: 경계 너머로 보내는 값의 모양

**무엇이 비어 있었나:** 화면 함수의 결과, 질문의 선택지와 `data`, 합법 수의 인자, 거절 사유의 인자는 모두 커널 `Value`다. 그런데 `Value`에는 데이터 말고도 함수 값·클로저·컴포넌트 값처럼 경계에 나오면 안 되는 것이 섞여 있고, 연결부가 그대로 쓰면 커널 어셈블리에 묶인다(G324의 "커널 객체가 새지 않는다"). 화면은 엔티티를 클릭해 다시 보내야 하고(id), 이름·그림으로 그려야 하며(Def), 번역 글·숨긴 값·고정소수점을 다뤄야 한다.

**어떻게 정했나:** **경계 전용의 작은 값 타입을 엔진 무관한 작은 어셈블리에 둔다.**

- 닫힌 목록: 없음, 참거짓, 정수, 고정소수점(원래 정수값 그대로, 실수로 바꾸는 것은 화면 표시 때만), 문자열, 리스트, 사전, 엔티티(id와 Def id), 숨김, 글(키와 인자), 선택지(option).
- 같은 프로세스 구현이 커널 `Value`를 이 타입으로 바꿔 넘긴다. 경계에 못 나오는 값(함수 값 등)이 돌아오면 그 호출의 오류다.
- 다리의 JSON은 저장 형식의 값 규칙(`{"fixed": raw}`, `{"entity": id}`, `{"text": 키, "args": …}` 등, `World.Save`)에 엔티티의 `def`와 숨김 표시를 더한다. 같은 값은 같은 바이트다.
- 연결부(Unity)는 커널 DLL 없이 이 어셈블리만 알면 된다.

**이유:** 셋 중 고른 것: 경계 전용 값(이것), 커널 `Value`를 그대로(지금 가장 싸나 함수 값이 새고 연결부가 커널에 묶임), 같은 프로세스에서도 JSON 문자열(다리와 같으나 호출마다 직렬화·파싱이고 타입 검사가 없음). 엔티티에 Def id를 싣는 것은 그릴 때마다 경계 너머로 Def를 다시 묻는 왕복을 없애기 위해서이고, 엔티티가 보이는 사람에게는 Def도 보이므로(G197) 새는 정보가 없다. 고정소수점을 원래 정수값으로 보내 결정론 값이 경계에서 흐려지지 않는다.
