**위치:** G347에서 이어서: Unity 패키지가 게임에 내놓는 API

**무엇이 비어 있었나:** 구현에는 `KesaGame.Load(폴더, 시드, 언어)` 하나가 모드를 불러 판까지 열었고, 모드에 오류가 하나라도 있으면 예외를 던졌다. 커널은 오류가 난 모드를 의존 모드와 함께 빼고 남은 모드로 다시 만드는데(G10·G11·G28·G49) 호스트가 그 결과를 쓰지 않았다. 새 게임이나 불러오기 때마다 모드를 다시 읽어야 했다. 콘솔 호스트도 오류가 있으면 시작하지 않는다.

**사례(일반 지식):** RimWorld는 모드 오류를 로그 창에 남기고 계속하며, 모드와 데이터는 시작할 때 한 번 읽고 판(`Game`)을 그 위에서 여러 번 만든다. CK3·Stellaris는 `error.log`에 남기고 시작한다.

**어떻게 정했나 (사용자가 고름):**

- `LoadedMods.Load(modsRoot, languages, hostLocaleFolder)`는 던지지 않는다. `Diagnostics`(모드와 번역의 진단, 정렬됨), `Disabled`(빠진 모드 id), `HasErrors`, `Translator`·`Format`, `Assets`, `ModFolders`를 준다. 보일지, 오류면 멈출지는 게임이 정한다.
- `mods.NewMatch(seed)`가 판 하나(`Match`: `Mods`, `Host`)를 연다. 모드를 다시 읽지 않는다. 저장 파일 불러오기도 나중에 이 자리에 둔다.
- API 타입 이름에 `Kesa` 접두사를 붙이지 않는다. 네임스페이스(`Kesa.Engine.Unity`)는 그대로다. 그래서 창 없는 확인 도구도 `SmokeTest`다. 데모처럼 게임 쪽 코드의 이름은 게임이 정한다.
- 판을 "Session"이라 부르지 않는다: 경계에서 세션은 연결 하나(`IHostSession`)이고 판 하나에 여럿 붙는다.
- 콘솔 호스트는 개발 도구라 오류가 있으면 시작하지 않는 지금대로 둔다.

**이유:** 커널의 "망가진 모드만 뺀다" 설계를 호스트가 살리고, 모드가 많을 때 오타 하나로 게임 전체가 막히지 않게 한다. 진단을 문자열이 아닌 구조(모드·파일·줄)로 넘겨 게임이 자기 화면에 보일 수 있다. 모드 읽기와 판 열기를 나누면 새 게임마다 모드를 다시 읽지 않는다.
