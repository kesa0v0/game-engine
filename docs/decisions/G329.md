**위치:** G325에서 이어서: 콘솔 호스트를 경계로 옮기며 남은 읽기

**무엇이 비어 있었나:** 콘솔 호스트는 모드에 화면 파일이 없으면 엔티티를 종류별로 늘어놓고 컴포넌트·멤버 값을 읽어 보였다(`World.All`·`Has`·`Get`). 경계에는 화면 함수를 부르는 길뿐이라 이 읽기가 없다.

**어떻게 정했나:** **세션에 거른 읽기 둘을 더한다.**

- `Entities()`: 이 연결에게 보이는 엔티티를 (스키마의 종류 순, id 순)으로. 엔티티마다 도장(`Version`)과 `Volatile`(남의 엔티티를 읽는 `derived` 칸이 있어 도장이 다 덮지 못함, G251)을 싣는다.
- `Read(엔티티)`: 보이는 컴포넌트마다 멤버 이름과 경계 값. 못 보면 null.
- 둘 다 `WorldView`의 `All`·`Has`·`Get`을 감싼다(G197의 보기 규칙을 그대로 지킴). 값은 G326의 경계 값이다.

**이유:** 셋 중 고른 것: 거른 읽기를 경계에(이것), 판 주인 전용 디버그(숨긴 정보까지 보이나 경계 밖이고 원격에 못 씀), 기능 빼기(모드를 만들 때 디버깅 수단이 줄어듦). 도장을 목록에 싣는 것은 호스트가 바뀐 엔티티만 다시 읽게 하려는 것이다(G235).

**상태:** 확인
