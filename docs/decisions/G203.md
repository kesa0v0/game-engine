**위치:** G197 보기 정책이 없거나 둘이거나 실패할 때

**무엇이 비어 있었나:** 입구 정책은 G124가 정했지만 보기 정책은 비어 있었고, 정책 함수가 실행 중 오류를 내거나 `bool`이 아닌 값을 돌려줄 때는 어느 쪽에도 없었다.

**어떻게 정했나:** **G124를 따른다:** 정책이 없으면 모두 보이고, 호스트는 시작할 때 `requireViewPolicy`를 켤 수 있다(켰는데 없으면 시작 거부). **`requireViewPolicy`를 켜면 입구 정책(`may_act`)도 필수다:** G200의 "답할 수 있는 질문"은 `may_act`로 정하는데 입구 정책이 없으면 `may_act`가 누구에게나 참이라(G124) 질문이 모두에게 보이기 때문이다(검토에서 찾음, 사용자 확인). 활성 모드 전체에서 최대 하나, 둘이면 로드 오류, 교체는 `override=True`. **정책이 실행 중 오류를 내거나 `bool`이 아닌 값을 돌려주면 "안 보임"으로 처리하고**(닫는 쪽), 오류는 서버 쪽 진단으로 남긴다.

**이유:** 싱글·숨김 없는 게임은 아무것도 적지 않아도 된다. 고장 난 정책을 여는 쪽으로 처리하면 비밀이 조용히 새고(S9), 닫는 쪽은 화면이 비어 금방 드러난다(보안의 fail closed, 일반 지식).

**상태:** 일부 바뀜(G237)

**바뀜:** "`requireViewPolicy`를 켜면 입구 정책도 필수"는 입구 정책이 없어져 빠진다. 보기 정책 규칙은 그대로 → G237.

**바뀜:** "최대 하나, 교체는 `override=True`"는 대상마다 규칙을 거는 보기 규칙과 로드 순서 겹침으로 바뀐다. 없으면 모두 보임·실패하면 안 보임은 그대로, `requireViewPolicy`는 `requireViewRules` → G315.
