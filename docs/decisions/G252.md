**위치:** 모더용 문서의 형식

**무엇이 비어 있었나:** spec과 spec-gaps는 결정 기록이라 모더가 읽을 글이 아니다. 모드를 처음 쓰는 사람이 무엇을 어떤 순서로 쓰는지 설명한 문서가 없었다.

**어떻게 정했나:** 저장소 안의 마크다운 안내서 `docs/modding/`. 장은 시작하기, 데이터(스키마·Def·패치), 로직, 커맨드, 흐름(질문·시간), 반응, 자리와 숨긴 정보, 화면에 보일 값, 아직 없는 것이고 예시 게임 `samples/skirmish`를 따라간다. 빠짐없는 목록(레퍼런스)은 손으로 쓰지 않고 엔진이 만드는 `.pyi` 스텁(G207~G209)을 가리킨다. 안내서의 예시 코드는 테스트가 로드하는 모드(`samples/`)에서 가져와, 예시가 깨지면 테스트가 실패한다. 엔진이 만드는 레퍼런스 페이지(`kesa docs` 같은 것)와 문서 사이트는 미룬다. 마크다운으로 써 두면 사이트로 그대로 옮길 수 있다.

**이유:** 코드와 같은 커밋으로 고칠 수 있고 GitHub·VS Code에서 바로 읽힌다. 손으로 쓴 레퍼런스는 코드와 금방 어긋난다. Factorio는 엔진이 내보낸 JSON으로 Lua API 레퍼런스를 만들고 안내서는 위키에 두며, 패러독스는 `script_docs` 명령으로 트리거·효과 목록을 뽑아 주고, RimWorld는 공식 레퍼런스 없이 커뮤니티 위키가 메운다(일반 지식). 번역(X4)·UI 행동처럼 비어 있는 곳이 있어 지금 생성 레퍼런스를 만들면 금방 바뀐다.
