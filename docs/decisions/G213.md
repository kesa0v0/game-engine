**위치:** S1 ① 파일 이름의 유니코드 정규화 (G7 보강)

**무엇이 비어 있었나:** G7은 `use` 경로를 디스크 이름과 서수로 비교한다. macOS에서 온 자모 분리형(NFD) 파일 이름을 완성형(NFC)으로 적은 `use("defs/유닛.py")`는 화면에서 같아 보여도 `MOD002 file not found`였다(재현함, "혹시 …?"도 없음). 해시(G212)에 적을 경로도 정규화가 정해져야 한다.

**어떻게 정했나:** **경로는 NFC로 다루고 디스크의 실제 이름은 열 때만 쓴다.** `use`·`use_all`의 단계마다 NFC로 같은 이름을 찾고(그다음 대소문자만 다른 이름, G7), 찾은 실제 이름으로 연다. 그래서 바이트가 같아야 열리는 Linux에서도 결과가 같다. `use_all`로 찾은 경로, 오류 위치의 파일 이름, 해시·저장의 경로, 대소문자 힌트는 NFC다. 한 폴더에 NFC로 같은 이름이 둘이면 `use`는 `MOD002`, `use_all`은 `LOD001` 오류다(어느 것인지 모호). 모드 폴더 이름은 그대로 둔다.

**이유:** 대소문자처럼 오류로 알리고 이름을 고치게 하는 안(B)은 정규화 차이가 눈에 보이지 않고 macOS가 다시 NFD로 저장할 수 있어 모더가 할 수 있는 것이 거의 없다. 일반 지식: macOS에서 온 한글 파일 이름이 윈도우에서 "자소 분리"되는 것은 잘 알려진 문제다.

**상태:** 확인
