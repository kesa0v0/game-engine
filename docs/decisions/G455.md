**위치:** G454에서 이어서: 블록 안에서 판에 직접 쓰기

**무엇이 비어 있었나:** 블록 안에서 `play`(커맨드)로만 판을 바꿀지, 판에 직접 가정을 쓸 수 있게 할지.

**어떻게 정했나 (사용자가 고름):** **연다.**

```python
with imagine():
    u.Pos.x, u.Pos.y = 3, 2     # 여기 서 있다고 치자
    play("Attack", unit=e, target=u)
```

- 쓰기 문법과 검사는 커맨드 본문과 같다(G132·G134). 타입이 틀린 값, 없는 엔티티, 뗄 수 없는 컴포넌트는 커맨드에서와 같은 오류다.
- 판에 쓰는 함수를 부를 수 있는 곳에 imagine 블록 안을 더한다.
- 있을 수 없는 판(체력이 최대보다 큼, 한 칸에 둘)을 엔진이 막지 않는다. 차례 건너뛰기처럼 일부러 규칙 밖의 판을 만드는 것이 쓰임이라 엔진은 "있을 수 없음"을 판정할 수 없다. 그런 판에서 커맨드가 거절되거나 오류를 내면 `play`가 그대로 돌려준다.
- 진짜 판에 닿는 것은 블록 밖의 `submit`뿐이고 진짜 판의 입구·전제 조건을 다시 거친다. 잘못된 가정의 끝은 나쁜(그러나 규칙에 맞는) 수이거나 거절된 수(G377)다.

**버린 것:** 막기(차례 건너뛰기·잠깐 놓아 보기를 못 함), 모드가 만든 추측 함수 안에서만 쓰기(탐색 중간의 가정마다 함수가 따로 필요).

**이유:** 시험 판은 버려지는 복사본이라 진짜 판의 위험이 없다. 사례: 체스 엔진의 null move(규칙에 없는 패스로 탐색을 줄임), Wesnoth AI의 `temporary_unit_placer`·`temporary_unit_mover`(이동 규칙 없이 유닛을 잠깐 놓음), 카드 게임 AI의 결정화(못 본 손패를 추측으로 채움)(모두 일반 지식). 규칙이 "블록 안은 커맨드 본문처럼 쓸 수 있고 끝나면 버린다" 하나다.

**구현하며 좁힌 것:** 블록 안에서 봇 본문이 직접 부르는 `ask`·`wait`·`emit`은 `RUN025`다. 봇 본문은 멈추거나 신호의 반응을 돌릴 자리가 없으므로, 질문·기다림·신호는 그것을 하는 커맨드를 `play`한다(`advance`는 G460대로 된다). "식 안에서 쓰는 함수를 부를 수 없음"(G117)은 블록 안에서도 같다.
