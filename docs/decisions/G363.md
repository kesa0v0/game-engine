**위치:** G359에서 이어서: USS 안에서 그림 같은 파일을 가리키는 법

**무엇이 비어 있었나:** USS는 `url("…")`(파일 경로)과 `resource("…")`(Unity `Resources` 안의 에셋 이름)로 파일을 가리킨다. 이전 게임 USS는 둘 다 쓰지 않고 그림을 UXML의 바인딩으로 넣었다. G360이 Unity USS 그대로를 약속하므로 모드 USS에서 이 둘이 무엇을 뜻하는지 정해야 했다.

**어떻게 정했나:** **`url()`은 공유 가상 경로, `resource()`는 받지 않음.**

- `url("skirmish/art/card-frame.png")`의 경로는 G335·G362와 같은 공간이다: 모드 폴더를 겹친 가상 경로, 나중 모드가 이긴다. 시트 파일이 있는 폴더 기준의 상대 경로가 아니다.
- 찾지 못하면 화면을 올릴 때 진단(G361)이 나온다.
- `resource("…")`는 진단을 내고 그 값을 쓰지 않는다. 진단은 모드 USS에서는 `url()`을 쓰라고 알린다.
- 정하지 않았다: 그림이 아닌 파일(폰트 등)을 `url()`로 읽는 방식.

**이유:** 고른 것: 공유 가상 경로(이것), 시트 기준 상대 경로(웹 CSS 관례이나 이미지·UXML 경로와 규칙이 달라지고 시트가 교체되면 기준 폴더도 바뀜), 둘 다 아직 받지 않음(G360의 약속에 구멍). 그림 경로가 `bind-image`·`<Style src>`·`Include`와 같은 규칙 하나로 끝나고, `resource()`는 G362와 같은 이유로 게임 빌드 안의 이름에 기대게 한다.

**상태:** 확인
