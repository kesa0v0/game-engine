**위치:** 화면 파일의 오류도 Unity를 열어 올려 봐야 보였다. G480은 그림·공간·보는 법만 넓혔다.

**어떻게 정했나 (사용자가 고름):** `.uxml`도 `check`에 넣는다. 게임에서 화면을 올릴 때 하는 검사를 그대로 쓴다.

**이유:** 가장 흔한 실수인 함수 이름 오타는 읽기만으로 잡히지 않는다. 검사를 따로 짜면 게임과 규칙이 갈라지므로 `UiInterpreter`에서 세션 없이 쓸 수 있는 `UiChecker`로 뺐다.

**구현하며 정한 것 (사용자 확인함, 2026-11-15):**

- 코드는 `UIX001` 하나이고 모두 오류다. USS 문제는 게임에서 화면을 막지 않지만(G364) 번역 오류처럼 `check`에서는 오류다(`docs/modding/01-start.md`의 `LOC`).
- 끼워지는 파일은 끼우는 쪽에서 본다. 혼자 보면 창 안에서만 되는 `window-drag`가 잘못 걸린다. 서로만 끼우는 파일은 그래도 본다.
- 같은 경로가 여러 모드에 있으면 게임처럼 나중 모드의 파일만 읽는다.
- 호스트가 넘기는 맨 위 `params` 값은 알 수 없어 보지 않는다.
- 켜지지 못한 모드가 있으면 없는 이름이 잘못 걸리므로 함수·커맨드 이름을 보지 않는다. 그 모드를 고치면 다시 나온다.
- 이름 찾기에는 `World`를 만들되 돌리지 않는다. 선언 파일의 호스트 함수는 월드를 못 돌리므로(G221) 호스트 함수 표를 받지 않는 생성자를 쓴다.

**보지 않는 것:** 요소 이름(`Buton`)과 일반 속성 이름. 어떤 요소가 있는지는 렌더러가 안다. USS `url()`의 파일과 `bind-image` 값. 바인딩이 돌려주는 값의 타입.

**확인:** Commander와 `samples/skirmish`, `samples/guide`에서 새 진단이 없다.
