**위치:** G221에서 미룬 것: 콘텐츠 파일 최상위에서 호스트 함수를 값으로 쓰기

**무엇이 비어 있었나:** 호스트 함수는 함수 본문 안에서만 이름으로 풀렸다. Def 파일의 맨 위(`Goal("B", check=core.goals.reached)`)나 패치 값(`patch.set("core:B", "check", core.goals.reached)`)에 적으면 "이름 없음" 오류였다. 스크립트 함수는 `check=done`처럼 칸에 들어가므로, 호스트 함수만 한 줄짜리 스크립트 함수로 감싸야 했다.

**어떻게 정했나:**
- **읽기 등급 호스트 함수는 `Cond[...]` 칸의 값이 될 수 있다.** 이미 G216이 정한 "읽기 등급은 `Cond`에서도 부를 수 있다"를 파일 최상위의 값에도 적용한 것이다.
- **로드가 칸에 맞는지 본다** (값 검사, Def 값은 `VAL002`, 패치는 `PAT009`):
  - 쓰기 등급이면 거절한다. `Cond` 칸은 읽기만 받는다(G117과 같다).
  - 칸이 부르는 꼴로 부를 수 있어야 한다. 첫 매개변수가 그 칸의 Def 타입의 `Ref[X]`이고 나머지는 기본값이 있어야 한다.
  - 반환이 `bool`이어야 한다.
- **`Action[...]` 칸은 지금처럼 스크립트 함수만 받는다.** 호스트 함수는 한 번 부르고 끝나서 `ask`·`wait`로 멈출 수 없는데, 그 차이를 칸이 어떻게 다룰지는 쓰려는 사례가 생기면 정한다.
- 로드 때는 월드가 없으므로 값은 이름과 서명만 든 참조(`HostReference`)다. 게임이 그 칸을 읽을 때 그 월드의 호스트 함수 값으로 바뀐다. 참조를 로드 중에 부르면 오류다. 덤프는 `{"host": "core.goals.reached"}`로 적는다.
- 보이는 범위는 함수 본문과 같다(G218): 소유 모드가 자신이거나 필수 의존인 호스트 함수만 쓸 수 있다.
- 호스트 함수의 서명은 Def 파일을 실행하기 전에 푼다(전에는 실행 뒤).

**이유:** 호스트 함수의 읽기 등급은 엔진이 쓰기 창구를 건네지 않아 지킨다(G217). 그래서 믿고 말고 할 문제가 아니고, 감싸는 스크립트 줄을 모더가 쓰지 않게 하면 된다. 서명은 로드 때 보는 편이 칸을 평가하는 순간 인자 어긋남으로 터지는 것보다 모더에게 친절하다(스크립트 함수의 매개변수 타입 추론은 G228). 일반 지식: 패러독스는 효과·조건 목록을 엔진이 내보내 모더가 이름으로 부른다.

**상태:** 확인

**바뀜:** `Action` 칸은 G292에서 호스트 함수를 받게 되었다. 위 "`Action[...]` 칸은 지금처럼 스크립트 함수만 받는다"는 더 이상 맞지 않다.
