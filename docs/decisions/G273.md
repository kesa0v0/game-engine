**위치:** 엔진 예약 이름 `engine` (G272의 `kesa.pick`, G269의 `kesa-hidden`·`kesa-console-…`에서 드러남)

**무엇이 비어 있었나:** G272는 엔진 커맨드를, G267·G269는 엔진·호스트의 번역 키를 `kesa`(어셈블리 이름 `Kesa.Engine`에서 따옴, 따로 정한 적 없음) 아래에 두었다. 그런데 모드 id 규칙(소문자·숫자·`_`, 글자로 시작, `MOD005`)은 어떤 이름도 엔진용으로 막지 않는다(`ManifestReader.cs`에 예약 검사 없음, 2026-10-20 확인). 모드 `kesa`가 `pick` 커맨드를 만들면 엔진 커맨드와 겹친다.

**어떻게 정했나:** **모드 id `engine`은 엔진 예약이라 쓰면 `MOD005`("엔진이 쓰는 이름")다.** 엔진 커맨드는 `engine.pick`, 엔진이 주는 번역 키는 `engine-hidden`, 호스트의 번역 키는 `engine-console-moves`처럼 `engine-` 아래에 호스트 이름을 붙인다. G267·G269·G272에 적힌 `kesa` 이름은 모두 이렇게 바꾼다.

**이유:** 모드 id가 커맨드 id의 앞부분이라(`모드.함수`) 예약 하나로 커맨드와 키가 함께 지켜진다. 후보는 제품 이름 `kesa`(Minecraft의 `minecraft:`처럼 겹칠 일이 가장 적지만 이름이 바뀌면 같이 바꿔야 함), `engine`(뜻이 바로 보이지만 증기기관·함선 엔진 모드가 쓰고 싶어 할 흔한 낱말을 막음), 모드 id가 될 수 없는 꼴(`_engine`, 예약 규칙은 필요 없지만 Fluent 키는 글자로 시작해야 해 키와 커맨드의 이름이 달라짐)이었다. 사용자가 `engine`을 골랐다. RimWorld는 `Core` 모드를 엔진 쪽 내용으로 둔다(일반 지식).

**상태:** 확인
