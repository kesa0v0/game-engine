**위치:** G306에서 이어서: 스키마 이름 자리의 문자열 표기를 계속 받을지

**무엇이 비어 있었나:** G306으로 `query(City)`·`defs(City)`가 되면 옛 표기 `query("City")`를 어떻게 할지 정해야 했다. 후보는 (A) 받지 않음, (B) 둘 다 받음, (C) 리터럴만 막고 실행 중에 만든 문자열은 받음이었다. 예시 모드·시험·안내서에 문자열 표기가 110여 곳 있었다.

**어떻게 정했나:** **(A).** 스크립트의 `query`·`defs`에 문자열 리터럴을 주면 로드 오류이고 안내는 맨 이름 표기다(`query(City)`로 쓰라). 실행 중에 문자열이 오면 실행 오류다. 호스트 C# API(`World.Query("City")` 등)는 스크립트 밖이라 문자열 그대로다. 기존 표기는 일괄 수정한다(대부분 따옴표만 지우는 기계적 수정, 오류 메시지를 시험하는 곳은 손으로).

**이유:** G306의 목적이 표기를 하나로 맞추는 것이다. 둘 다 받으면 "어디는 이름, 어디는 문자열"이 그대로 남는다. 실행 중에 타입을 데이터로 고르는 사례는 예시 모드에 없어 생기면 따로 연다. 파이썬도 클래스를 받는 API에 이름 문자열을 함께 받는 경우는 드물다(일반 지식).

**상태:** 확인
