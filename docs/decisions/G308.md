**위치:** G306에서 이어서: 엔진이 스크립트에 넘기는 컴포넌트 (보기 정책 `may_see`의 `component`, 기여 줄의 `c.component`)

**무엇이 비어 있었나:** 보기 정책 `may_see(viewer, entity, component)`(G197·G238)의 `component`와 선언에서 모인 기여 줄의 `c.component`(G298)는 컴포넌트 이름 문자열이라 모드가 `component == "Face"`로 썼다. G306 원칙(이미 있는 스키마 이름은 맨 이름)과 어긋나고, `"Fcae"` 같은 오타는 조용히 거짓이 된다. 후보는 (A) 문자열 그대로, (B) 엔진이 컴포넌트 값을 넘김, (C) 둘을 같게 비교였다.

**어떻게 정했나:** **(B).** 두 자리 모두 로직에서 맨 이름 `Face`가 뜻하는 것과 같은 컴포넌트 값을 넘긴다. 모드는 `component == Face`로 쓰고, 이름 오타는 로드 때 이름 검사(`EVL001`, "혹시 …?")가 잡는다. 옛 표기 `component == "Face"`는 늘 거짓이 되어 조용히 깨지므로, 값의 타입을 아는 자리(이 두 곳)에서 컴포넌트를 문자열 리터럴과 비교하면 로드 때 경고한다(G261의 맨 문자열 Def id 비교 경고와 같은 방식). `component`가 `None`(엔티티 층)인 것은 그대로다.

**이유:** G306의 원칙과 맞고, 오타가 로드 때 잡혀 지금보다 낫다. (C)는 섞인 표기를 남긴다.

**상태:** 확인
