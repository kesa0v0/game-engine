**위치:** G330에서 이어서: UXML 파일이 바깥에서 값을 받는 법

**무엇이 비어 있었나:** 최상위 패널의 "나"와 다른 파일을 가져온 UXML의 인자는 같은 문제였다. 이전 엔진은 `<ui:Include vpath=".." ui-context="경로" ui-context-key="Self"/>`로 값 하나를 `Self`(예약 이름)로 넘겼고, 안 넘기면 가져온 파일이 부모의 컨텍스트 전체를 눈에 안 보이게 물려받았다. 창을 열 때는 `OpenWindow`의 `ContextPayload`가 `Self`가 됐다. 지금 엔진에서 스크립트는 연결 꼬리표를 모르므로(G241) 앉은 엔티티는 호스트가 줘야 하고, 콘솔 호스트는 패널 함수에 인자로 넘기며 `@ui_action`에서는 이름이 `me`인 매개변수에 넣는다(G250·G286).

**어떻게 정했나:** **파일에서 받는 이름을 선언하고, 이름 붙은 인자로 넘긴다.**

- 파일의 맨 위 요소에 `params="이름, 이름"`으로 받는 이름을 선언한다. 선언한 이름은 그 파일 안에서 변수로 쓴다(G330).
- 가져오는 쪽은 `<Include src="파일" 이름="식" … />`로 넘긴다. 식은 G332의 문법(변수나 고정값)이다.
- 최상위 패널은 `seat="이름"`으로 호스트가 앉은 엔티티를 넣을 매개변수를 가리킨다. 이름은 모더가 짓고 예약 이름(`me`·`Self`)은 없다.
- 선언이 있으므로 로드할 때 빠진 인자, 모르는 인자 이름, 선언하지 않은 변수의 사용을 오류로 잡는다(G249의 `CheckCall`과 같은 정신).
- 정하지 않았다: 한 연결이 여러 곳에 앉았을 때 패널을 앉은 곳마다 만들지(콘솔은 그렇게 함), `Include`의 `src` 경로를 찾는 법(G335의 가상 경로와 같은지), 매개변수의 기본값과 타입 검사.

**이유:** 셋 중 고른 것: 이름 붙은 선언과 인자(이것), 값 하나에 예약 이름(이전 엔진: 짧지만 값이 하나뿐이고 예약어가 생겨 모더가 짓는다는 G330과 어긋남), 부모의 이름을 물려받음(이전 엔진의 기본: 선언이 없어 파일만 봐서는 어떤 변수가 필요한지 모르고 로드 때 검사도 못 함).

**상태:** 확인
