**위치:** G359에서 이어서: USS 진단의 무게

**무엇이 비어 있었나:** UXML은 문제가 하나라도 있으면 화면을 올리지 않고 문제 목록을 돌려준다. USS를 해석기가 같은 길로 읽게 되면서 USS 문제도 화면을 막는지 정해야 했다.

**어떻게 정했나:** **경고로 둔다.**

- USS 파일을 못 찾거나, 문법이 깨졌거나, 모르는 속성이 있거나(G361), 호스트가 값을 바꾸지 못해도 화면은 올린다.
- 잘못된 규칙이나 선언만 빼고 나머지는 붙인다. 파일을 못 찾으면 그 시트만 빠진다.
- 문제는 바인딩 오류처럼 `UiInterpreter.Errors`에 한 번씩 담기고, 보이는 것은 호스트 몫이다.
- UXML의 문제가 화면을 막는 것은 그대로다.

**이유:** 고른 것: 경고(이것), UXML처럼 막기(놓칠 일은 없으나 오타 하나로 화면이 사라지고 다른 모드의 시트를 덮은 스킨 모드가 남의 화면을 막을 수 있음), 못 찾음·문법 오류만 막기(막는 경계가 모더에게 덜 분명함). 모양은 게임 진행에 필요하지 않고, Unity와 CSS도 모르는 것은 건너뛴다. UXML의 이름은 틀리면 동작이 틀리지만 USS는 모양뿐이다.

**상태:** 확인
