**위치:** S1 ⑥ 최종 값의 타입 검사와 `min`/`max` (G25·G39·G48 모음)

**무엇이 비어 있었나:** ⑥이 최종 값을 스키마 타입과 대조하는 규칙과 `min`/`max`가 적용되는 범위가 없었다.

**어떻게 정했나:** 타입: `int`는 정수만(`fixed` → `int` 오류), `fixed`는 정수·소수, `bool`·`str`은 그 종류만, `TextKey`와 `DefId[X]`는 문자열(번역표 존재는 텍스트 시스템의 일, Def 존재는 ⑤), `list`·`dict`는 원소·키·값을 재귀로, 함수 자리는 함수 값(효과가 자리와 맞는지는 함수 분석기가 생긴 뒤). 어긋나면 `VAL002`(“expected int, found str”). 범위: `min`/`max`는 숫자 값에, 리스트·맵이면 **원소와 맵 값 각각**에 적용한다(양끝 포함, 맵 키에는 적용하지 않음). 벗어나면 `VAL003`. `int`와 `fixed`는 수로 비교한다. 오류 위치와 책임 모드는 G64와 같은 출처 규칙이다.

**이유:** 위의 타입 규칙은 기존 결정을 모은 것이다. 범위를 컬렉션 원소에 적용해야 “모든 비용은 0 이상”을 한 번에 쓸 수 있고, 스칼라에만 두면 쓸 방법이 없다.

**상태:** 확인
