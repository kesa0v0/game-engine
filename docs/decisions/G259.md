**위치:** S1 Def id의 이름 공간 ② 조각의 글자 (G258에서 이어짐)

**무엇이 비어 있었나:** G14는 Def id에 글자 제한을 두지 않았다(한글·공백·`-`도 됨). 이름 공간의 조각에 무엇을 허용할지 없었다.

**어떻게 정했나:** **점으로 나눈 조각마다 ASCII 식별자 `[A-Za-z_][A-Za-z0-9_]*`이고 대소문자를 구분한다.** 첫 조각인 모드 id(`[a-z][a-z0-9_]*`, G2)도 이 안에 든다. 한글 Def id는 더 이상 안 된다(사용자: 상관없음, 화면 이름은 번역 파일이 맡음). 대소문자만 다른 id는 따로 경고하지 않고, 참조에서 못 찾았을 때의 "혹시 …?"가 그런 후보를 보인다.

**이유:** 조각에 `-`가 없으므로 Def 이름의 번역 키(조각을 `-`로 이음, 따로 정함)가 겹침 없이 하나로 정해지고 되돌릴 수 있으며, Fluent 이름도 ASCII만 받는다. 스크립트 식별자 규칙(G14)과 같아 나중에 따옴표 없는 표기(G63의 후속 과제)를 열 때 조각이 그대로 이름이 된다. 사례(일반 지식): Minecraft id는 소문자 ASCII와 몇 기호만, RimWorld defName도 영문·숫자·`_`·`-`만 받고 사람이 읽는 이름은 번역에 둔다.

**상태:** 확인
