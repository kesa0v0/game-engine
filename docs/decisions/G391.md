**위치:** G390에서 이어서: 3D 모델 파일을 무엇으로, 어떻게 읽나

**무엇이 비어 있었나:** Unity는 실행 중에 모드 폴더의 모델 파일을 읽지 못한다. 이전 엔진은 `GetMeshAsync`에 "AssetBundle 또는 glTF 임포터, 구현 필요"만 남기고 기본 도형만 썼다. 2D(png·jpg)는 내장 `ImageConversion`으로 이미 읽는다.

**어떻게 정했나 (사용자가 고름):**

- 모더는 `<Model src="units/infantry.glb" />`처럼 경로만 적는다. 확장자로 로더를 고르고, 맡을 로더가 없으면 로드 때 등록된 확장자와 함께 진단한다.
- 호스트에 모델 로더 등록 자리를 둔다(C#, 요소 종류 등록 G390과 같은 모양). 게임은 제 로더를 더한다.
- 로더는 모두 같은 모양을 돌려준다: 꺼내 쓸 원본(Unity에서는 복제할 GameObject), 이름 붙은 노드(`bone`이 찾음), 이름 붙은 애니메이션 클립(`clip`이 찾음), 값을 넣을 재질 칸(`tint` 등). 로더가 못 주는 것을 정의가 쓰면 그곳에서 진단한다.
- 첫 로더: glTF를 Unity glTFast(`com.unity.cloud.gltfast`, Apache-2.0)로 읽는다. 확인한 것(6.15 문서): 최신 6.15.1(2025-12-09), 최소 Unity 2020.3.48f1, 실행 중 skin·모프 지원, 실행 중 애니메이션은 옛 `Animation` 체계로 재생(Mecanim은 클립만 가져오고 재생하려면 더 할 일이 있음, Playable API는 없음). 버전은 구현할 때 패키지 관리자에서 다시 보고 고정한다.
- 파일 하나 안의 여러 에셋(`bundle.ab#infantry`)과 스프라이트 시트의 일부를 가리키는 표기는 G335에서 미룬 것과 함께 정한다.

고른 것: glTF 하나만(형식 하나), AssetBundle(Unity 기능 전부, Unity 버전에 묶임), 여러 형식 범용 라이브러리(유료·네이티브). 사용자가 "길을 여럿 열어 두고 glTF 하나로 먼저"를 냈다.

**이유:** glTF는 Blender가 바로 내보내는 열린 표준이고 뼈대·클립 이름을 표준으로 담아 G390의 조립 요소가 기댈 곳이 된다. 로더를 등록 자리로 두면 형식을 늘리는 일이 정의 문법을 바꾸지 않는다. 사례: 0 A.D.는 COLLADA를 받아 캐시, 패러독스는 자체 형식과 내보내기 도구, KSP는 자체 형식 뒤에 AssetBundle을 더함, Valheim 모드는 AssetBundle(일반 지식).
