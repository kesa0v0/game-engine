**위치:** G369에서 이어서: 봇이 턴을 넘어 들고 있는 것

**무엇이 비어 있었나:** 봇은 부를 때마다 처음부터 생각한다. 전략 AI는 목표, 유닛마다의 임무, 계획 단계를 턴을 넘어 들어야 하고, 진영 봇 안의 서브 AI(G368)는 유닛마다 기억이 필요하다. 화면 쪽 `ui_state`는 이미 리스트·맵 칸을 갖지만(G277) 화면 하나의 기록이라 봇 기억으로 쓸 수 없다.

**어떻게 정했나:** **`ui_state`와 같은 칸 규칙의 따로 된 선언.**

- 표기: `bot_state("BlueMind", target=ref("Sector", optional=True), orders=field(dict[Ref[Unit], str], default={}), plan=field(str, default="gather"))`. 칸은 모두 기본값이 있어야 하고 Ref는 선택적이다(G279와 같음).
- `@bot` 본문에서 `bot.BlueMind.plan = "attack"`, `bot.BlueMind.orders = {u: "cover"}`처럼 읽고 쓴다(맵도 그 자리에서 고치지 않고 새 값을 쓴다, G104). 칸 이름과 타입은 로드 때 검사한다.
- 칸 타입은 `ui_state`와 같다: 리스트와 맵(엔티티를 키로 쓰는 맵 포함, G277). 판 상태에서 열지 않은 것(G129)은 열(칼럼) 저장 때문이고 봇 기억은 게임 상태가 아니다.
- 가리키던 엔티티가 없어지면 `None`으로 읽고, 맵의 키였던 엔티티는 그 줄이 빠진다.
- 봇마다 기록 하나를 엔진이 만들어 주고 호스트가 든다(`UiState`처럼). 저장 파일에 남길지는 이어서 정한다.

**이유:** 고른 것: `ui_state`와 같은 칸 규칙의 따로 된 선언(이것), 선언 없는 자유 맵(Wesnoth `self.data`처럼 쓰기 쉽지만 오타를 실행해야 앎, wiki.wesnoth.org/Creating_Custom_AIs). 결정할 때 `ui_state`가 낱값뿐이라고 잘못 설명했으나 실제로는 이미 리스트·맵이 있어(G277) 결정은 그대로이고 문장만 고쳤다. Unreal 블랙보드도 키 이름과 타입을 미리 선언한다(일반 지식). 엔진의 다른 곳처럼 선언하고 로드 때 잡는다. 쓰는 쪽 `bot.기록.칸`은 화면의 `ui.기록.칸`과 짝이다.

**상태:** 확인
