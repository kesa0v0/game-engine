**위치:** G394가 미룬 것: 모드가 공간을 선언하고 종류·설정을 고르는 자리

**무엇이 비어 있었나:** `at("square", [2, 3])`을 그리려면 호스트가 공간 `square`가 있고 네모 칸이며 한 칸이 화면에서 얼마인지 알아야 한다. 모드가 이것을 어디에 적는지 없었다.

**어떻게 정했나 (사용자가 고름):**

- 공간은 호스트가 읽는 XML에 `<Space name kind …설정>`으로 선언한다. 설정 속성은 종류가 정한다(네모 칸 `grid`는 G414).
- `kind`는 Unity 패키지의 기본 종류(네모 칸·육각 칸·고정소수점 연속 좌표·구역+순번)나 게임이 C#으로 등록한 종류다.
- 커널은 공간을 모른다. `at()`의 공간 이름 오타는 로드 때 잡지 못하고, 호스트가 처음 보는 이름을 "혹시 …?"와 함께 경고한다.
- 같은 이름의 공간은 그림 정의처럼 로드 순서가 뒤인 모드가 통째로 이긴다(G390).

고른 것: 호스트 XML(이것), 로직 파일의 `space(...)`(이름 오타를 로드 때 잡으나 커널이 뜻 모를 설정을 듦), C#으로만(모더가 C# 없이 공간을 못 더함).

**이유:** 공간의 종류와 설정은 화면의 뜻이라 커널 밖이다(G240·G387). 패러독스도 지도 정의를 스크립트 로직과 다른 데이터 파일에 두고 엔진이 읽는다(일반 지식).

**상태:** 확인
