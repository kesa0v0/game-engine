**위치:** G359에서 이어서: 모드 USS에서 쓸 수 있는 문법의 범위

**무엇이 비어 있었나:** G359는 모드 USS를 Unity가 진짜 `StyleSheet`으로 적용하게 했으나 모더에게 어디까지 약속하는지는 정하지 않았다. 이전 게임은 클래스·자손·자식(`>`)·`:hover`·`:active`·`:focus`·`:checked`·`:root`·`var()`와 속성 95종(`-unity-` 32곳)을 썼고 `@import`·`url()`은 쓰지 않았다.

**어떻게 정했나:** **Unity USS 그대로.**

- 선택자: 타입(`Button`), `.클래스`, `#이름`, `*`, 이어 붙이기(`.a.b`), 쉼표 목록, 자손(띄어쓰기), 자식(`>`), 의사 클래스 `:hover`·`:active`·`:inactive`·`:focus`·`:disabled`·`:enabled`·`:checked`·`:root`.
- 속성: Unity가 아는 USS 속성 전부와 `--` 사용자 변수, `var()`.
- 모더는 Unity 공식 USS 문서를 그대로 본다. 엔진 문서는 다른 점만 적는다.
- 아직 없는 것: `@import`. `url()`·`resource()`가 모드 가상 경로(G335)를 어떻게 가리키는지는 따로 정한다.

**이유:** 고른 것: Unity USS 그대로(이것), 이전 게임이 쓴 만큼만 약속하고 넓혀 가기(넓히기는 호환이 쉬우나 Unity가 할 수 있는 것을 일부러 막는 코드와 진단이 늘고 모더가 Unity 문서 중 되는 범위를 따로 알아야 함). 적용은 Unity가 하므로 넓게 받아도 엔진이 짤 것은 읽기뿐이고, 모드 UI가 이미 UXML(Unity 형식)이다.

**상태:** 확인
