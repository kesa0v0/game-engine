# spec 빈틈 상세: S8 저장

색인과 상태 규칙은 `docs/spec-gaps.md`. 이 파일은 G 번호마다 무엇이 비어 있었고 어떻게, 왜 정했는지의 전문이다.

## G140

**위치:** S8 저장 형식

**무엇이 비어 있었나:** spec은 정규형(같은 상태는 같은 바이트, C4)과 C# 클래스 이름 금지만 정했다. 이전 엔진은 C# 객체 그래프를 통째로 직렬화했다: Quarantined는 MemoryPack(필드 순서가 바이트 배치)을 붙였다가 `de3c609`에서 Newtonsoft JSON으로 옮겼고, ENG `SaveManager`는 `TypeNameHandling.Auto`(타입 이름이 세이브에 들어감) + 선택적 gzip이다(코드 확인). RimWorld는 XML, 패러독스는 텍스트 세이브와 같은 구조의 바이너리(아이언맨)를 쓴다(일반 지식).

**어떻게 정했나:** **정규형 텍스트(JSON)를 엔진이 직접 쓴다.** 형식은 C# 클래스가 아니라 엔진 데이터 모델(엔티티·칼럼 값·키 줄·기여 행·카운터·Flow 프레임·메타)에 대해 엔진이 한 번 정의하고, 스키마 이름(컴포넌트·필드·Def id)은 문자열로 들어간다. 키 순서·공백·수 표기는 고정이고 값 종류는 엔진이 정한 닫힌 태그로 적는다(C# 타입 이름 없음). 압축은 호스트가 바이트 위에 한다. 같은 구조의 바이너리 인코딩은 크기가 문제가 될 때 더한다.

**이유:** 자체 바이너리만(B)은 초기 디버깅에 덤프 도구가 필요하다. 둘 다(C)는 지금 일이 두 배이고 A 위에 나중에 더할 수 있다.

**상태:** 확인

## G144

**위치:** S8·C5 멈춘 Flow의 함수 본문 해시가 덮는 것

**무엇이 비어 있었나:** S8은 Flow가 함수별 본문 해시를 저장하고 다르면 로드를 거부한다고 했지만, 무엇이 바뀌면 해시가 달라지는지(주석·공백·상수·데코레이터)와 어느 함수를 덮는지가 비어 있었다.

**어떻게 정했나:** **위치 정보를 뺀 구조로 해시한다.** 매개변수(기본값·타입 표기)·반환 표기·본문의 문장과 식, 이름, 연산자, 상수가 들어가고 공백·주석·줄 위치·괄호·파일 안의 순서·데코레이터는 들어가지 않는다. 덮는 함수는 멈춘 프레임의 함수와 Flow가 든 람다가 속한 함수다(람다 번호가 그 구조에 기댄다). 그 함수가 부르는 다른 함수는 아직 실행 전이라 새 본문으로 실행한다. 다르면 `SAV004`로 바뀐 함수를 모두 보이고 거부하며 위치를 옮겨 보지 않는다. 해시는 SHA-256 앞 16바이트(고정 골든 테스트, C6). 데코레이터는 로드 때 한 번 읽는 선언이라 Def 값 변경처럼 본다. Flow 취소 후 로드와 `migrate`는 S8의 다음 단계로 미룬다.

**이유:** 소스 글자 그대로(A)는 주석 수정마저 진행 중 저장을 모두 막는다. 뼈대만(C)은 앞은 옛 규칙·뒤는 새 규칙으로 섞여 C5에 어긋난다. Ren'Py는 바뀐 스크립트에서 남은 문장으로 되감아 조용히 섞이는 문제가 알려져 있고 패러독스는 스크립트 도중 저장이 없다(일반 지식).

**상태:** 확인

## G210

**위치:** S8 칼럼 삭제의 고아 데이터 영역

**무엇이 비어 있었나:** S8은 삭제된 칼럼의 값을 고아 영역에 보존하고 경고한다고 했지만, 지금 `World.Load`는 지워진 컴포넌트·멤버·키 Def를 모두 `SAV002`로 거부한다. 고아 영역을 만들면 저장 형식·복구 규칙·되살릴 때의 검사가 새로 생긴다.

**어떻게 정했나:** **기본은 지금처럼 목록과 함께 거부하고, 호스트가 `World.Load(..., dropRemoved: true)`로 허락하면 버리고 불러온다:** 지워진 컴포넌트(런타임으로 붙였던 것 포함), 지워진 멤버, Def 목록에서 빠진 컴포넌트, 없어진 Def를 키로 한 줄, 지워진 derived 멤버나 버린 컴포넌트·줄에 걸린 기여 행의 값을 버리고 곳마다 `SAV005` 경고를 남긴다. 버린 뒤의 저장은 지금 내용과 맞으므로 다시 불러올 때 경고가 없다. 타입이 바뀐 값, 좁아진 범위, 정적 기본값 없는 새 멤버, 키 종류 변경, 다른 타입의 Def가 된 키, Def 자체의 삭제(엔티티가 사라짐), 멈춘 Flow의 어긋남은 그대로 거부한다(타입 변경은 나중의 `migrate`, Def 삭제는 다음 단계). 고아 영역은 만들지 않는다.

**이유:** 사용자가 "다른 게임도 세이브 불일치 오류를 띄우고 버리고 로드하지 않나"라고 짚었다. 일반 지식: RimWorld는 모드가 빠지면 경고 창을 띄우고 로드하면서 모르는 정의의 값을 버리고(오류 로그), 패러독스 게임은 체크섬이 다르다고 알리고 모르는 키를 무시한다. 고아 영역을 둔 예는 찾지 못했다. 보존은 형식과 복구 규칙이 늘어나는 데 비해 되살릴 일이 드물고, 조용히 버리면 S8의 "조용히 버리지 않음"을 어기므로 버릴지는 호스트(대개 플레이어 확인 창)가 정한다.

**상태:** 확인

## G211

**위치:** S8 Def가 없어진 엔티티 (G210에서 이어짐)

**무엇이 비어 있었나:** S8은 사용자가 고르면 "격리 로드"로 제거된 Def의 엔티티를 격리 영역에 보존하고 모드를 다시 설치하면 복구한다고 했다. 지금은 `dropRemoved`를 줘도 거부한다. 또 거부할 때 그 엔티티가 대상인 멈춘 Flow가 있으면 원인과 함께 "깨진 저장"(`SAV001`) 오류가 하나 더 나왔다(재현함).

**어떻게 정했나:** **`dropRemoved`가 Def가 없어진 엔티티도 버린다: 불러올 때 파괴된 것처럼 다룬다.** 런타임 `Destroy`(G91·G164)와 같게, 남의 Ref 칸은 죽은 id로 남고(읽으면 선택적은 None), 그 엔티티를 키로 한 줄과 주거나 받는 기여 행은 버리고, 그것이 대상이거나 답할 엔티티가 모두 그것인 멈춘 Flow는 취소한다. 각각 `SAV005` 경고다. 로드는 커맨드 밖이라 반응은 부르지 않는다. **살아 있는 엔티티의 필수 Ref가 그것을 가리키면 그래도 거부한다(`SAV002`, S8 "필수 Ref는 로드 오류").** Def가 데이터 전용 타입이 된 것은 타입 변경이라 거부한다. 거부할 때 Flow의 엉뚱한 `SAV001`은 내지 않는다. 격리 영역은 두지 않는다.

**이유:** 격리 영역(B)은 G210의 고아 영역과 같은 이유에 더해, 격리된 동안 그것을 가리키던 키 줄·Flow가 정리되면 되살릴 때 상태가 어긋난다. 늘 거부(C)는 모드 하나를 빼면 판을 이을 길이 없다. 필수 Ref를 허용하면 그 칸을 읽는 순간 런타임 오류가 나는데, 게임이 직접 파괴해 생긴 죽은 Ref(G91)와 달리 모드는 이 엔티티가 사라질 줄 몰랐다. 일반 지식: RimWorld는 Def를 못 찾는 물건을 오류 로그와 함께 버리고 로드한다.

**상태:** 확인

## G212

**위치:** S8 세이브 메타의 모드 내용 해시

**무엇이 비어 있었나:** S8은 세이브 메타에 모드마다 "id, 버전, 내용 해시"를 적는다고만 했다. 무엇을 해시하는지, 구조, 알고리즘, 다를 때의 동작이 없었다. 이 엔진은 패러독스와 달리 정해진 폴더 구조가 없어(`mod.py`와 `schema/`만 정해짐, 나머지는 `use` 목록) 폴더 이름으로 "여기는 바뀌어도 괜찮다"를 정할 근거가 없다.

**어떻게 정했나:** **엔진은 판단 없이 사실만 낸다.** 로드한 모드마다 엔진이 실제로 읽은 파일(`mod.py`, `use`로 읽은 스키마·Def 파일)의 목록을 만들고 항목마다 경로(모드 폴더 기준, NFC, G213), 종류(`manifest`·`schema`·`defs`, 폴더 이름이 아니라 엔진이 읽은 방식), 파일 해시를 둔다. 파일 해시는 맨 앞 UTF-8 BOM을 빼고 줄바꿈(`\r\n`·홀로 있는 `\r`)을 `\n`으로 바꾼 바이트의 SHA-256 앞 128비트(16진수 32자, G144와 같음)이고 그 밖은 바꾸지 않는다(주석도 들어감). 모드 해시는 `kesa-mod-hash/1` 표시 뒤에 경로 서수 순으로 항목의 경로·종류·해시를 길이를 먼저 적어 이어 붙인 것의 같은 해시다(읽는 순서는 `mod.py`가 정하고 그것도 들어감). 로드 결과와 저장의 `mods`에 둘 다 싣는다. 불러올 때 다르면 기존 `SAV003` 경고에 바뀐·생긴·없어진 파일을 적는다(버전이 같아도). 무엇을 무시할지(번역 등)는 사용처(멀티플레이 접속, 리플레이, 제보 도구)가 이 목록으로 정한다. 저장 형식은 1 그대로이고 새 칸은 필수다.

**이유:** 사용자가 계층 해시를 제안했다. 폴더 단계는 폴더에 뜻이 없고 저장 안에서는 파일 목록 비교로 충분해 뺐다(멀티플레이에서 가지별 비교가 필요해지면 그때 끼운다). 무시할 부분은 엔진이 정하면 어느 사용처에는 틀린다는 것도 사용자가 짚었다. 구조 해시(주석 무시)는 "같은 뜻"의 정의가 엔진 버전에 따라 흔들린다. CRC32는 짧고 xxHash·BLAKE3은 외부 패키지가 필요하다. 일반 지식: 패러독스 체크섬은 파일 내용 기반이고 번역·그림을 뺀다. RimWorld는 모드 목록만 적는다. 실제 저장이 아직 없어 지금 형식을 바꾸는 비용이 없다.

**상태:** 확인

## G214

**위치:** S8 "해당 Flow 취소 후 로드"

**무엇이 비어 있었나:** S8은 멈춘 Flow의 함수 본문이 바뀌면 거부하고 `migrate` 또는 "해당 Flow 취소 후 로드"로 해결한다고 했지만, 취소를 고를 길이 없어 진행 중인 행동 하나 때문에 저장 전체를 열 수 없었다. 무엇을 취소하는지, 옵션 모양, 알림이 없었다.

**어떻게 정했나:** **호스트 옵션 `World.Load(..., cancelBrokenFlows: true)`를 `dropRemoved`와 따로 둔다.** 켜면 Flow의 기록 안에서 어긋남이 난 Flow(본문이 바뀐 함수 `SAV004`, 없어진 함수·커맨드·핸들러·응답 커맨드·람다, Flow 안의 값의 어긋남 `SAV002`)를 그것이 든 질문과 함께 취소하고, Flow마다 새 경고 `SAV006` 하나에 질문 번호와 이유를 모두 적는다. 멈추기 전까지 한 일(낸 비용, 쓴 값)은 남는다(런타임의 대상 소멸 취소 G164와 같은 결과). 로드는 커맨드 밖이라 반응은 부르지 않으므로 모드가 취소를 알아채 비용을 돌려주는 길은 지금 없다(필요해지면 "불러온 뒤 첫 실행에 취소 신호" 같은 것을 더한다). Flow 밖의 어긋남은 이 옵션과 무관하게 거부 또는 `dropRemoved`를 따른다. 꺼져 있으면 지금처럼 거부한다.

**이유:** `dropRemoved` 하나로 묶는 안(B)은 데이터 버리기만 허락하려던 호스트도 진행 중인 행동을 끊게 되고, 확인 창에서 따로 묻는 편이 정직하다. 일반 지식: RimWorld는 불러올 때 Def를 못 찾는 일감(Job)을 오류 로그와 함께 끝내고 폰을 다른 일로 돌린다.

**상태:** 확인
